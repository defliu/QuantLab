# 项目管理：控制台看板与研究流程

> 本仓库同时跑多条研究线与实盘策略，靠**一套文档纪律**保证不失控。核心只有一句话：
> **`全局控制台.md` 是唯一任务看板，任务状态变化必须当场更新，不更新即视为工作没做完。**

---

## 一、四份必须知道的元文档

| 文档 | 定位 | 什么时候读 |
| --- | --- | --- |
| `全局控制台.md` | **唯一**任务/项目看板 + 资金分配总表 + 工作区定位 + 费率口径 | **每次开工前** |
| `研究总览与路线图.md` | 以前研究过什么 / 因子 IC 实证汇总 / 踩过什么坑 / 现在研究什么 / 未来研究什么 | 接手新方向、判断"这个是不是已经做过了" |
| `全局复利与踩坑日志.md` | 分章节编号的踩坑日志（QMT 红线、下单异步、持仓同步…） | 动实盘代码前 |
| 各项目 `PROJECT_MEMORY.md` | 项目级历史研发记忆（硬约束 / 工程惯例 / 经验教训） | 进入某个项目目录前 |

`全局控制台.md` 的结构：

```
一、工作区定位（各区域路径与使用者）
资金分配总表与账户总额约束（硬规则）
二、策略项目总表（研究层 + 实盘生产层）
三、当前任务看板：TODO / DOING / DONE(按日期) / 陈旧项已关闭
四、开发环境 + 交易费率（实盘口径）
Project_01 参数固化
五、文档导航
```

## 二、任务生命周期

### 编号规范

`T-YYYYMMDD-NNN`（如 `T-20260903-004`），同一天内多个任务顺序编号。

### 状态流转

```
TODO → DOING → DONE
              ↘ 陈旧待裁决（超过一定时间未推进，需拍板关闭或重启）
```

### 任务书

非平凡任务先在对应项目 `specs/` 或仓库根写**任务书**（如 `审计任务书_P16实时链路_20260903.md`、`通宵批次任务书_20260817.md`），写清：背景、目标、验收标准、预注册阈值。任务完成后写**汇总报告**（如 `通宵批次汇总_20260818.md`）。

### 更新纪律（硬规则）

1. 开工前先读「三、当前任务看板」确认有哪些未完工作；
2. 任务**新建 / 完成 / 阻塞 / 拍板**必须当场更新控制台；
3. 策略级状态同步更新「策略项目状态」表；
4. 不更新 = 工作没做完。

## 三、研究流程（从想法到结题）

```
想法 / 外部需求
   ↓  写任务书（含预注册阈值与验收标准）
因子实现 + PIT 数据
   ↓
IC / ICIR / 五分位 → 达标？
   ↓ 否 → 证伪归档（写清为什么不成立）
   ↓ 是
回测 + 鲁棒性（B 组全过，D 组至少 D-1/D-2/D-6）
   ↓
因子健康监控（上线后持续）
   ↓
上线 / 或再次证伪
```

**证伪与证实同等重要。** Project_12（RPS 主升浪）、Project_18（买卖点信号工具）都是完整走完流程后**结题证伪**的范例——结论同样写报告归档，避免后人重复调查。

`研究总览与路线图.md` 第二章整理了已跑过的因子 IC 实证数据（P01 IC 统计、harness 462 因子 × 3 universe 科学证伪、6+2 评分器证伪等），**动手前先查，勿重复**。

## 四、审计模式

当用户明确要求「审计模式」时：

- **只输出任务文档**（诊断报告、修复清单、验证表）；
- **不改动代码 / 配置 / 账本**。

外部策略资料走 `外部策略资料审计清单.md` 登记，审计脚本集中在 `research_audit/`，红线是**只读**：只允许新建脚本与结果 txt，禁止修改其它文件、禁止 commit。

---

## 五、文档同步是交付的一部分

用户验收时会追问「文档是否同步、看板是否更新」。因此一个任务在技术上完成后，还要确认：

- [ ] `全局控制台.md` 看板已更新（TODO→DOING→DONE）
- [ ] 项目 `PROJECT_MEMORY.md` 已补充新的硬约束/教训
- [ ] 涉及策略状态的，「策略项目状态」表已同步
- [ ] 关键结论已落盘（避免重复调查）
- [ ] 代码改动已 commit

---

## 六、长期记忆（防复发机制）

对**会反复踩的坑**，不要只留在当日日志，要提升到长期记忆：

- 跨项目/个人偏好 → `~/.workbuddy/MEMORY.md`
- 项目级工程惯例 → `D:\QuantLab\.workbuddy\memory\MEMORY.md`
- 每次实质工作 → 追加 `D:\QuantLab\.workbuddy\memory\YYYY-MM-DD.md`（append-only）

判定标准：**如果换个人（或下次的自己）还得从头摸索一遍，它就该进长期记忆。**

另有跨会话检索工具 engram（MCP，项目作用域 `quantlab`），与上述三层记忆**分工并存**、不做迁移。注意：engram 用 SQLite FTS5，对中文连续串会整体成一个 token，纯中文查询必然 miss——**所有条目必须写「英文锚点标题 + 中文说明正文」，检索一律用英文锚点**（moneyflow / QMT / passorder / Project_16 / IC / LightGBM / ATR…）。记忆必须经 MCP 工具落库，CLI 裸 `engram save` 不绑定项目会检索不到。
