### 关键数据语义

| 项 | 事实 |
|---|---|
| `adj_factor` | 是**后复权因子**（以上市首日为基准）。前复权价 = 原始价 × (adj_factor / 最新 adj_factor) |
| 回测复权口径 | **用 hfq（当日 adj_factor，PIT 安全）；qfq 才 look-ahead**（需未来数据做归一） |
| `circ_mv` | 单位是**万元**，30 亿 = 300000 |
| 日期类型 | astock parquet 日期是 `datetime.date`；pandas 3.0 下与 `datetime64` 比较需去掉 `.date()` |
| `suspend_type` | 停牌类型字段 |
| 财务 PIT | 用 **`ann_date` / `f_ann_date`** 对齐行情，**不能用 `end_date`**（否则用未来财务数据） |

> ⚠️ **gpsj `is_st` 语义反转（2026-08-27 发现，待修）**：astock `is_st`=1 是 ST、0 正常；**gpsj 的 `"ST"` 列相反：0=该股是 ST、1=正常**。`data/gpsj_reader.py::_COL_MAP` 直接透传未反转 → 凡用 gpsj_reader 的 is_st 做 ST 过滤，结果**反转**（正常股被当 ST 剔、ST 股被放行）。
> 排查：600 只面板 is_st 分布 gpsj=`1:131240 / 0:6352`，与 astock `0:131914 / 1:5678` 几乎镜像。

### 通达信筹码（历史遗留）

- `COST(N)`：累积成交量达 N% 时的价格（线性插值），1min bar 代表价 `(O+H+L+C)/4 × vol` 前复权，250 日 lookback → 与通达信 MAE 1-2%。
- **SCR 是系统技术指标不是公式函数，算法未公开**，知识库所有 SCR 公式互相不一致，只能方向近似。
- WINNER：通达信用换手率衰减的移动成本分布，简单直方图在长牛股差异巨大。
- `COST_ratio(C95/C5)` 是比值不受复权漂移影响，**可长期复用**。

## QMT 构建与发布流程

```mermaid
flowchart TD
    S["改明文源 projects/*/strategy/*_src.py"] --> B["python build.py<br/>构建+四道验证闸"]
    B --> T["自动替换 BUILD_TAG=YYYYmmdd-HHMMSS"]
    T -->|验证红| Back["回退 git HEAD<br/>禁止部署"]
    T -->|验证绿| P["记事本打开 build/ 产物<br/>人工粘贴进 QMT 客户端策略编辑器"]
    P --> R["查日志 BUILD_TAG 核对<br/>「本地构建版本 = 实际运行版本」"]
    R --> S2["模拟盘跑 1 交易日<br/>按核对清单逐项验证"]
```

**纪律**：

1. **QMT 客户端对策略加密存储——直接复制文件到 `<QMT>\python\` 目录无效**（2026-09-10 实证），唯一生效途径是**客户端策略编辑器粘贴**；部署流程 = 构建+校验 → 记事本打开产物 → 人工粘贴 → 日志核对 BUILD_TAG。
2. QMT 是**自绘 UI**：无 UIA 控件树、无子 HWND、窗口最小化时 rect=-32000 → **粘贴不可自动化**（`deploy_paste_qmt.ps1` 失败方案留档），人工粘贴是设计内动作。
3. 粘贴后策略自动加密成密文 `STRATEGY.py`，本地改代码必须**重新粘贴**才生效。
4. 部署后必须核对日志出现新 `BUILD_TAG`（`XtClient_FormulaOutput_*.log`，GBK 读取用 `python -X utf8` 防 mojibake）。

**验证四道闸**：静态（GBK / 首行 `# coding=gbk` / `ast.parse(feature_version=(3,6))` / 无 f-string）—— 关键标记（策略名 / 账号 / BUILD_TAG / 风控阈值）—— 腐蚀（`?` 乱码计数）—— 功能（模块 exec + 单测）。

> 💀 **事故档案**：2026-08-19 审计发现 Fix4 build 编码腐蚀 4168 个 `?`（`沪深A股`→`????A??`、`买入/卖出`→`????`），**从未真正部署远程**却一直以为已上线。此外修复脚本曾因 `open("w")` + GBK 异常把 ATR build 截断为 0 字节。→ 已改为**原子写入** + pyc 校验 + 字节级校验。

### 夸克网盘自动备份（`Quant_QuarkBackup_Daily`，2026-10-05 建，T-20261005-002）

**性质**：`D:\QuantLab` 开发目录 → 夸克网盘的**异地灾备**。核心动作全部下沉为纯 Python 脚本（标准库，**不依赖 LLM/Agent/模型在线**），符合「模型卡住不阻塞业务动作」的定时任务降级原则。

| 项 | 值 |
|---|---|
| 计划任务 | `Quant_QuarkBackup_Daily`（每日 21:20，`S4U` / `RunLevel=Highest`） |
| 包装脚本 | `scripts/run_quark_backup.ps1`（**必须带 UTF-8 BOM**） |
| 业务脚本 | `scripts/quark_backup.py`（纯标准库） |
| 远端目录 | `夸克网盘/来自：OpenClaw/QuantLab_backup/QuantLab_{full\|increment}_<YYYYmmdd-HHMMSS>/` |
| 远端根 FID | `28184179e44648c2a325f628ad423c5d`（**首次由 CLI 返回的真实值，禁止假定为 `0`**） |
| 状态/日志 | `data/quark_backup/{state.json, backup.log, scheduler.log}` |
| 退出码 | `0` 成功/无变更 · `1` 上传失败 · `2` 前置不满足 · `3` 备份自身异常 |

**已实测证据**（`data/quark_backup/backup.log`）：首次全量 5118 文件 / 1027.0MB → ZIP 652.9MB（`sha256=5347b682…`）→ 上传 `code=0` / 121s；随后一次真实增量（2 文件，`sha256=3ee5dbbe…`）上传 `code=0` / 6s，远端 `…/QuantLab_backup/20261005-162153`；再跑一次变更=0 → exit 0 不建空档（幂等）。日志同时确认凭据白名单每次生效（3 个文件被排除）。

**模式**：首次运行强制全量；此后 `auto` 模式**周日全量、其余日增量**。全量归档额外打 `git bundle --all`（含未推送提交，以 `ZIP_STORED` 存放，因 pack 已压缩），Git bundle 失败即作废全量；增量归档不带历史，由每周全量兜底。

**状态一致性三原则**（改动脚本时勿破坏）：

1. ZIP **完全关闭后**才计算 SHA-256（否则摘要与最终归档不一致）。
2. 任一文件 `zf.write()` 失败 → 归档作废、删除、**不推进 manifest**，下次重跑仍覆盖本次变更。
3. **上传成功后才**更新 manifest；失败时本地归档保留待重传。

**排除规则**：`.git`（改由 bundle 保存）、`data/quark_backup`（防递归打包自身）、各 `__pycache__`/缓存目录、`node_modules`、Agent 运行时目录、`.log/.tmp/.lock/.pack/.idx`、时间戳 `.bak_*`、**单文件 > 64 MB**。凭据硬排除 `.mcp.json`、`config/.web_search_keys.yaml`、`config/data_source_keys.json` 及 `.env`/key/token/cookie/credential 命名模式——**新增凭据文件时必须同步加进 `EXCLUDE_*`**。

**已知边界（不掩盖）**：

- 差分依据是 `(size, mtime_ns)`，非内容哈希；内容变而大小与纳秒 mtime 均保持不变时可能漏检。
- **不传播删除、不清理远端旧快照**（CLI 无删除能力），远端快照会持续累积，需人工清理。
- > 64 MB 的大模型/数据资产**不进备份**。
- `data/quark_backup` 整体被排除，故 `state.json` 本身不上传；本地状态丢失会退化为重新全量。
- 每日运行，不排除周末与法定节假日。

> ⚠️ **与既有夸克 TRAE 任务 `5f2bd77c` 无冲突（三查已做）**：`5f2bd77c`「夸克行情数据分享每周更新检查」是**周一 03:00 的行情离线包转存**（目标目录 `行情数据`，消费方 `scripts/update_astock_from_e.py`），本任务是**代码目录灾备**（目标 `QuantLab_backup`）。二者调度层、频率、输入、输出、远端目录全不同，**不构成双调度器冲突**，排查时勿误判为重复注册。

| 中文变 `?` | 编码腐蚀，回退 git HEAD，禁止部署 |
| 账户总额校验失败 | 重新查 QMT 客户端总资产并更新 `capital_allocation.yaml` |
| 清仓脚本报缺 xtquant | 必须用 QMT 自带解释器：`& 'E:\国金QMT交易端模拟\bin.x64\pythonw.exe' <script> --execute` |
| 飞书推送静默失败 / 全无推送 | ①**先看错误 JSON 的 `message` 字段**——若含 `openclaw context detected` 即 T-20260923-004 上下文坑（`OPENCLAW_CLI` 未清扫，S4U 会话必现），与凭据无关；②查 `LARK_CLI` 两条路径是否都存在（2026-09-23 已加固为「主路径 + 自动回退」）；③查 lark 版本号（文档写 `1.0.4` 已失效，实际只有 `1.0.5`）；④确认 `~/.lark-cli/config.json` 与系统 keychain 凭据在位；⑤失败会落盘 `data/schedules/feishu_fallback_<date>.json` |
| Windows 计划任务侧推送全失败、TRAE 侧正常 | S4U 会话环境差异坑（T-20260923-004）：`OPENCLAW_CLI=1` 只在 S4U 存在 → lark-cli 拒绝本地配置。四出口已改为按前缀清扫 `OPENCLAW*`/`HERMES*`。**交互会话推送成功不能代表 S4U 也成功**，验证须建临时 S4U 任务跑真实代码路径 |
| 分不清飞书消息来自哪个调度器 | WorkBuddy 侧推送标题带 **`[WB]`** 前缀（`LARK_SRC_TAG` 机制）；**无前缀 = TRAE/Windows 侧** |
| WorkBuddy 自动化里脚本找不到 `python` | WorkBuddy shell 的 PATH 不可靠，必须写绝对路径 `...\envs\miniqmt\Scripts\python.exe`；不要用 TRAE 内置解释器（缺 xtquant） |
| 同一目的任务在两个调度器重复跑 | 调度器已三层（Windows `Quant*` / TRAE 面板 / WorkBuddy 自动化），新建前必须**三查**；下单类任务尤其危险（guard 只认产物文件、不认「正在执行」→ 会补跑造成重复下单） |
| S4U 计划任务里脚本找不到 `python` / `node` | S4U session 0 的 PATH 不含二者（`python` 只有 WindowsApps 空壳会 `exit 9009`）。包装脚本必须写**绝对解释器路径** `C:\Users\Administrator\.workbuddy\binaries\python\envs\miniqmt\Scripts\python.exe`，并显式前置 `C:\Program Files\nodejs` 到 `$env:Path` |
| 含中文的 `.ps1` 在计划任务里解析崩溃 | PS 5.1 对无 BOM 文件按 ANSI/GBK 解码 → 中文乱码吞引号 → 级联「意外的标记」。**每次编辑后必须校验 BOM 仍在**，并设 `PYTHONIOENCODING=utf-8` + `[Console]::OutputEncoding` 对齐编码 |
| 备份「看起来成功」但 manifest 已推进 | 三条状态一致性铁律：ZIP 关闭后才算 SHA-256、任一写入失败即作废归档、上传成功后才推进 manifest。破坏任一条都会永久漏备份且无声 |
