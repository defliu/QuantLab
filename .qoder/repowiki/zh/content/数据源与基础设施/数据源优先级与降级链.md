## 二、F2 主力资金链（最容易出事的一条）

历史事故（T-20260831-003）：TDX 返回 503 后降级到 iFind，用了**前一日**口径，把 8/28 的 +5.26 亿当作当日数据打 F2=10 分；实际东财口径 8/28 为 -2.79 亿、8/31 当日 -1.25 亿，**方向全反**（真实 F2=1，总分 86→68）。

修复后的规则：

1. **模型特征层**：Tushare `moneyflow` 为权威主源（T-1）。快照新鲜则走 Tushare，滞后则回退新浪兜底。
2. **评分卡实时层（9:45）**：坚持**当日口径**，优先级 mcp_tdx → 悟道 capital_flow（东财当日）→ 东财 mx → 东财 curl；iFind 仅作兜底，且必须写入 `main_net_inflow_date`。
3. **时效校验**：`review_full._valid_main_inflow` 校验资金流日期，**非当日即按缺失计（F2 = 5 分）**，绝不拿隔日数据充数。
4. **盘前交叉验证（9:25）**：双源对拍 F2 资金 / 行情 / F5 板块，写 `crosscheck_<date>.json`；`review_full._read_crosscheck` 对不一致候选打 `[交叉验证]` 预警，只预警不阻塞。

> **Tushare `moneyflow` 的 `amount` 字段单位是万元，不是元。** 历史 parquet `D:/astock/moneyflow/moneyflow.parquet` 同样以万元存储，任何刷新脚本**不得 ÷1e4**。量级突变 1e4 倍即为单位 bug 信号。

## 三、扩展指标降级链（v8）

按职责分组，基础行情锚定腾讯（最稳），扩展指标走多级降级：

```
基础行情：腾讯 → ...
扩展指标：mcp_tdx → iFind → 东财 mx → 东财 curl   （TDX 不可达不阻塞）
F3 催化：官方公告 / 研报 / CLS 快讯 → 新浪 stockNewsSearch → 悟道
F5 板块：theme_intraday_capital / sector_analysis → ...
```

**悟道（wudao）**：真实端点 `https://stock.quicktiny.cn/api/mcp`（JSON-RPC POST + Bearer），63 个工具，盘中可用。注意：早先文档里推断的 `/api/openclaw` REST 路径**实测 404，不存在**。

> 教训：**定时任务（Schedule）环境与交互环境的 MCP 配置可能不同**。项目级 `.mcp.json` 若未登记某个 MCP，定时任务加载不到就会「不可达」。远程数据源一律写 Python 直连客户端（如 `scripts/wudao_client.py`、`caihui`），不要依赖客户端插件层。

直连客户端用法：

```bash
python scripts/wudao_client.py <tool> '<json_args>'
# 失败打印 [WUDAO-ERR] 且 exit != 0
```

## 四、熔断路由（`scripts/data_source_router.py`）

避免单个挂掉的源被反复重试拖垮整条链：

- 取数前 `check<源>`：已 OPEN（熔断中）则直接跳过；
- 调用后 `record(ok|fail)`；
- **连续失败 3 次熔断 300 秒**；
- 状态落 `data/cache/datasource_health.json`，多任务共用。

CLI 自测：`fail × 3 → OPEN → 恢复` PASS。

## 六、夜间检修（`scripts/nightly_check.py`，01:00 工作日）

全模块 A–G 自检，确保次日策略可运行：

- **A 数据完整性**：含 moneyflow、财务 PIT 覆盖检查
- **B 面板模型同步**：面板最新日落后于最近交易日 → 自动 `refresh_panel_v3` 重刷
- **C 调度任务健康**：核对次日 6 个任务 Active
- **D 数据源连通性**：含熔断恢复
- **E QMT 进程 / 桥心跳 / 账本戳 / 对账**
- **F 磁盘 / 清理 / 脚本冒烟**
- **G 报告 + 告警**

```bash
python scripts/nightly_check.py --fix      # --fix 自动修复
# 报告落 data/cache/nightly_check_<date>.md
```

首次 dry-run 就抓到真实问题：面板最新日 9/2 ≠ 最近交易日 9/3（当天 16:30 的 refresh 未到位）。

## 七、新鲜度治理：三个必须做硬断言的地方

历史反复踩的坑：**「生成侧与核算侧不同源」的管道，必然出现「能出信号、无法验证」的死局。**

1. **候选 vs 收益源**：`候选日期最大值 > 收益数据源最新日` 即为死局，必须 fail-loud（非零退出码）。
2. **面板 vs 交易日**：面板最新日必须等于最近交易日（夜间检修 B 项已覆盖）。
3. **零产出**：回填 / 统计类任务输出 0 笔，**不得以 exit 0 报 OK**。

> 典型案例（T-20260904-009）：`paper_forward.py --backfill` 只依赖人工周更的 `Updatedata/`（常滞后 7 天以上），而选股侧用自动日更的增量库 → 候选每天照常产生、收益一笔也算不出，连续 4 天「回填 0 笔」仍 exit 0 静默，有效样本实为 N=0 却被记成「9 个交易日」。
