### Phase 1b: 全周期信号扫描（已完成 2019-2024，2026-09-29）
```bash
cd D:\QuantLab\projects\Project_21_日内做T
set PYTHONPATH=D:\QuantLab\projects\Project_21_日内做T
python research/scanner.py --start 20190101 --end 20191231 --out results/signal_scan_20190101_20191231.parquet
# 六年全量并行驱动（MaxConcurrent=2、MinFreeGB=15、缺产物自动重试 ≤3 次）：
powershell -File research\run_scan_waves.ps1      # 单年并行变体：run_scan_parallel.ps1
```
**产出**：
- `results/signal_scan_{start}_{end}.parquet`（逐年六件，2019: 4.75M … 2024: 7.81M 事件）
- `results/signal_scan_partial_*.parquet`（每批增量落盘，跑完可删）
- `results/scan_{year}.out.log` / `.err.log`、`results/scan_waves.log`

**实测耗时**：13.9 ms/stock-day（优化前 42.9），单年 ~2.5-3.5 小时；**并发上限 2 个进程**（每个峰值 ~6GB，3 并发实测 OOM）；`--test` 会 preload 全池约 21 分钟，不是快速验证手段。

**参数**：`--start/--end`（YYYYMMDD）、`--out`（缺省自动写 `signal_scan_{start}_{end}.parquet`）；退出码 0=成功 / 3=事件为 0（FAIL-LOUD）

## 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: strategy` | PYTHONPATH 未设置 | `set PYTHONPATH=D:\QuantLab\projects\Project_21_日内做T` |
| `KeyError: 'trade_date'` | 1min 数据 trade_date 在 MultiIndex 中 | 用 `df.index.get_level_values('trade_date')` |
| 内存溢出 (OOM) | 同时跑太多 scanner（每进程峰值 ~6GB） | **并发上限 2**（`run_scan_waves.ps1` MaxConcurrent=2）；3 并发实测 preload 期 MemoryError |
| 扫描极慢 (>1h/天) | 单股单日串行 + 重复 I/O | 已修：exit/中位量预计算 + `.iat` 取值 + `hv` 预计算（42.9 → 13.9 ms/stock-day） |
| 零股信号泛滥 | 未执行 `<100` 跳过逻辑 | 检查 `_estimate_shares` 和 `if shares < 100: continue` |
