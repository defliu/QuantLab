# Project_22 RPS每日监控 — 编码规范

- 文件头 `# coding=utf-8`；注释/日志全中文；日志 tag 前缀约定：`[STEP]/[INFO]/[RUN]/[GATE-WARN]/[GATE-FAIL]/[SKIP-DATADEFECT]/[DONE]/[VERIFY-PASS]/[VERIFY-FAIL]`；
- **禁止交易语义词**（买入/信号/建议/下单）：本项目仅监控、排序、研究辅助（硬边界，DE 任务书明令）；
- 主库 `D:/astock` **只读**，任何缺陷只报告不修（多项目共用资产；上游缺陷日走 skip_with_manifest 分流）；
- `quality_gate` 判据与 RPS 计算逻辑（复权口径/收益窗口/PIT 池阈值/排名算法）修改前必须有 SPEC 或业主拍板；缺陷日跳过是唯一豁免且必须留痕；
- look-ahead 防线：财务/口径外数据不引用；`prev_rank_20` 为状态链字段，链条检验必须用它而非当日 rank_20 对比；
- verify_rps.py 必须保持"独立实现"原则（不复用 rps_daily 内部函数），已有断言判据强度不得回调；
- 产物 CSV `utf-8-sig` 编码；state parquet 每跑一天原位更新；大文件操作禁止全量加载（列裁剪 + 行过滤）。
- 含中文的 `.ps1` **必须带 UTF-8 BOM**（PS 5.1 按 ANSI/GBK 解码会吞引号致级联解析错误）；**每次编辑后都要复核 BOM仍在**（编辑工具改写时可能丢）。
- 调度脚本的「跳过」与「故障」必须可区分：非交易日 exit 0，探测/运行故障 exit 1，不得用 fail-safe 把故障吞成正常跳过。
- 日历/大表探测一律走 parquet **谓词下推**，不得回退全列扫描；窗口要向前留足余量以支持「数据滞后时仍能报出最新日期」。
- 改调度相关逻辑后，`audit_scheduled_tasks.ps1` + `check_bom_scheduled_ps1.ps1` + `Get-ScheduledTask` 回读三项都要跑。
- **收件人等跨项目配置必须运行时从唯一事实源提取，禁止留硬编码副本**：P22 复用 P16 的 `FEISHU_OPEN_ID` 靠运行时读 `qmt_config.py`；留副本等于「上游换人后本项目静默推给旧人」。
- **跨项目能力用 CLI 调用而非 import**：`P16/lark_push.py` 的 `record_failure()` 把兜底记录写死在它自己的 `_proj_dir()`，import 会让调用方的失败记录落进 P16 账下、归属错乱。
- **「成功必推」是硬要求**：成功路径的摘要构建即使抛异常，也必须降级发一条基础通知，不允许静默不推；任何结果分支都要么推送、要么显式记日志说明为何不推（非交易日跳过是唯一豁免）。
- **通知失败必须以非零退出码传出**（本项目用 `exit 2`），不得被末尾无条件 `exit 0` 吞掉——否则「跑成功但没通知」在调度器里与完全正常无法区分，等于静默失联。
- 推送失败时**必须留档未送达正文**到本项目目录（`push_failed_<tag>_<时间戳>.txt`）：依赖被调方的兜底记录等于跨项目查不到 = 没留痕。
