# Project_22 RPS每日监控 — 概述

## 定位

RPS（Relative Price Strength，区间收益百分位）强势股**每日监控与研究辅助工具**：只做排序、观察、跟踪，**不产生任何下单/交易语义输出**（SPEC 第一节风险边界；禁止出现买入/信号/建议等词）。

## 目录结构

```
projects/Project_22_RPS每日监控/
├── research/
│   ├── rps_daily.py       # 主程序：单日运行 / N 日回补（升序逐日推进）
│   └── verify_rps.py      # 独立交叉校验（8 项断言，不复用主程序内部函数）
├── scripts/
│   └── run_rps_daily.ps1  # 交易日单日运行包装（schtasks 唯一入口，含两层交易日判定）
├── config/
│   └── rps_monitor.yaml   # 窗口/池过滤/门控/enrich/defect 配置
├── results/               # 产物：daily/full CSV、state parquet、缺陷台账、回补日志、logs/
└── specs/                 # SPEC 与 DE 任务书
```

## 核心产物（results/）

- `rps_rank_daily_YYYYMMDD.csv`：当日 Top50 明细 + 状态快照字段（prev_rank/rank_chg/入榜以来收益等）；
- `rps_rank_full_YYYYMMDD.csv`：当日全池（约 3500~4000 只）三窗口 ret/rps + 涨停池/题材标注；
- `rps_state.parquet`：滚动状态快照（键 ts_code，含 first_top20_date、prev_rank_20、consec 等 11 列）；
- `defects_manifest.csv`：主库缺陷日台账（2026-10-04 起，覆盖写）；
- `backfill_round3.log`：60 交易日回补全程留痕（命令行/起止/退出码/缺陷清单/逐日 [RUN]）。

## 关键机制：主库缺陷日分流（2026-10-04 业主拍板）

`D:/astock/daily/stock_daily.parquet` 的 `listed_days` 列在 2026-08-03/04/05、09-14、09-18 五日整列失效（NaN 比例 0.999~1.0），当日 PIT 池过滤全灭。拍板口径：**坏数据日显式跳过 + 缺陷台账留痕，跳过逻辑扶正进主程序，不修上游主库**（多项目共用资产）。60 交易日窗口实际有效产出 55 天——**不得声称「60 日回补完成」**。

## 交易日定时任务（2026-10-04 业主追加）

任务名 `Quant_P22_RPS_Daily`，每周一至周五 18:30 触发，包装脚本 `scripts/run_rps_daily.ps1`。**交易日判定必须两层，缺一不可**：

1. 任务触发器 `DaysOfWeek=62`——只过滤周末；
2. 脚本内查 `D:\astock\daily\stock_daily.parquet` 当日是否已有行情——过滤法定节假日/调休/主库未更新。

**只做第 1 层是错的**：A 股国庆春节全部落在工作日，`MON-FRI` 会把长假逐日误触发。第 2 层复用 `rps_daily.py` 同一日历，避免两套「交易日」定义打架，同时兼具数据就绪检查。18:30 的排期理由是排在 `Quant_AstockKit_Update`（周一至周五 17:30 更新主库）之后，确保读当日已落库数据。

**未接WorkBuddy 消费方、未接交易**，产出仍是纯确定性 CSV + 状态快照。SPEC 依据见项目 `specs/SPEC_RPS每日监控_20261004.md` 附录 B.7。

## 飞书推送：成功与失败都推（2026-10-04 业主追加）

业主要求「成功和失败都推，不然我知道结果」。收件人**复用 Project_16的 `FEISHU_OPEN_ID`**，包装脚本运行时从 `P16/qmt_config.py` 动态提取（不留硬编码副本）；推送以 **CLI 方式调 `P16/lark_push.py --file`**，不跨项目 import（其 `record_failure()` 写死在 P16 目录，会让 P22 的失败记录归属错乱）。

| 场景 | 推送 |
|---|---|
| 交易日成功 | 推 Top10（`ts_code` / RPS20-60-120 / 涨停 / 题材） |
| 成功但摘要构建异常 | 推降级基础通知（「成功必推」不容缺口） |
| 探测故障 / 无 `HIT=` 标记 / 运行失败 / 产物缺失 | 推错误上下文（运行失败含日志末尾 25 行） |
| 非交易日跳过 | **不推**（避免长假刷屏） |

推送是**非核心动作**：失败不改变产物判定，以 `exit 2` 标记；失败时未送达正文留档 `results/logs/push_failed_<tag>_<时间戳>.txt`。**成功/失败/通知降级三分支均已实跑验证**（成功与失败两分支拿到 `ok:true` + `message_id` 真实送达；降级分支退出码实测为 2）。
