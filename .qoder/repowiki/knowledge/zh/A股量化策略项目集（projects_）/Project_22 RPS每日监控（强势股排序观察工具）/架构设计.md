# Project_22 RPS每日监控 — 架构设计

## 数据流（rps_daily.py main）

```
交易日历(只读 trade_date 列) → 窗口确定(--date 1天 / --backfill N天)
  → load_frame(区间+列裁剪 9 列, pyarrow filters 下推)
  → detect_defect_days(listed_days NaN 比例 > 0.5 → 缺陷日, 打 [SKIP-DATADEFECT], 写台账, 不产出)
  → build_return_pivots(P = close*adj_factor, pivot 后 ffill, ret_w = P/P.shift(w)-1)
  → pool_mask(PIT 池过滤) → day_counts(预期池大小中位数)
  → fetch_enrich(仅产出日; 涨停池/同花顺题材, 网络失败降级不阻断)
  → 逐日: compute_day → apply_enrich → quality_gate → update_state → save_state → write_outputs
```

## 关键口径（SPEC 4.x，错则全盘皆错）

- **复权**：P = close × adj_factor（后复权价的单调等价变换）；不依赖"最新因子"，PIT 干净；
- **RPS 百分位**：当日 PIT 池内 `rank(pct=True)*100`（最强=100，并列取平均，NaN 不参与排名）；
- **PIT 池**：amount≥50000（千元=5000万）、流通市值 20亿~5000亿、listed_days≥252、剔除 ST；
- **rank_20**：1=最强；rps_20 为 NaN 者不参与排名（full CSV 中写 -1）；`rps_20` 精确并列组内的 rank_20 次序无业务语义；
- **状态快照**（rps_state.parquet，键 ts_code）：不在当日池的历史股票 in_top50_now=0、连续天数清零、其余字段冻结；同日重跑幂等（prev_rank_20/consec 不二次移动）。

## 质量门控 quality_gate（判据不得放宽）

覆盖比 <0.80 / rps_20 缺失率 >0.02 / 唯一比例 <0.30 / 当日池为空 → `[GATE-FAIL]` + `sys.exit(1)`；涨停池/题材 0 条 → WARN 降级不阻断。**唯一豁免是缺陷日跳过（必须留痕），正常日门控强度不得降低。**

## 缺陷日分流（2026-10-04 扶正进主程序）

- `DEFECT_NAN_RATIO_THRESHOLD = 0.5`（yaml `defect.nan_ratio_threshold` 可覆盖）；
- `detect_defect_days(df, days, threshold)` → (缺陷日列表, 逐日 NaN 比例, 逐日行数)；
- `write_defects_manifest(...)` → `results/defects_manifest.csv` 覆盖写，列 `trade_date, listed_days_nan_ratio, total_rows, verdict(MAIN_DB_DEFECT), skipped(True)`；
- 分流位置在 quality_gate **之前**；缺陷日不调用 compute_day/quality_gate/update_state/write_outputs；
- `defect.action` 仅允许 `skip_with_manifest`，启动时硬校验（continue/silent 拒绝启动）；
- 台账覆盖写策略：回补模式每次覆盖写当前窗口；单日模式仅当日为缺陷日时覆盖（防日常运行清掉历史台账）。

## 校验架构（verify_rps.py）

独立实现不复用主程序函数，8 项断言：①ret_20 随机抽样独立手算（<1e-6）；②rps_20 分布合理性；③state rank_chg 恒等式；④PIT 早晚对比；⑤窗口完整性（产出+缺陷==窗口交易日，防「报 60 实 55」）；⑥缺陷台账一致性（vs 日志 [SKIP-DATADEFECT] 行数）；⑦链条连续性（daily[Ti].prev_rank_20 == full[T(i-1)].rank_20，必须用 prev_rank_20，不能用当日 rank_20 对比前日——后者是错误检验）；⑧无未来状态（first_top20_date/last_update_date ≤ 产出日）。失败以非零退出码结束。

## 调度与通知层（scripts/run_rps_daily.ps1，2026-10-04 业主追加）

```
Task Scheduler(周一~周五 18:30, S4U)
  → 第2层交易日判定: astock 主库当日 probe(HIT=1?)
      HIT=0 → 正常跳过 exit 0（不推送，避免长假刷屏）
      探测异常 / 无 HIT 标记 → exit 1（fail-closed，基础设施故障不可混同非交易日）
  → rps_daily.py --date YYYYMMDD
      exit≠0 → 失败推送(日志尾部) exit 1
  → 产物自检(daily + full 均存在、统计行数)
      缺失 → 失败推送 exit 1
  → 成功推送 Top10 摘要 → exit 0 / 推送失败 exit 2
```

关键设计：

- **交易日两层判定缺一不可**：触发器 `DaysOfWeek=62` 只过滤周末，法定节假日与调休靠主库 probe 过滤；第二层与 `rps_daily` 同一 `stock_daily` 日历，避免两套「交易日」定义打架；
- **通知为非核心动作**：推送失败绝不回滚/改变「产物已落盘」判定，只以 `exit 2` 传出（否则「跑成功但没人收到」在调度器里与完全正常无法区分＝静默失联）；
- **收件人不留副本**：`FEISHU_OPEN_ID` 运行时从 P16 `qmt_config.py` 提取；解析失败则不推（fail-closed）+ 正文留档 + `exit 2`，不猜、不沿用历史值——「推错人」比「推不出去」危险；
- **未送达正文必须落在 P22 自己目录**（`results/logs/push_failed_<tag>_<时间戳>.txt`）：P16 `lark_push` 的兜底记录写在 P16 下，跨项目查不到等于没留痕。
