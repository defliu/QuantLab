# Project_22 RPS每日监控 — 特殊配置与命令

## 常用命令

```
D:\Python311\python.exe research\rps_daily.py --date 20260924     # 单日
D:\Python311\python.exe research\rps_daily.py --backfill 60       # 回补最近 60 交易日（升序逐日）
D:\Python311\python.exe research\rps_daily.py --backfill 60 --workers 2
D:\Python311\python.exe research\verify_rps.py                    # 8 项独立交叉校验
```

注意：系统 `python` 指向 WindowsApps 占位 stub（无输出），**必须用 `D:\Python311\python.exe` 全路径**。

## config/rps_monitor.yaml 要点

- `windows: [20, 60, 120]`（上限 120，超限启动报错）；`top_n_report: 50`；
- `pool.min_amount: 50000`——**amount 列为千元单位**（Tushare 口径，2026-10-04 实测核实；SPEC 原文按"元"假设会过滤掉全部股票）；
- `defect.nan_ratio_threshold: 0.5` / `defect.manifest: defects_manifest.csv` / `defect.action: skip_with_manifest`（action 硬校验，改 continue/silent 拒绝启动）；
- 配置读取有 `_DEFAULT_CONFIG` 完整兜底，yaml 缺失只 WARN。

## 已知数据缺陷与产物口径

- 主库 `listed_days` 五日整列失效：2026-08-03/04/05（NaN 0.999）、2026-09-14、2026-09-18（NaN 1.0）→ 台账 `results/defects_manifest.csv`；若离线包升级修复，回补自动恢复产出；
- 60 交易日窗口（2026-07-03 ~ 2026-09-24）**实际有效产出 55 天**，不得声称"60 日回补完成"；
- 历史备份：`rps_state.parquet.bak_preround3_20261004_122954`（round3 前 state）、`results/_archive_round2_20261004_122954/`（round2 110 个 CSV）；
- 回补日志 tee 落盘范式见 `results/backfill_round3.log`（命令行/起止时间/每步耗时/退出码/缺陷清单/逐日 [RUN]/峰值内存），重跑时建议沿用相同 wrapper。

## 定时任务（schtasks）

| 项 | 值 |
|---|---|
| 任务名 | `Quant_P22_RPS_Daily` |
| 触发 | 每周一至周五 18:30（`DaysOfWeek=62`） |
| 入口 | `scripts/run_rps_daily.ps1`（UTF-8 BOM 必需） |
| 运行身份 | `LogonType=S4U` / `RunLevel=Limited`（禁Interactive，否则每晚弹窗） |
| 主日志 | `results/logs/rps_daily_run.log` |
| 单日日志 | `results/logs/rps_daily_YYYYMMDD.log`（仅交易日命中才生成） |

手工复现单次触发（等价于调度器行为，含交易日判定）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\QuantLab\projects\Project_22_RPS每日监控\scripts\run_rps_daily.ps1"
echo $LASTEXITCODE
```

**退出码契约**：`0`=已产出且推送成功 / 非交易日正常跳过；`1`=交易日运行失败**或日历探测故障**（探测挂了必须与「非交易日」可区分，否则基础设施故障会被静默吞掉，fail-closed）；`2`=**通知降级**（产物已落盘、核心计算成功，但飞书推送失败——表示业主收不到通知，需人工确认）。

## 飞书推送

| 项 | 值 |
|---|---|
| 收件人 | **复用 P16 的 `FEISHU_OPEN_ID`**（P22 不另设配置） |
| 取值方式 | 包装脚本运行时**正则从 `P16/qmt_config.py` 动态提取**，**不留任何副本常量**（副本会导致 P16 换人后 P22 静默推给旧 open_id）；**解析失败 → fail-closed 不推送** + 正文留档 + `exit 2`（推错人比推不出去更危险：前者无声失联，后者可查可修） |
| 推送出口 | **CLI 调用** `projects/Project_16_LightGBM股票大师/lark_push.py --file <msg> --user-id <id> --title <t>`，**不 import** |
| 失败留档 | `results/logs/push_failed_<tag>_<yyyyMMdd_HHmmss>.txt`（含未送达正文 + 推送返回 + 收件人） |

| 场景 | 推送 | 内容 |
|---|---|---|
| 交易日成功 | 推 | Top10：`ts_code` / `rps_20` / `rps_60` / `rps_120` / 涨停标记 / `zt_stat` / `ths_reason` |
| 成功但摘要构建异常 | 推 | 降级基础通知（日期 + 池规模 + 产物路径），仍满足「成功必推」 |
| 日历探测故障 / 无 `HIT=` 标记 / `rps_daily.py` 失败 / 产物缺失 | 推 | 对应错误上下文（失败分支含日志末尾 25 行） |
| 非交易日跳过 | **不推** | 设计如此，避免长假刷屏 |

要点：

- 用 `--file` 不用 `--text`，避开 Windows 命令行 32767 字符上限；
- 推送是**非核心动作**：失败不改变产物判定，仅以 `exit 2` 标记；**成功路径末尾不得无条件 `exit 0`**，否则「跑成功但没推送到」在调度器里与正常无异（静默失联）；
- **CSV 无 `name` 列**，摘要只能用 `ts_code`，臆造字段会导致整列为空；
- 手工验证送达（会真的发消息）：
  ```powershell
  D:\Python311\python.exe "D:\QuantLab\projects\Project_16_LightGBM股票大师\lark_push.py" --check
  # 判成功看返回 JSON 里 "ok": true 且有 message_id，不能只看进程退出码
  ```

常用运维命令：

```powershell
Get-ScheduledTask -TaskName Quant_P22_RPS_Daily | Get-ScheduledTaskInfo
powershell D:\QuantLab\scripts\audit_scheduled_tasks.ps1# 全库乱码/缺失文件审计
powershell D:\QuantLab\scripts\check_bom_scheduled_ps1.ps1    # 被调度.ps1 的 BOM 校验
```

注册必须走 `New-ScheduledTaskAction/Trigger/Principal/SettingsSet` + `Register-ScheduledTask -InputObject` **对象方式**，禁 XML/schtasks 命令行拼接（中文路径会 UTF-8→Latin-1 乱码写入任务定义，注册后须回读 `Actions.Arguments` 核对）。

## 已知限制

- 主库滞后与法定假日**无法区分**，都表现为 `HIT=0`，靠日志里的 MAX 日期人工判断；
- 真实交易日 18:30 若上游未更新完 → 当日跳过且**不重试**，次日不补跑该日（监控类工具可接受，需补跑时手工`--date`）；
- 日历探测的 parquet **谓词下推**优化（约 27s → 约 2s）不得回退为全列扫描；窗口向前留 60 天是为主库滞后时仍能报出 MAX 日期便于排障。

## 踩坑记录

- `rps_20` 精确并列（rank 平均）组内 rank_20 次序在不同运行环境间可互换（如 002303.SZ/300426.SZ ret 逐位相同）；对比两轮产物时 daily/Top50 层逐字节一致，full 层允许并列组内名次互换，不是 bug；
- pandas 3.x + pyarrow 25 下 `read_table(...).to_pandas()` 会按 parquet 元数据恢复 MultiIndex，需拍平（`_flat_df` / load_frame 同款防御）；
- 回补必须从干净 state 起步（清 state 前先备份改名），避免冒烟残留污染链条检验。
