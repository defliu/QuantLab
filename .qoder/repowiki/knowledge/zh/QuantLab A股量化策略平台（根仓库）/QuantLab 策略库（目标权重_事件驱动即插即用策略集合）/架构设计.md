采用「扁平模块 + 运行时自动发现」的注册表架构：`registry.py` 在进程启动时 `pkgutil.iter_modules` 扫描 `strategy/` 下所有文件，跳过 base/registry/schedule 等基础模块，逐个 import 触发各模块顶层的 `@register_strategy(name)` 装饰器把 `evaluate_day` 写入全局 `_REGISTRY`；`schedule.py` 集中实现 `is_rebalance_day(weekly/monthly/quarterly)` 调仓日历判断，被所有策略复用以避免各自重复实现。

每个策略模块即一个自包含的 `evaluate_day(current_date, market_window, positions, cash, universe, account_state, strategy_config, aux_data)` 函数，遵循两种模式：
- **target_weights 模式**（atr_lowvol、template_lowvol、atr_lowvol_quality、rps_momentum）：只输出 `{code: 1.0}` 等权意愿，仓位模型（equal/vol_parity）、行业上限、波动率目标、杠杆、涨跌停/停牌/ST±5% 约束全部委托给框架组合层；非调仓日走统一的 `_hold_decision` 止损分支。
- **事件驱动增量模式**（huang_529、trae_main_uptrend）：直接产出 `sell_decisions` / `buy_candidates` 增量命令，用于信号稀疏场景避免强制再平衡。

横向复用能力：`sector_rps.py` 提供可懒加载的 `SectorRPS` 类计算板块 RPS；`schedule.is_rebalance_day` 统一调仓日历；诊断字典统一包含 `candidate_total` / `candidate_passed` / `logs` / `diagnostics.strategy_specific`，由 `registry.get_strategy_diag` 读取。模块导入全部包裹在 `try/except` 中，单策略失败不影响整体。
