模块以「阶段化流水线」组织：`data_config.py` 提供集中式数据/模型路径和主仓+Updatedata增量合并的 `read_main_daily`，作为所有脚本的唯一入口；阶段0~2由 `build_features[_v2].py`、`train_baseline.py`、`train_optuna.py` 产出 `feature_panel_*.parquet` + `features_v*.json` 与 `versions/models/lgb_model_v*.txt`；阶段3通过 `deploy_predict.py` 加载候选模型做 LightGBM 概率 × 评分卡(权重 `SC_WEIGHTS`) 双轨综合，输出 `data/selections/` 候选清单；阶段3b 用 `review_full.py` 拉取 TDX 资金流/新闻/板块做实时复核。盘后调度由 PowerShell 脚本 `run_scheduled.ps1` 驱动，依次调用 `xtdata_update.py → merge_live_features.py → deploy_predict.py → reconcile_trades.py → verify_model_panel_sync.py`；周更重训走 `refresh_panel_v3.py → train_optuna.py --model-tag _retrain_*`，再用 `promote_model.py` 提升候选为正式模型。实盘执行层包含 `qmt_trader.py`（按选股下单）、`qmt_monitor.py`（止损止盈提醒 / 可选 auto-sell）、`qmt_clear.py`、`strategy_capital.py` 等，QMT 账号固定为 `67014907`（miniQMT），并通过 broker/qmt_builder 生成 GBK 单文件策略。研究侧在 `research/` 下运行独立实验（如 `trim_rule_backtest.py`），结果归档于 `versions/V*_candidate_xxx/`；全量中间产物集中在 `data/`（panel parquet、选号 CSV/MD、日志）与 `data/schedules/`（定时任务日志）。依赖方向单向：scripts → data_config → astock parquet/TDX/DuckDB → LightGBM → selections → QMT。
