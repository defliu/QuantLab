该仓库未定义统一的自定义异常类型或全局错误码体系，而是采用**以 Python 内置异常 + logging 日志 + 结构化 diagnostics 字段**为核心的轻量级错误处理模式。核心设计决策如下：

1. **异常使用范围有限且语义明确**
   - `ValueError` 用于参数校验失败（如 `engine.py` 中交易日历为空、trading_model 不在允许列表、`portfolio.py` 中未知 side）。
   - `ImportError` 用于策略模块动态导入失败时回退默认值。
   - `NotImplementedError` 在 `broker/local_context.py` 中显式抛出，标记本地不支持的 QMT 接口，触发 fail-open 行为。
   - 其余路径普遍使用 `except Exception as e` 捕获后降级/跳过，而非向上抛出。

2. **日志驱动的错误传播**
   - 所有核心模块通过 `logging.getLogger(__name__)` 获取 logger，统一用 `log.warning(...)` / `log.error(...)` 记录异常上下文（如 benchmark 加载失败、fundamentals reader 异常、target_weights 重平衡失败）。
   - 回测引擎将每日 `[INFO]` / `[ERROR]` 前缀的日志行累积到 `daily_logs`，最终随 trades/equity/positions 一起输出到报告目录，形成可追溯的错误审计轨迹。

3. **结构化 diagnostics 字段承载运行时诊断信息**
   - 每个 rebalance/execution 步骤返回的 decision dict 包含 `diagnostics` 子字典，记录 `warnings`、`candidate_total/passed`、`unfilled_order_count` 等计数与警告列表。
   - 引擎层对 `diagnostics.warnings` 去重聚合为 `warnings_unique`，并统计 `strategy_specific` 指标，使错误信息结构化地沉淀到 summary JSON 中。

4. **Fail-open 与降级策略**
   - 数据读取失败（benchmark/fundamentals）：记录 warning 后跳过该功能，继续运行回测。
   - 涨跌停/停牌/价格无效：执行层返回 `(None, reason_string)`，由引擎侧记录 `[ERROR] unfilled_order ... reason=...` 并计数，不中断流程。
   - 本地 QMT 适配器对缺失接口直接抛 `NotImplementedError`，调用方捕获后按 fail-open 处理。

5. **脚本级错误收集**
   - 批量脚本（如 `batch_ic_test.py`）维护 `errors` / `skipped` 列表，逐因子 try-except 捕获异常后追加到结果集，最后汇总输出 CSV/Markdown 报告，保证单因子失败不影响整体批处理。

6. **无全局中间件/装饰器**
   - 未发现统一的 error middleware、@handle_error 装饰器或全局异常处理器。错误处理内联在各函数中，遵循“就近捕获、就近降级”的原则。

**约束与约定**
- 策略 evaluate_day 返回值中的 `logs` 列表必须为字符串行，引擎统一加 `[INFO]` 前缀写入日志。
- 执行层函数必须返回 `(trade_or_None, unfilled_reason_or_None)` 二元组，禁止抛异常中断主循环。
- 所有外部依赖（数据源、QMT、benchmark DB）的失败必须被 try/except 包裹并以 warning 形式记录，不得导致回测进程退出。
- 自定义异常类型未被使用，新增错误场景应沿用 ValueError/Exception + logging + diagnostics 三件套模式。
