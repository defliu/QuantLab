# 概述

## 是什么

`scripts/feishu_bridge/` 是 QuantLab 与飞书之间的**双向消息桥**，让诚哥能在飞书里直接和
WorkBuddy AI 对话，也让 AI 能主动向飞书推送。

建立日期：2026-10-09。归属：基础设施（非策略模块）。

## 与 P16 飞书推送的区别

| | P16 盯盘推送（既有） | feishu_bridge（本模块） |
|---|---|---|
| 方向 | 单向（QuantLab → 飞书） | **双向** |
| 触发 | 盯盘信号 / 心跳 | 用户消息事件 |
| 实现 | `qmt_card.py` + `lark-cli` | `bridge.py` + `listen.py` + 定时任务 |

两者**共用**同一个飞书应用 `cli_aade2524ddbd9bd6` 与同一份 `~/.lark-cli/config.json`。

## 能力矩阵（2026-10-09 实测）

| 能力 | 结论 | 说明 |
|---|---|---|
| 发送消息（私聊/群） | ✅ | bot 身份，`im +messages-send` |
| 接收消息事件 | ✅ | WebSocket 长连接 `im.message.receive_v1`，**无需公网 IP** |
| 按 `message_id` 回复 | ❌ | 应用缺 `im:message` 系列 scope → `99992354`（权限掩码错误） |
| 读取消息列表 | ❌ | 应用缺 `im:message:readonly`，错误码 `230027` |
| bot 列私聊会话 | ❌ | 飞书隐私保护，bot 身份不可列 p2p chat |

**回复落地方式**：`bridge.py reply` 先试 `+messages-reply`，失败自动回退为「按 `chat_id` 发新消息」。
回退能成立的前提是事件载荷里带了 `chat_id`——**不要只存 `message_id`**。

## 已知限制

- 回复延迟最长约 **1 小时**：WorkBuddy 定时任务最小调度粒度为 1 小时，
  常驻监听负责「捕获零丢失」，定时任务负责「处理 + 回复」。
