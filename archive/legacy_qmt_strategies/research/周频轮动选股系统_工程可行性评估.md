## 2. 计算复杂度与性能估算

### 2.1 因子计算复杂度分析

8个原子因子全部是滚动窗口运算，可完全向量化（pandas/numpy）：

| 因子 | 计算方式 | 每股票复杂度 | 向量化？ |
|------|---------|:-----------:|:-------:|
| momentum_10 | close.pct_change(10) | O(1) per row | ✅ |
| reversal_5 | -(close.pct_change(5)) | O(1) | ✅ |
| volatility_20 | rolling(20).std() | O(1) amortized | ✅ |
| volume_ratio | vol / vol.shift(1).rolling(5).mean() | O(1) | ✅ |
| quality | -CV(close, 60) | O(1) | ✅ |
| value | MA60/close - 1 | O(1) | ✅ |
| limit_up_lag | pct_chg >= 5% shift(1) | O(1) | ✅ |
| multi_momentum | close.pct_change(10/20/60) | O(1) | ✅ |

### 2.2 全市场性能估算（5793只股票）

```
数据加载:    pd.read_parquet(1.3GB)        → ~3秒
因子计算:    5793 × 8因子 全向量化          → ~5秒  (单线程pandas)
中性化:      5793 × 1次 OLS (18 dummies)   → ~0.5秒 (numpy.linalg.lstsq)
排名+筛选:   argsort + top_n                → <0.1秒
─────────────────────────────────────────────────
总计:        ~10秒（单线程，全市场5793只）
```

**即使回退到文档说的100只股票池：< 0.5秒。**

### 2.3 策略复合计算（11个策略并行）

11个策略 = 不同因子组合权重，因子值可复用：
```
因子计算（一次）:   5秒
11个策略排名（并行）: <1秒
─────────────────────────
总计:               ~6秒
```

### 2.4 结论

**计算完全不是瓶颈。** 每周全市场计算 < 10秒，远低于当前6+2评分器每日运行的计算量。现有硬件足以支撑。

## 3. QMT集成方案

### 3.1 Python 3.6.8兼容性分析

文档中8个因子的计算全部基于 `pandas.rolling()` / `numpy`，这些在 Python 3.6.8 下完全可用。需注意：

| 语法项 | 3.6.8兼容？ | 注意事项 |
|--------|:----------:|---------|
| `pd.DataFrame.rolling()` | ✅ | pandas 0.20+ 即可 |
| `np.linalg.lstsq()` | ✅ | numpy 1.13+ 即可 |
| `pd.read_parquet()` | ⚠️ | 需要 pyarrow，QMT的Python 3.6.8可能没有 |
| `dict[str, float]` | ❌ | 必须用 `Dict[str, float]` |
| `str \| None` | ❌ | 必须用 `Optional[str]` |
| f-strings | ⚠️ | 可用但不稳定，建议 `.format()` |

**关键风险：QMT Python 3.6.8 可能缺少 pyarrow/pandas。** 如果QMT端需要读取parquet，有两个方案：
- **方案A（推荐）**：因子计算在外部Python 3.10完成，QMT只读取最终选股结果CSV → 零依赖
- **方案B**：为QMT 3.6.8安装pandas/pyarrow → 可能遇到编译兼容问题

### 3.2 与现有全天版框架的集成模式

**推荐的集成模式：分离式架构 — 不和现有策略耦合**

```
┌─────────────────────────────────────────────────────┐
│ 周五盘后 (Python 3.10, 外部)                         │
│                                                      │
│  weekly_ranker.py                                    │
│  ├── 读 E:/astock/daily/stock_daily.parquet          │
│  ├── 计算 8 因子 + OLS中性化                          │
│  ├── 11 策略排名                                     │
│  └── 输出 Top N → D:/QMT_POOL/weekly_selected.txt    │
│                                                      │
├─────────────────────────────────────────────────────┤
│ 周一开盘 (QMT Python 3.6.8, strategy_main.py)        │
│                                                      │
│  读取 D:/QMT_POOL/weekly_selected.txt                │
│  → 合并到现有 pool → 6+2评分排优先级                   │
│  → 仓位分配 → passorder 买入                          │
│                                                      │
│  周中 (QMT): 现有风控引擎照常运行                      │

└─────────────────────────────────────────────────────┘
```

**为什么不把因子计算放到QMT内部？**
1. QMT Python 3.6.8的第三方库环境受限
2. 现有build_strategy.py构建流程面向单文件GBK产物，不适合嵌入numpy/pandas计算
3. 分离式架构：外部计算（灵活）+ QMT执行（可靠），各司其职
4. 已在现有D:/QMT_POOL/机制中验证可用

### 3.3 与6+2评分器的关系

**推荐模式A：周频选股池 → 日频6+2精细化**
```
周频系统选出 Top 30 → 作为当日6+2评分的候选池
→ 6+2负责盘中择时（哪天买、买多少）
→ 风控引擎照常运行
```

理由：6+2评分器提供的是"日内择时"能力，与周频选股的"周度方向判断"是互补关系。

## 4. 因子中性化（OLS回归）在 Python 3.6.8 的实现

### 4.1 推荐实现（numpy纯实现，零额外依赖）

```python
import numpy as np

def neutralize_factor(raw_scores, industry_labels, log_mcap):
    """
    raw_scores:   (N,)  原始因子得分
    industry_labels: (N,) 行业标签
    log_mcap:     (N,)  log(流通市值)
    返回: (N,) 中性化后残差
    """
    # 行业 → one-hot
    unique_ind = sorted(set(industry_labels))
    ind_dummies = np.zeros((len(raw_scores), len(unique_ind)))
    for i, label in enumerate(unique_ind):
        ind_dummies[:, i] = (np.array(industry_labels) == label).astype(float)
    
    # hstack: [行业dummies | log市值 | 常数]
    X = np.column_stack([ind_dummies[:, :-1], log_mcap, np.ones(len(raw_scores))])
    
    # OLS: beta = (X'X)^-1 X'y
    beta, residuals, rank, singular = np.linalg.lstsq(X, raw_scores, rcond=None)
    y_pred = X @ beta
    return raw_scores - y_pred
```

### 4.2 性能

- 全市场5793只 × 18个行业 → 设计矩阵 5793×20 → lstsq耗时 < 0.1秒
- 8个因子独立中性化 → 总计 < 1秒
- **在外部Python 3.10中完成**，QMT不参与计算

## 8. 总体评估结论

### 可行性判定：✅ 高度可行

**核心原因：**
1. **数据基建已完备** — 本地parquet 17年全A数据，不需要腾讯财经API
2. **计算不是瓶颈** — 全市场5793只 × 8因子 < 10秒/周

### 关键建议

1. **立即将100只股票池扩展到全市场** — 100只存在严重幸存者偏差
2. **放弃腾讯财经作为主数据源** — 本地数据更全更可靠
3. **优先跑回测而非急于上线** — 用17年真实数据验证后再决策
4. **与6+2保持互补** — 周频选方向 + 日频择时机
