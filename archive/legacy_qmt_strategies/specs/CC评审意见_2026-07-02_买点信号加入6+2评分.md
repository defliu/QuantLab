# CC 评审意见：买点信号加入6+2评分

**日期**：2026-07-02
**评审人**：CC
**评审对象**：[[会议纪要_2026-07-02_买点信号加入6+2评分]]
**立场**：方向认同，形式与节奏有保留意见

---

## 一、总体评价

方向对——加分优于硬合并、保留选股池不变、买点1/2分开、渐进部署，这四条底线守得好。**但纪要里最值钱的不是"加几分"，而是 Phase 1"先采集验证增量 alpha 再决定权重"这个节奏**。可惜纪要又在 Phase 1 之前就把权重定成了 +5/+5，顺序本末倒置。

核心立场：**先验证增量 alpha，再定权重；重叠 85% 的维度，加 3 分都嫌多。**

---

## 二、认同的部分（不展开）

1. 加分方案优于硬合并——不排除无信号票，不推倒重来。
2. 买点1/买点2 分开加分——两者逻辑不同。
3. 重叠风险被识别——纪要 2.2 是全文最清醒的一段。
4. 渐进部署三阶段——节奏对。

---

## 三、保留意见

### 3.1 顺序本末倒置：先定权重再验证，应反过来

纪要 2.2 自己算出买点1重叠 ~39分、买点2重叠 ~46分，却在 3.1 直接折中 +5/+5，然后 Phase 1 才去"验证买点信号是否提供独立增量 alpha"。

**真问题不是"加几分"，而是"买点信号到底有没有独立增量 alpha"。** 应该：

- Phase 1：**0 分**，纯采集统计有信号 vs 无信号股后市表现。
- 数据说话：有独立增量 → 再定加几分；重叠太严重无增量 → 不加。
- 而不是：先定 +5，再去验证。这会预设结论。

### 3.2 权重：倾向 CIO 的 +3/+5，甚至更保守

纪要折中 +5/+5，我倾向 CIO 的判断：

| 信号 | 纪要折中 | CC意见 | 理由 |
|:----|:----:|:----:|------|
| 买点1（回踩反包） | +5 | **+3 或不加** | 与 Consolidation 重叠85%，阈值只差0.018。加5分=回踩特征吃 Consolidation20+买点1 5=25分，占比过高 |
| 买点2（趋势突破） | +5 | **+5** | 与 Breakout 重叠90%，但筹码密集度是纯增量，CIO说得对 |
| 双信号共振 | +8封顶 | **+8~10** | 见 3.3 |

**重叠 85% 的维度，加 3 分都嫌多**——除非 Phase 1 数据证明有独立增量。

### 3.3 双信号共振该加分，不该互斥——纪要自相矛盾

纪要 3.2 第3条："买点1和买点2互斥取最高分（同时出现时取买点1）"
纪要 3.1："两者同时触发 +8分（封顶），双信号共振最有价值"

这两条打架。逻辑上：

- **双信号共振恰恰是最该加分的场景**——两个独立逻辑（回踩反包 + 趋势突破）都确认，互相验证。
- 却要"互斥取最高"？等于把最强信号压成单信号分。

建议反过来：

- 单信号：买点1 +3 / 买点2 +5
- 双信号共振：+8~10（不互斥，共振加分）
- 共振是该被奖励的稀缺场景，不该被互斥掉。

### 3.4 数据接入：离线CSV起步会带滞后信号进实时评分，建议直接实时重算

纪要 3.2 第2条："推荐离线CSV管道（通达信导出→Python读取），后续可升级为Python端实时重算"。

问题：这套评分是给 QMT 盘中实时选股用的。CSV 离线管道意味着买点信号只能 T-1 或盘前生成，盘中用昨天的信号。**可买点信号是日内的**（回踩反包、突破），T-1 信号到今天可能已失效或滞后。

加一个滞后信号进实时评分，可能帮倒忙——选中"昨天有买点、今天已破位"的票。

建议：**直接 Python 端实时重算**（复刻通达信买点公式逻辑）。工程量大些，但时效性对。两套路：

| 方案 | 工程量 | 时效 | 风险 |
|:----|:----:|:----:|:----:|
| 离线CSV | 小 | T-1滞后 | 滞后信号误导实时评分 |
| Python实时重算 | 中（复刻公式） | 实时 | 需对齐通达信公式逐值 |

考虑到 [[筹码复权与对齐坑]] 那类"通达信公式 Python 复刻对齐"的经验，实时重算可行但要逐值验证。

## 四、现实提醒：执行链路优先

这套评分是给**实盘选股**用的。但今天（0702）刚花一天修的 603283 问题说明：**策略现在连"持仓的票该卖"都还没完全卖利索**——孤儿持仓刚修（BUG1/2/4）、反查失败根因 BUG5 还没修。

建议：**先把交易执行链路（买入/卖出/反查/纳管）彻底跑稳，再加第9维度评分。** 否则评分加得再漂亮，选中了票下单下不进去、该卖卖不掉，第9维度是空中楼阁。

纪要 Phase 1 是"1-2周数据采集"——这个窗口正好用来**并行夯实交易执行链路**。Phase 2 再上加分。

## 五、建议汇总

| 项 | 纪要方案 | CC意见 |
|---|---|---|
| 加分形式 | +5/+5 折中 | 倾向 +3/+5，Phase 1 先 0 分采集 |
| 顺序 | 先定权重再验证 | **先验证增量alpha再定权重** |
| 双信号 | 互斥取最高 | **共振应加分不互斥**，+8~10 |
| 数据接入 | 离线CSV起步 | **直接Python实时重算** |
| 上线节奏 | Phase 1-3 渐进 | 同意，但**并行夯实执行链路** |
| 重叠风险 | 识别了仍要加 | 重叠85%加3分都嫌多，先观察 |

## 六、推荐落地路径（调整后）

```
Phase 1 (1-2周): 0分纯采集 + 并行修执行链路
  → 买点信号Python实时重算（复刻通达信公式，逐值对齐）
  → 0分跑，统计有信号vs无信号股后市表现
  → 同时把BUG5（反查失败根因）等执行链路夯实

Phase 2 (3-4周): 保守加分（+3/+5，双信号共振+8），模拟运行
  → 数据支撑下定权重，不预设
  → 按牛/震/熊分层统计
  → 观察排名变化

Phase 3 (第5周起): 数据决定
  → 显著跑赢→可上调权重
  → 无显著差异→撤回纯6+2
```

## 七、一句话结论

**这套方案最该做实的是 Phase 1 的"0分采集验证增量 alpha"，权重等数据说话再定。同时用这两周把执行链路夯稳——评分再准，下单卖不掉也是白搭。**
