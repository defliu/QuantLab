# 卖出策略 V1.0

> **策略名称**：QMT 量化策略 — 四层卖出引擎
> **版本**：V1.0
> **日期**：2026-06-12
> **状态**：已上线

---

## 一、架构概览

卖出系统采用**四层优先级递减**的分层引擎，每层由独立的信号系统触发。核心代码位于两个文件：

| 文件 | 职责 |
|------|------|
| `core/risk_manager.py` | 纯决策引擎 `SellStrategyEngine`，只做信号判断，不执行交易 |
| `strategy_main.py` | 交易执行编排，调用引擎并处理委托、成交确认、换仓、淘汰 |

### 优先级顺序

```
底线层（硬止损） > 清仓层（技术破位） > 预警层（减仓30%） > 确认层（追加减仓50%）
```

---

## 二、引擎入口 & 执行时机

### 2.1 `SellStrategyEngine.evaluate()` — 主入口

**位置**：`core/risk_manager.py` 第 181 行

```
输入：today, holdings_dict, all_data, positions_data
输出：[(code, SellDecision, shares_to_sell), ...]
```

对每只持仓逐只执行 `_evaluate_position()`，按四层优先级依次检查，命中即返回，不再检查低优先层。

### 2.2 执行时机

| 时机 | 代码位置 | 触发条件 |
|------|----------|----------|
| 盘中连续监控 | `strategy_main.py:5543` | 每个 `handlebar` tick，交易时间内 |
| 全天版操作点 | `strategy_main.py:5589` | 0924 / 1000 / 1330 / 1430 |
| 尾盘强制卖出 | `strategy_main.py:5559` | 14:58 之后 |

### 2.3 执行流程

```
SellStrategyEngine.evaluate()
  → _check_and_execute_sell()          # 执行卖出委托
    → _g_trader.sell()                 # 下卖出单
    → _g_pending_sells[code] = {...}   # 记录待确认委托
  → _check_pending_sells()             # 轮询成交状态
    → 全部成交 → _finish_pending_sell() → 更新累计盈亏
    → 部分成交 → 撤单重下剩余
    → 未成交 → 撤单重试（retry >= 1 则市价重试）
    → 跌停 → 移入跌停等待队列
  → _check_limitdown_sells()           # 跌停队列管理
    → 跌停打开 → 立即重卖
    → 连续跌停5天 → 强制卖出
```

## 三、四层卖出引擎详解

### 3.1 底线层（最高优先级）

**代码**：`core/risk_manager.py` 第 466–491 行

无条件硬止损，触发即**清仓**：

| 条件 | 参数 | 阈值 | 动作 |
|------|------|------|------|
| 累计亏损 | `BOTTOM_LINE_LOSS_PCT` | ≤ -5% | 清仓 |
| 单日跌幅 | `BOTTOM_LINE_DAILY_DROP_PCT` | ≤ -7% | 清仓 |

```
累计亏损 = (current_price - cost_price) / cost_price
单日跌幅 = (current_price - prev_close) / prev_close
```

---

### 3.2 清仓层

**代码**：`core/risk_manager.py` 第 535–563 行

任一条件触发即**清仓**。注意：如果预警层已触发但确认层尚未处理，则跳过移动止盈检查，让确认层优先决策。

| 信号 | 条件 | 参数 |
|------|------|------|
| **A3: 破20日线** | 收盘价连续 3 天低于 MA20 | `CLEAR_MA20_DAYS = 3` |
| **C3: 破最高日低点** | 当前价 < 近30日最高价那天的低点 | — |
| **移动止盈** | 见下表 | 见下表 |

#### 移动止盈分级

**代码**：`core/risk_manager.py` 第 569–607 行

| 盈利区间 | 止盈条件 | 参数 |
|----------|----------|------|
| 盈利 < 10% | 跌破 MA5 | `TRAILING_BREAK_MA5_INTERVAL = 0.10` |
| 10% ≤ 盈利 < 20% | 从最高点回撤 ≥ 6% | `TRAILING_DRAWDOWN_LO = 0.06` |
| 20% ≤ 盈利 < 30% | 从最高点回撤 ≥ 8% | `TRAILING_DRAWDOWN_MID = 0.08` |
| 盈利 ≥ 30% | 从最高点回撤 ≥ 10% | `TRAILING_DRAWDOWN_HI = 0.10` |
| 任意盈利 | 吊灯止盈：当前价 ≤ 最高价 − 3×ATR(14) | `CHANDELIER_ATR_MULTIPLE = 3` |

> 移动止盈仅盈利 > 0 时生效，盈利 ≤ 0 时不检查。

---

### 3.3 预警层（减仓 30%）

**代码**：`core/risk_manager.py` 第 424–447 行

仅在**尚未预警**时检查。任一信号触发 → **减仓 30%**，并标记 `warning_reduced = True`。

| 信号 | 条件 | 参数 |
|------|------|------|
| **B1: 爆量分歧** | 成交量 > MA5×1.5 且长上影线 | `VOLUME_RATIO_THRESHOLD = 1.5` |
| **B2: 量价背离** | 价格在5日高点但成交量 < 前日 70% | `VOLUME_DIVERGE_THRESHOLD = 0.70` |
| **C2: MACD红柱缩短** | MACD 红柱连续 3 天缩短（红柱须仍为正） | `MACD_SHORTEN_DAYS = 3` |
| **KDJ死叉+MA5走平** | MA5 斜率角度 ≤ 15° 且 KDJ 死叉 | `MA5_SLOPE_FLAT_DEG = 15` |

#### B1 次日追踪机制

**代码**：`core/risk_manager.py` 第 497–505 行

B1 触发后设置 `b1_needs_nextday_check = True`。次日在确认层检查中：
- 如果价格 ≤ MA5 **且** ≤ 开盘价 → 未修复 → **追加减仓 20%**（`WARNING_ADD_REDUCE_PCT = 0.20`）
- 如果价格 > MA5 **且** > 开盘价 → 已修复，清除 B1 标记

---

### 3.4 确认层（减仓 50%）

**代码**：`core/risk_manager.py` 第 449–458 行，第 511–529 行

仅在**预警层已触发** 且 **确认层尚未触发**时检查。任一信号触发 → **减仓 50%**（`CONFIRM_REDUCE_PCT = 0.50`）。

| 信号 | 条件 |
|------|------|
| **A2: 破10日线** | 收盘价低于 MA10 |
| **C1: 高位长上影** | 近5日最高价 ≥ 10日前收盘 × 1.05 且今日长上影 |
| **B3: 高位天量收阴** | 近5日最高价 ≥ 近20日最高价 × 0.95，阴线，成交量 ≥ MA5 × 1.5 |

## 四、状态机

每只持仓维护一个 `SellPositionState` 对象（`core/risk_manager.py` 第 96 行），记录完整生命周期：

```
买入 → 预警触发(warning_reduced) → 确认触发(confirm_reduced) → 清仓(cleared)
                                    ↘ 反弹回购(rebound_restored) → 重置回正常
                                    ↘ B1隔日未修复(warning_add) → 追加减仓
```

### 关键状态字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `warning_reduced` | bool | 预警层已减仓 |
| `warning_trigger_date` | str | 预警触发日期 |
| `b1_needs_nextday_check` | bool | B1 信号待隔日确认 |
| `b1_additional_reduced` | bool | B1 次日追加减仓已执行 |
| `confirm_reduced` | bool | 确认层已减仓 |
| `cleared` | bool | 已清仓 |
| `cleared_date` | str | 清仓日期 |
| `reduction_volume` | int | 累计减仓股数（用于反弹回购） |
| `highest_price` | float | 持仓期间最高价（用于移动止盈） |
| `entry_date` | str | 买入日期（用于淘汰计算） |

## 五、换仓逻辑

### 5.1 买入阶段换仓（`strategy_main.py:4942-5009`）

当 `MAX_HOLD` 已满且无可直接买入的候选时触发：

1. 对全部持仓打分排序（低分优先）
2. 检查淘汰条件：持有 ≥ 5 天 且 收益 < 3%
3. 换仓门槛：
   - 非淘汰标的：候选评分 ≥ 持仓评分 + **15**
   - 淘汰标的：候选评分 ≥ 持仓评分 + **10**
4. 评分 ≥ 70 的非淘汰标的不参与换仓
5. 卖出成交确认后，候选股插入队列头部自动买入

### 5.2 全天决策矩阵换仓（`strategy_main.py:5279-5306`）

在每个操作点（0924/1000/1330/1430）执行：

- **REDUCE 决策换仓**：卖出引擎返回 REDUCE 且持仓评分 < 70 → 找候选 → gap ≥ 15 → 换仓
- **淘汰换仓**：未被卖出引擎标记但满足淘汰条件 → gap ≥ 15 → 换仓

### 5.3 `_execute_swap()` 函数（`strategy_main.py:5328`）

1. 获取可用股数（取整百）
2. 卖出全部持仓（`is_clear = True`, `pct = 1.0`）
3. 候选股插入 `_g_candidate_queue` 头部
4. 卖出成交确认后自动买入替换

## 六、淘汰逻辑

```
条件：持仓天数 ≥ 5 天 且 (当前价 - 成本价) / 成本价 < 3%
```

- 持仓天数使用**自然日**计算
- 在买入阶段换仓中降低 gap 门槛（15 → 10）
- 在全天决策矩阵中直接尝试换仓（gap ≥ 15）
- 若无合适候选则继续持有

## 七、辅助机制

### 7.1 反弹回购

**代码**：`core/risk_manager.py` 第 335–393 行

预警减仓后 3 天内（`REBOUND_WINDOW_DAYS = 3`），同时满足：
- 当前价 > MA5
- 当前价 > 今日开盘价
- 当前价 > 昨日最高价

→ 买回 `reduction_volume` 股，重置状态机所有标记。

### 7.2 禁止重入

**代码**：`core/risk_manager.py` 第 260–282 行

清仓后 **20 个交易日**内（`NO_REENTRY_DAYS = 20`）不得再次买入同一标的。到期后自动清除状态记录。

### 7.3 T+1 处理

无最低持有时间限制，当日买入当日可卖出（简化处理）。

### 7.4 跌停卖出队列

**代码**：`strategy_main.py:4468-4536`

- 卖出委托未成交且标的跌停 → 移入 `_g_pending_limitdown_sells`
- 跌停打开 → 立即重新挂卖单
- 连续跌停 5 天 → 强制市价卖出

### 7.5 卖出失败冷却

**代码**：`strategy_main.py:4336-4342`

卖出委托失败后 **60 秒**冷却，期间不再对该标的发起卖出。

### 7.6 尾盘处理（14:58+）

- 撤销所有未成交买单
- 清空重试队列
- 撤销所有未成交卖单
- 执行最后一次 `_check_sell()` 强制卖出检查
