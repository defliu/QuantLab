## 0. 文档范围

**范围内**：数据层、回测引擎、7 类策略模块、绩效评估、QMT/Ptrade 实盘适配层、风控与监控。

**文档定位（2026-09-30 补，评审 P0-1）**：本 PRD 是 **QuantLab 既有平台的演进需求**，不是新建平台；§7 交付物逐项按「复用 / 改造 / 新建」三分标注，禁止重复建设。既有资产映射：

## 1. 总体架构（分层）

| 层 | 职责 | 关键接口 |
|---|---|---|
| L1 数据层 | 行情/财务/另类数据接入、清洗、存储 | `DataSource.get_bars()`, `get_factor()` |
| L2 指标层 | 技术指标、因子计算（无未来函数） | `Indicator.*`, `Factor.*` |
| L3 策略层 | 信号生成 → 目标持仓（**只输出目标权重，不下单**） | `Strategy.next() -> TargetPortfolio` |
| L4 组合层 | 多策略权重分配、风险预算 | `PortfolioAllocator` |
| L5 回测层 | 逐 bar 撮合、成本、滑点、绩效 | `Backtester.run()` |
| L6 执行层 | 订单路由、拆单、撤单、回报 | `BrokerAdapter`（QMT/Ptrade 实现） |
| L7 风控层 | 事前/事中/事后风控 | `RiskGate.check()` |
| L8 监控层 | 日志、告警、净值曲线、异常检测 | `Monitor` |

**核心设计原则**：L3 与 L6 解耦。策略只产出 `TargetPortfolio{code, weight, reason}`，由 L6 负责"当前持仓 → 目标持仓"的委托单生成。

## 2. 数据层需求（L1）

| 项目 | 需求 |
|---|---|
| 周期 | 日线、分钟（1/5/15）、Tick（可选） |
| 字段 | OHLCV、amount、turnover、adj_factor、limit_status（涨跌停）、suspend、ST 标记 |
| 复权 | 前复权用于信号，后复权用于净值；**必须记录复权方式** |
| 幸存者偏差 | 回测需含退市/ST 历史快照，股票池按**当时**成分股快照 |
| 质量检查 | 缺口检测、异常值（涨跌幅>阈值）、停牌标记、时间戳对齐 |
| 数据接口 | 抽象 `DataSource`，支持 CSV/Parquet 本地、QMT `xtdata`、Ptrade `get_history` |
| **财务/另类数据 PIT（硬条款，2026-09-30 补，评审 P0-4）** | 一律按公告日 `ann_date`/`f_ann_date` 对齐，**禁止按报告期直接入模**；任意回测时点 t 的可见性 = 公告日 ≤ t；未带公告日的字段不得进入回测 |

**验收**：给定任意日期，能还原该日可交易股票池；数据缺失率报表自动生成；财务字段随机抽样前视检查通过（公告日之前该字段值不可见）。

## 3. 通用模块需求


### 3.1 成本模型


- 佣金（双边，默认万 1，可配）、印花税（卖出千 0.5，可配）、过户费
- 滑点：固定 bp 或 按成交量占比（参与率）函数
- 冲击成本：`slippage = k * (order_volume / bar_volume)^γ`，k、γ 可配




### 3.2 仓位与约束


- 单票上限、行业上限、总仓位上限、杠杆上限、最大持仓数
- 禁止买入当日涨停/停牌/ST（可配开关）




### 3.3 风控（L7）


- 事前：资金/持仓校验、黑名单
- 事中：单日最大亏损、最大回撤触发降仓/停机、连续亏损 N 次暂停
- 事后：净值异常波动、委托失败率告警




### 3.4 绩效指标

年化收益、年化波动、Sharpe、Sortino、Calmar、MaxDD 及发生区间、胜率、盈亏比、换手率、IC/IR（因子策略）、交易次数、暴露度（行业/市值/风格）。

## 4. 策略模块需求规格


> 每个策略统一输出：信号值 → 目标权重。默认参数仅作起点，**必须标注"需调优"**。
> 
> **验收口径基线（2026-09-30 补，评审 P0-2）**：以下五要素为 S1–S7 验收的默认绑定，任何策略偏离须显式写出，**缺一即视为不可验收**：
> ① 回测区间 2019-01-01 ~ 2024-12-31（六年，含 2019 牛市与 2021–2024 熊市）；
> ② 成本口径 = §3.1 默认（佣金万 1 双边 + 印花税卖出千 0.5 + 过户费 + 默认滑点），另出成本 ×2 敏感性；
> ③ 数据源 = `D:/astock/` 日线（净值用后复权核算），定稿后按仓库规则抽 1 个自然年做备用源交叉验证；
> ④ 频率 = 日频（信号 t 日收盘后生成、t+1 执行），分钟级策略另行标注；
> ⑤ 基准 = 沪深300 与中证500 双基准（A 股股票策略）；期货/跨品种策略基准在立项时补录。

### S1 均值回归（Mean Reversion）


- **假设**：价格偏离统计中枢后会回归
- **输入**：收盘价、20 日均值/标准差（参数 N=20，K=2，需调优）
- **信号**：Z-score = (P − MA_N) / σ_N；Z < −K 做多，Z > +K 平仓/反手
- **过滤**：剔除上市<1 年、停牌、近 20 日波动率分位>90%、处于单边趋势（ADX>25 可配）
- **出场**：Z 回归 0 附近、持有上限 T 日、止损 −X%
- **风控**：单票 ≤2%，总仓 ≤60%
- **验收**：费后年化 Sharpe ≥ 0.8 且 MaxDD ≤ 15%；口径按 §4 基线五要素，样本内 = 2019–2021、样本外 = 2022–2024（样本外单独达标才通过）




### S2 动量突破（Momentum Breakout）


- **假设**：趋势具有延续性
- **输入**：N 日高低点（N=20）、ATR（N=14）
- **信号**：收盘价突破 N 日高点做多，跌破 N 日低点做空/平仓；可选均线斜率确认
- **过滤**：成交量放大 ≥ 1.5 倍均量；剔除上市<60 日
- **出场**：ATR 移动止损（2×ATR）、时间止损、反转突破
- **仓位**：波动率倒数加权（risk parity per position）
- **验收**：①趋势段（**事前**定义：基准 60 日收益 ≥ +10% 的连续区间）组合年化超额 ≥ +5pp 且超额 t 值 > 2；②震荡段（|60 日收益| ≤ 5%）最大回撤 ≤ 15%；③全期按 §4 基线五要素结算；任一项不达标判不通过




### S3 统计套利（Statistical Arbitrage）


- **假设**：多资产价差序列平稳（协整）
- **输入**：候选资产对/篮子日频或分钟价差
- **建模**：Engle-Granger 或 Johansen 协整检验（p<0.05），OLS 得对冲比 β；滚动窗口重估（60/120 日）
- **信号**：标准化价差 Z > +2 做空价差，Z < −2 做多价差，|Z|<0.5 平仓
- **过滤**：半衰期 < 30 日、价差波动率下限、流动性下限
- **风控**：协整关系失效检测（滚动 p 值恶化）、价差发散止损（|Z|>4）、多空市值中性
- **验收**：价差序列 ADF 检验通过；多空组合市场中性（Beta 绝对值 < 0.2）




### S4 配对交易（Pairs Trading）


- **定位**：S3 的特例（两资产），独立模块便于对比
- **输入**：两只高相关标的（行业/产业链相关），相关系数滚动窗口 120 日 > 0.7
- **信号**：价差 Z-score 开平仓；可选距离法（标准化价格距离）
- **差异点**：固定 1:1 或 β 对冲；要求**融券/做空可用性**配置（不可做空时仅做多头替代或放弃）
- **风控**：单对资金上限、价差结构突变（Chow 检验/滚动相关性跌破阈值）强制平仓
- **验收**：与 S3 结果可对比；交易频率与成本敏感性报告




### S5 多因子模型（Multi-Factor）


- **假设**：因子暴露可解释并预测横截面收益
- **因子库（至少）**：
  - 价值：EP、BP、DP
  - 质量：ROE、ROA、毛利率变化
  - 成长：营收/净利同比增速
  - 动量：过去 20/60/120 日收益（剔除最近 1 月）
  - 波动/流动性：波动率倒数、换手率
  - 规模：流通市值对数

  
- **流程**：去极值（MAD/3σ）→ 中性化（行业+市值）→ 标准化 → 加权（等权/IC_IR 加权/优化）
- **评估**：分层回测（5/10 组）、IC 均值与 IR、换手率、因子相关性矩阵
- **组合**：Top N 只（N=20，可配），行业中性约束，月度/周度调仓
- **验收**：多头组合年化超额基准 > 0，IC 均值 > 0.03，分组单调性成立




### S6 网格交易（Grid Trading）


- **假设**：区间震荡，波动可收割
- **输入**：基准价 P0、网格间距 g%（等差/等比可配）、每格手数、网格上下界
- **逻辑**：价格每下跌一格买入一份，每上涨一格卖出一份；触界暂停或重置
- **过滤**：仅适用于震荡品种；需计算历史区间命中率
- **风控**：总仓位上限、跌破下界止损（防止"接飞刀"）、资金占用上限、单边行情检测（连续 N 格同向触发告警）
- **验收**：网格区间须**事前**认定（滚动 250 日价格上下界，参数与边界仅用区间形成期之前数据，禁止事后画框）；事前区间内策略费后净收益 > 持有基准；单边下跌情景（跌破下界后继续 -20%）总亏损 ≤ 组合资金 8%；全期按 §4 基线五要素结算




### S7 CTA 趋势跟踪（CTA Trend Following）


- **假设**：期货趋势持续性 + 波动率自适应
- **输入**：主力连续合约（需处理换月跳空）、多周期（日线/小时线）
- **系统**：通道突破（Donchian）+ 均线系统（双均线）可选并联；ATR 波动率目标仓位（目标年化波动 10–15%，可配）
- **组合**：多品种分散（商品/金融期货），等风险贡献
- **出场**：跟踪止损、波动率扩张减仓、换月规则（主力合约切换前 N 日移仓）
- **风控**：单品种 ≤10%，总杠杆 ≤2，保证金占用监控，隔夜风险
- **验收**：§4 基线区间 2019–2024 全期（期货数据源待 Q4 确认后锁定）多品种组合 Calmar ≥ 0.8；与股票策略净值相关性 < 0.3（同区间日频）

## 5. 回测引擎需求（L5）

| 需求项 | 说明 |
|---|---|
| 撮合规则 | 日频：次开盘/收盘价成交（可配）；分钟频：当根 bar 收盘价或限价模拟 |
| 防未来函数 | 信号仅用 t−1 及之前数据；当日数据 t 日收盘后才可用 |
| 订单生命周期 | 下单 → 部分成交/拒单 → 回报；支持限价/市价 |
| 资金管理 | 可用资金、冻结、保证金（期货）、手续费逐笔扣减 |
| 事件驱动 | 按时间轴推进，支持股票+期货混合 |
| 输出 | 逐日净值、逐笔成交、持仓快照、绩效报告（HTML/PDF） |
| 复检工具 | 换手率异常检测、收益来源分解（因子/行业/择时） |
| **引擎验证套件（验收硬项，2026-09-30 补，评审 P0-3）** | 回测引擎交付 = 通过两类套件：**B 类**（已知结果校验、成本逐笔、涨跌停/停牌、资金约束、先卖后买、止损、回测一致性，参照 `projects/verification/engine_tests.py` B-1~B-8）+ **D 类**（子样本、牛熊分割、压力、成本压力、容量、未来函数、幸存者偏差，参照 `robustness_tests.py` D-1~D-7） |
| **look-ahead 三类检验（评审 P0-3 关联）** | 复权 look-ahead、宇宙选择 look-ahead（静态池套全期）、撮合 look-ahead（盘中取当日 close）逐项过检；干净判别法：盘中 vs 尾盘对照差异 >30pp 且方向反转即判失败 |

**验收**：①同一策略在回测与模拟盘的信号序列逐 bar 一致（容差 0）；②上表「引擎验证套件」B/D 类全部通过——**此项先于任何策略验收，引擎未过套件则策略结论一律无效**。

## 6. 实盘执行层需求（L6，QMT / Ptrade）


### 6.1 统一适配接口


```text
BrokerAdapter:
  connect(config) / disconnect()
  get_positions() -> Position[]
  get_account() -> {cash, market_value, frozen, margin}
  order(code, side, volume, price_type, price=None) -> OrderID
  cancel(order_id)
  on_tick / on_bar / on_order / on_trade   # 事件回调
```

### 6.2 QMT（迅投）实现要点

- 使用 `xtquant`（`xtdata` 取数、`xt_trader` 交易）；支持 miniQMT 独立模式
- 支持 Python 策略 + VBA 兼容（按团队技术栈选择）
- 全推/订阅行情、篮子交易、算法单（TWAP/VWAP 拆单）
- 本地运行：需常驻进程与断线重连机制
- **生产硬约束（2026-09-30 补，评审 P0-5，不满足即交付返工）**：
  - 双 Python 版本：研究 3.11 / QMT 内置 **3.6.8**；产物禁用 `dict[str, ...]`、`list[str]`、`str | None`、`:=`、`match/case`、f-string 等不支持或禁用语法
  - 产物为 GBK 单文件、首行 `# coding=gbk`，内嵌 `BUILD_TAG`（`YYYYmmdd-HHMMSS`），`init()` 与每日日志/日终报告输出该标记
  - 部署 = 客户端策略编辑器**人工粘贴**（复制到运行目录无效、粘贴不可自动化）；部署后核对日志 `BUILD_TAG` 与本地构建一致
  - `passorder` 为全局函数且**异步、正常返回无订单号**：真实订单号须 `get_trade_detail_data` 反查并短轮询容忍 ~100ms 分配延迟，反查失败不得断链（必须落 pending 状态）
  - 数据源用 CSV（QMT 内置 Python 无 pyarrow，不能读 parquet）；PE/PB/市值等财务字段来自预生成 CSV

### 6.3 Ptrade（恒生）实现要点

- 券商内置 Python 环境，事件驱动（`initialize` / `handle_data` / `before_trading_start`）
- 云端运行，无需本地常驻；注意函数调用频率与额度限制
- 支持普通/融资融券、篮子、条件单

### 6.4 通用要求

- **双环境**：模拟盘 → 实盘，最少模拟运行 N 个交易日（由研究阶段定）
- 幂等与断点续跑：重启后能恢复持仓与信号状态
- 限频与限流：委托频率上限、失败重试上限（≤3 次）、重复下单拦截
- 时间同步：交易时段判断、集合竞价处理、节假日历
- 审计：每笔委托/成交落库，保留原始回报
- **对账与订单状态机（2026-09-30 补，评审 P0-6）**：

### 10.3 我对 §9 的 3 处异议（同题不同判断）

**异议 1：S1 的"族归属"判错，会误导排期序。**
§9 9.4-1 把 S1 均值回归归为"与 05 红利低波同族"，并据此排在 S5 之后第二位。但 S1（Z-score 反转：Z < −K 做多）在**信号构造上属反转族**，与"低波+股息"的红利低波不是同族。仓库对反转族的实证是**明确为负**：P07 低换手反转 -6.9%/年、P01 全池反转因子超额 -9.0%/年，因子健康监控中动量/反转类均 FAILED/WATCH。

**异议 2：MA200 大盘门控不宜写成通用条款。**
§9 9.4-2 引用"MA200 门控：回撤 -29.7% → -15.8%、年化代价 -4.4pp，做成可配"，隐含"门控是正向机制"。但仓库结论是**策略依赖**的：该正结果出自 **P10 价值小盘**；而在 **ATR 低波**上实测 MA200 门控 exit/hold **两档均为负优化**（`研究总览与路线图.md` §五）。
**建议**：PRD 写"门控可配 + 每个策略须独立实证"，**不要写成继承性红线**，否则会把一个在部分策略上负向的机制固化成"最佳实践"。

**异议 3：§9 对 P0-2 的"五要素"方向对，但漏了更硬的一条——风控执行频率必须与实盘一致。**

### 10.4 排期方法论：建议把"横向分层"改为"纵向切片"（与 §9 最大的不同意见）

§9 给的是**策略优先级序**（S5→S1→S2/S7→S6/S3/S4），但 §1 的 8 层架构 + §7 的 8 项交付物是**横向分层**的：先建完 L1–L8，再上策略。对个人投资者单机项目，这是最大的排期陷阱——L1–L8 全量建完可能耗掉全部预算，却一次真实下单都没验证过；而实盘风险全在 L6/L7（仓库实测：**8 成 bug 在 QMT 集成层，MOCK 测不到**）。

**建议 v1.1 增"里程碑切片"：**
- **M0（打通）**：单策略 × 单标的池 × 一条纵向链路（数据 → 信号 → 回测 → 模拟盘 → 实盘下单 → 对账 → 日报），L1–L8 只做最小可用。验收 = 真实模拟盘跑通 1 个交易日且日志与对账一致。
- **M1（可信）**：接入 `projects/verification/` 全套件（B/D/E），把"引擎正确性"与"策略有效性"**分开验收**。

理由：M0 成本远低于"建完 8 层"，但它验证的是**最贵的那部分**（执行链路 + 对账 + 风控），符合仓库既有教训。
