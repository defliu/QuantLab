## 0. 文档范围与定位

**文档定位**：本 PRD 是 **QuantLab 存量资产的演进整合需求**，不是从零新建平台。L1–L8 各层与既有资产（`data/`、`factors/`、`strategy/`、`backtest/`、`broker/`、`risk/`、`projects/verification/`、`config/`）的复用/改造/新建关系见**附录 C 映射表**——8 层中 6 层有可用存量，任何排期不得重复建设已有能力。

**范围内**：数据层、回测引擎、7 类策略模块、绩效评估、**QMT** 实盘适配层、风控与监控。

**范围外（非目标）**：自动调参寻优的遗传算法引擎、机器学习平台（**新建**机器学习训练/研究平台出范围——存量 LightGBM 实盘链路属运行中资产，不在重建范围）、图像/新闻 NLP、真实资金账户管理、**Ptrade 适配器（后撤，挂 Q15——全仓库零实现/零数据/零账号实证，须先回答"为什么需要第二家券商通道"，答不上来就永不建）**。

**关键约束**

1. 所有策略必须可回测、可参数化、可关闭；**禁止硬编码标的与固定仓位**。
2. **回测与实盘共用同一信号语义**。等价性不由"物理同一套代码"保证（QMT 生产形态为构建生成的 GBK 单文件，见 §6.2），而由**构建管线**保证：`build.py` 构建四道校验 → 产物硬编码 `BUILD_TAG` → `broker/local_context.py`（LocalContext）本地 miniQMT 验证 → 模拟盘 1 交易日日志核对 BUILD_TAG；最终验收 = §5 逐 bar 信号对账（容差 0）。
3. 任何策略上线前必须通过「**预注册证伪线 + 样本外测试 + 成本敏感性测试**」三道门槛——判据先锁定再跑数（防 p-hacking，P21 预注册模式）。
4. **财务/另类数据一律 PIT 安全**：按公告日（`ann_date`/`f_ann_date`）对齐，禁止按报告期直接入模。
5. 验收标准必须绑定〔回测区间、成本口径、数据源、频率、基准〕**五要素**；未绑定视为不可验收（§3.4/§4 基线）。

## 1. 总体架构（分层）

| 层 | 职责 | 关键接口 |
|---|---|---|
| L1 数据层 | 行情/财务/另类数据接入、清洗、存储、口径管理 | `DataSource.get_bars()`, `get_factor()` |
| L2 指标层 | 技术指标、因子计算（无未来函数） | `Indicator.*`, `Factor.*` |
| L3 策略层 | 信号生成 → 目标持仓（**只输出目标权重，不下单**） | `Strategy.next() -> TargetPortfolio` |
| L4 组合层 | 多策略权重分配、风险预算、**虚拟子账户资金隔离** | `PortfolioAllocator` |
| L5 回测层 | 逐 bar 撮合、成本、滑点、绩效；**风控/结算频率与实盘强制同源** | `Backtester.run()` |
| L6 执行层 | 订单路由、拆单、撤单、回报、**对账（reconcile）** | `BrokerAdapter`（QMT 实现；Ptrade 暂缓见 Q15） |
| L7 风控层 | 事前/事中/事后风控（数值底线见 §3.3） | `RiskGate.check()` |
| L8 监控层 | 日志、告警、净值曲线、异常检测、**因子健康与退役监控** | `Monitor` |

**核心设计原则**：L3 与 L6 解耦。策略只产出 `TargetPortfolio{code, weight, reason}`，由 L6 负责"当前持仓 → 目标持仓"的委托单生成。各层与既有资产的复用关系见附录 C。

## 2. 数据层需求（L1）

| 项目 | 需求 |
|---|---|
| 周期 | 日线、分钟（1/5/15）、Tick（可选） |
| 字段 | OHLCV、amount、turnover、adj_factor、limit_status（涨跌停）、suspend、ST 标记 |
| 复权 | 前复权用于信号，后复权用于净值；**必须记录复权方式**；前复权基准日必须滚动（以当日为基准），**禁用全期终点复权**（防复权 look-ahead） |
| 幸存者偏差 | 回测需含退市/ST 历史快照，股票池按**当时**成分股快照 |
| 质量检查 | 缺口检测、异常值（涨跌幅>阈值）、停牌标记、时间戳对齐 |
| 数据接口 | 抽象 `DataSource`，支持 CSV/Parquet 本地、QMT `xtdata`；备用源 gpsj（DuckDB，全市场覆盖仅 2015-01 起）用于交叉验证 |
| 双源交叉验证 | 每个策略回测定稿后，用备用源随机抽取 1 个自然年做同区间对比，CAGR/最大回撤差异 **>1pp 必须排查口径**；源不可用时在报告显著位置标注「**单源结论，未经交叉验证**」（不静默跳过、不阻断交付） |
| 数据更新 | 离线包升级（主行情全量替换迁移 + 写后复核报告）+ 在线增量保鲜（best-effort，失败只告警不阻断）双轨（Q8） |

**PIT 硬条款**：财务/另类数据一律按**公告日**（`ann_date`/`f_ann_date`）对齐入模，禁止按报告期直接入模；**未带公告日的财务字段不得进入回测**。任何涉及财务数据的改动必须验证无前视偏差。此为不可妥协红线。

**字段口径表**（引用仓库既有口径，禁止重新定义）：

| 字段 | 口径 |
|---|---|
| `circ_mv` | 单位**万元**（30 亿 = 300000） |
| `adj_factor` | **后复权**因子；前复权价 = 原始价 × `adj_factor` / 最新 `adj_factor` |
| gpsj `收盘价` | 是前复权价，**禁止直接用**；须取 `不复权_*` 列 + `复权因子` |
| amount / turnover | 单位按数据源字典注明，随数据质量报表交付 |

**A 股微观结构（回测撮合必须建模）**：

- 涨跌幅**按板块区分**：主板 10%、创业板/科创板 20%、ST 5%、北交所 30%——直接决定"能否成交"判定
- 价格笼子：2020 起连续竞价申报价限制
- T+1 交收：当日买入不可当日卖出；卖出资金当日可用不可取
- 除权除息对持仓成本/可用股数的影响、配股与要约

**验收**：给定任意日期，能还原该日可交易股票池；数据缺失率报表自动生成；字段口径表与数据字典随数据质量报表交付；**财务数据 PIT 抽查：随机时点回放无公告日前视**。

## 3. 通用模块需求

### 3.1 成本模型

- 佣金（双边，默认万 1，可配）、印花税（卖出千 0.5，可配）、过户费
- 滑点：固定 bp 或 按成交量占比（参与率）函数
- 冲击成本：`slippage = k * (order_volume / bar_volume)^γ`，k、γ 可配
- 成本参数**校准来源必须披露**（实测费率 vs 假设值，Q11）；成本口径写入验收五要素

### 3.2 仓位与约束

- 单票上限、行业上限、总仓位上限、杠杆上限、最大持仓数
- 禁止买入当日涨停/停牌/ST（可配开关）

### 3.3 风控（L7）

- **数值底线（继承全局红线，策略只能更严不能更松）**：个股止损 8%（P16 系 -7% 为已批准的更严例外）、组合最大回撤 15%、最长持有 60 天、单日最大换手 30%
- **大盘门控 = 可配开关，每策略独立实证后才允许开启**（仓库实证策略依赖：价值小盘上为正优化、ATR 低波上为负优化，不得写成继承性红线）；开启时引用"确定性脚本输出 T 档、执行端只读"模式（`market_tier.py` 范式），禁止 agent 自行用其他行情源重算
- 事前：资金/持仓校验、黑名单
- 事中：单日最大亏损、最大回撤触发降仓/停机、连续亏损 N 次暂停
- 事后：净值异常波动、委托失败率告警
- 涉及清仓、减仓、禁入期、状态持久化、跌停暂缓的逻辑改动，必须补充或更新测试

### 3.4 绩效指标与口径

**验收五要素规则**：每条策略/引擎验收必须绑定〔回测区间、成本口径、数据源、频率、基准〕；缺一视为不可验收。**默认绑定值见 §4「验收口径基线」**；未定值集中在附录 A 并标注阻塞项。

**基准口径表**（默认值 2026-10-01 立，禁止跨策略混用；偏离须在预注册时显式写出）：

| 策略 | 基准 | 备注 |
|---|---|---|
| S1–S4、S6（默认） | **沪深300 与中证500 双基准**（§4 基线⑤） | 偏离须随预注册显式声明 |
| S5 多因子 | 默认双基准；倾向中证 500+1000 或等权全 A（随预注册锁定） | 须与股票池风格一致 |
| S7 CTA | 【待定：商品指数复合基准】 | 阻塞于 Q1 |

**收益与净值口径**：TWR（时间加权）为默认口径（应对出入金）；分红再投资 vs 现金处理须声明；**年化一律复利口径**（线性年化须显式标注——仓库实测线性口径曾致卡玛 1.17→0.86 虚高修正）；无风险利率来源须声明。

**指标清单**：年化收益、年化波动、Sharpe、Sortino、Calmar、MaxDD 及发生区间、胜率、盈亏比、换手率、IC/IR（因子策略）、交易次数、暴露度（行业/市值/风格）。

**过拟合度量**：调优类策略须报告 **PBO（过拟合概率）** 与 **Deflated Sharpe Ratio**；**参数搜索空间与试错次数必须披露**（写入 §8a Gate）——否则无法判断达标值是真信号还是搜出来的。

## 4. 策略模块需求规格

> 每个策略统一输出：信号值 → 目标权重。**参数值属于 specs/ 层**：本节出现的具体数值仅为示例起点，正式参数在项目 `specs/` 预注册时锁定。
> **每策略两条硬门槛**：①「阻塞项」行——阻塞未解除不得立项；②「预注册证伪线」——判据先锁定再跑数，未过线按 P12/P18/P21 模式归档结题，不得软性"再调调看"。
> **推荐排期序**：S5（存量最多，P01/P10 评分与实盘链路可复用）→ S1/S2/S7（先过预注册证伪线再立项）→ S6/S3/S4（阻塞项解除后再议）。
>
> **验收口径基线（2026-10-01 立，S1–S7 验收的默认绑定；任何策略偏离须显式写出，缺一即视为不可验收）**：
> ① 回测区间 **2019-01-01 ~ 2024-12-31**（六年，含 2019 结构牛与 2021–2024 长熊）；
> ② 成本口径 = §3.1 默认（佣金万 1 双边 + 印花税卖出千 0.5 + 过户费 + 默认滑点），另出成本 ×2 敏感性；
> ③ 数据源 = `D:/astock/` 日线（净值用后复权核算），定稿后按仓库规则抽 1 个自然年做备用源交叉验证；
> ④ 频率 = 日频（信号 t 日收盘后生成、t+1 执行）；分钟级策略另行标注；
> ⑤ 基准 = 沪深300 与中证500 双基准（S5/S7 见 §3.4 口径表）；
> ⑥ **最终保留集（final holdout）**：**2025-01-01 起至最新数据为一次性保留集**——任何策略的参数选择/调优/迭代不得触碰该区间；仅在全部其他 Gate（§8a）通过后做**一次性**最终验证，验证后区间即封存。此条防「基线区间内反复调参、保留集反复进出」的慢性 p-hacking。

### S1 均值回归（Mean Reversion）

- **阻塞项**：无。但属**反转族**（Z-score 时序反转），仓库对反转族 PIT 实证为负（P07 低换手反转 -6.9%/年、P01 幸存者偏差修复审计后反转因子超额转负、P21 F1 毛 alpha 恒 0）——**必须先过预注册证伪线，举证责任在策略方**（"带趋势/波动过滤的条件反转"与"裸横截面反转"不是同一命题，但不豁免预注册）。
- **假设**：价格偏离统计中枢后会回归
- **输入**：收盘价、20 日均值/标准差（参数 N=20，K=2，示例值，需调优）
- **信号**：Z-score = (P − MA_N) / σ_N；Z < −K 做多，Z > +K 平仓（**A 股现货无做空，「反手」不作默认**；若 Q3 解锁做空权限，反向腿须另行预注册）
- **过滤**：剔除上市<1 年、停牌、近 20 日波动率分位>90%、处于单边趋势（ADX>25 可配）
- **出场**：Z 回归 0 附近、持有上限 T 日、止损 −X%
- **风控**：单票 ≤2%（示例），总仓 ≤60%（示例），且不得松于 §3.3 数值底线
- **验收（默认基线，2026-10-01 立）**：费后年化 Sharpe ≥ 0.8 且 MaxDD ≤ 15%，按 §4 基线五要素结算，**样本内 = 2019–2021、样本外 = 2022–2024，样本外单独达标才通过**；Sharpe 的计算频率与无风险利率口径随预注册锁定（v1.0 无口径的「Sharpe ≥ 0.8」作废）

### S2 动量突破（Momentum Breakout）

- **阻塞项**：无，先过预注册证伪线（趋势/动量类在 A 股多次证伪：P11 ETF 轮动 7.6 年跑输基准、P12 RPS 全周期 -60.8%）
- **假设**：趋势具有延续性
- **输入**：N 日高低点（N=20）、ATR（N=14）
- **信号**：收盘价突破 N 日高点做多，跌破 N 日低点做空/平仓；可选均线斜率确认
- **过滤**：成交量放大 ≥ 1.5 倍均量；剔除上市<60 日
- **出场**：ATR 移动止损（2×ATR）、时间止损、反转突破
- **仓位**：波动率倒数加权（risk parity per position）
- **验收（默认基线，2026-10-01 立）**：①趋势段（**事前**定义：基准 60 日收益 ≥ +10% 的连续区间）组合年化超额 ≥ +5pp 且**超额 t 值 > 2**；②震荡段（|60 日收益| ≤ 5%）最大回撤 ≤ 15%；③全期按 §4 基线五要素结算。**任一项不达标判不通过**；分段规则为事前定义，禁止事后分段（v1.0 的「显著优于持有基准」无统计定义，作废）

### S3 统计套利（Statistical Arbitrage）

- **阻塞项**：**Q3（融券/做空权限）**——不可做空时"多空市值中性"无法实现，仅有做多腿替代（降级为另一策略另行预注册）
- **假设**：多资产价差序列平稳（协整）
- **输入**：候选资产对/篮子日频或分钟价差
- **建模**：Engle-Granger 或 Johansen 协整检验（p<0.05），OLS 得对冲比 β；滚动窗口重估（60/120 日）
- **信号**：标准化价差 Z > +2 做空价差，Z < −2 做多价差，|Z|<0.5 平仓
- **过滤**：半衰期 < 30 日、价差波动率下限、流动性下限
- **风控**：协整关系失效检测（滚动 p 值恶化）、价差发散止损（|Z|>4）、多空市值中性
- **验收**：价差序列 ADF 检验通过；多空组合市场中性（Beta 绝对值 < 0.2）；绑定五要素

### S4 配对交易（Pairs Trading）

- **阻塞项**：**Q3（同 S3）**
- **定位**：S3 的特例（两资产），独立模块便于对比
- **输入**：两只高相关标的（行业/产业链相关），相关系数滚动窗口 120 日 > 0.7
- **信号**：价差 Z-score 开平仓；可选距离法（标准化价格距离）
- **差异点**：固定 1:1 或 β 对冲；要求**融券/做空可用性**配置（不可做空时仅做多头替代或放弃）
- **风控**：单对资金上限、价差结构突变（Chow 检验/滚动相关性跌破阈值）强制平仓
- **验收**：与 S3 结果可对比；交易频率与成本敏感性报告；绑定五要素

### S5 多因子模型（Multi-Factor）

- **阻塞项**：无（仓库存量最多：`factors/base.py` FactorBase、`factors/engine.py` FactorEngine、P01/P10 评分与实盘链路、`research_audit/factor_health.py` 因子健康监控）
- **假设**：因子暴露可解释并预测横截面收益
- **因子库（至少）**：
  - 价值：EP、BP、DP
  - 质量：ROE、ROA、毛利率变化
  - 成长：营收/净利同比增速
  - 动量：过去 20/60/120 日收益（剔除最近 1 月）
  - 波动/流动性：波动率倒数、换手率
  - 规模：流通市值对数

- **流程**：去极值（MAD/3σ）→ 中性化（行业+市值）→ 标准化 → 加权（等权/IC_IR 加权/优化）；因子预处理顺序 winsorize(1%,99%) → z-score → 方向控制
- **评估**：分层回测（5/10 组）、IC 均值与 IR、换手率、因子相关性矩阵
- **组合**：Top N 只（N=20，可配），行业中性约束，月度/周度调仓
- **验收**：多头组合年化超额基准 > 0（基准按 §3.4 口径表），IC 均值 > 0.03，分组单调性成立；绑定五要素；财务因子全部过 PIT 硬条款

### S6 网格交易（Grid Trading）

- **阻塞项**：**T+0 品种资格**——A 股股票与多数 ETF 为 T+1，"当日买入当日卖出回转"不可行；须限定跨境/黄金/债券等 T+0 ETF（可复用 P11 遗产 `data/_fetch_etf_xtdata.py` 管道）或明确改用"底仓滚动"口径并写入预注册
- **假设**：区间震荡，波动可收割
- **输入**：基准价 P0、网格间距 g%（等差/等比可配）、每格手数、网格上下界
- **逻辑**：价格每下跌一格买入一份，每上涨一格卖出一份；触界暂停或重置
- **过滤**：仅适用于震荡品种；需计算历史区间命中率
- **风控**：总仓位上限、跌破下界止损（防止"接飞刀"）、资金占用上限、单边行情检测（连续 N 格同向触发告警）
- **验收（默认基线，2026-10-01 立）**：网格区间须**事前**认定——滚动 250 日价格上下界，参数与边界仅用区间形成期之前数据，**禁止事后画框**（v1.0 的事后区间认定属前视，作废）；事前区间内策略费后净收益 > 持有基准；单边下跌情景（跌破下界后继续 −20%）总亏损 ≤ 组合资金 8%；全期按 §4 基线五要素结算

### S7 CTA 趋势跟踪（CTA Trend Following）

- **阻塞项**：**Q1（期货市场）**——数据零存量（D:/astock 全股票）、双账号均为股票 QMT、保证金/换月/主力连续模块为零，**七策略中从零成本最高**；Q1 若答"仅 A 股"则本节整体作废
- **假设**：期货趋势持续性 + 波动率自适应
- **输入**：主力连续合约（需处理换月跳空）、多周期（日线/小时线）
- **系统**：通道突破（Donchian）+ 均线系统（双均线）可选并联；ATR 波动率目标仓位（目标年化波动 10–15%，可配）
- **组合**：多品种分散（商品/金融期货），等风险贡献
- **出场**：跟踪止损、波动率扩张减仓、换月规则（主力合约切换前 N 日移仓）
- **风控**：单品种 ≤10%，总杠杆 ≤2，保证金占用监控，隔夜风险
- **验收（默认基线，2026-10-01 立）**：多品种组合 Calmar ≥ 0.8，绑定 §4 基线区间 2019–2024 全期（期货数据源待 Q1/Q4 确认后锁定——商品大年与常态年份可差一倍）；与股票策略净值相关性 < 0.3（同区间日频）；绑定五要素

## 5. 回测引擎需求（L5）

| 需求项 | 说明 |
|---|---|
| 撮合规则 | 日频：次开盘/收盘价成交（可配）；分钟频：当根 bar 收盘价或限价模拟；涨跌停"能否成交"判定按 §2 分板块涨跌幅执行；T+1 约束 |
| 防未来函数 | 信号仅用 t−1 及之前数据；当日数据 t 日收盘后才可用；财务数据按公告日对齐（§2 PIT 硬条款） |
| **风控/结算频率** | **显式参数化，与实盘配置强制同源**（与 `config/trading_config.yaml` 同源校验）；引擎**禁止允许"回测比实盘少查风控"的配置存在**（仓库实测：风控频率差 -8.3pp、结算频率差 -2.2pp 年化虚高，18.0% 口径真实约 7.5%） |
| **状态隔离** | 带 state 的入口 **run 前强制重置 + 按 run 隔离**（仓库实测 risk_state 残留污染致年化 18.0%→35.7% 虚高） |
| **可复现性** | 每次回测落盘**四元组**：{代码 commit、数据快照 id/日期范围、参数全集、结果哈希}（`backtest/hashing.py`）；同一输入必须复现同一输出 |
| 订单生命周期 | 下单 → 部分成交/拒单 → 回报；支持限价/市价 |
| 资金管理 | 可用资金、冻结、保证金（期货）、手续费逐笔扣减 |
| 事件驱动 | 按时间轴推进，支持股票+期货混合 |
| 输出 | 逐日净值、逐笔成交、持仓快照、绩效报告（HTML/PDF） |
| 复检工具 | 换手率异常检测、收益来源分解（因子/行业/择时） |

**look-ahead 三类检验清单**（§8a Gate 必查）：①复权 look-ahead；②宇宙选择 look-ahead（静态池套全期）；③撮合 look-ahead（盘中取当日 close）。干净验证法 =「**盘中 vs 尾盘对照差异 >30pp 且方向反转**」即判定存在 look-ahead。

**验收（三条全部通过才算引擎交付）——本节先于任何策略验收：引擎未过套件，则一切策略回测结论一律无效、不得引用**：

1. **引擎自身正确性**：`projects/verification/` 全套件通过（引擎 B / 鲁棒性 D / 执行 E / 组合 F），而非仅本表自述；
2. **回测-实盘信号一致**：逐 bar 信号对账（容差 0）。**对账数据面** = 双侧信号快照 + sha256 只读留档（防事后改写，`candidates_asof/` 范式）+ 差异清单；**回测为基准，实盘偏差必须归因**；
3. **可复现**：同四元组重跑，结果哈希一致。

```text
  order(code, side, volume, price_type, price=None) -> OrderID

```

> Ptrade 实现暂缓（见 §6.3 / Q15），接口抽象保留以便后续扩展。

### 6.2 QMT（迅投）实现要点

**生产硬约束（不进验收即返工）**：

- **双 Python 版本**：研究 3.11 / QMT 生产 **3.6.8**；产物禁用 f-string、`dict[str]`、`list[str]`、`str | None`、`:=`、`match/case` 等 3.6 不支持语法
- **产物形态**：GBK 编码单文件 + 首行 `# coding=gbk` + 硬编码 `BUILD_TAG`（`YYYYmmdd-HHMMSS`，`init(C)` 与每日日志/日终报告输出，用于核对「本地构建版本 = 实际运行版本」；缺版本标记的构建视为未完成）
- **部署方式**：必须经客户端策略编辑器**人工粘贴**——直接把文件复制到 `<QMT>\python\` 运行目录无效（客户端加密存储）；QMT 为自绘 UI，**粘贴不可自动化**，人工粘贴是设计内动作
- **下单接口**：`passorder()` 是**全局函数**（非 `C.passorder`）、异步、正常返回 0/None 而非订单号；拿真实订单号必须反查 `get_trade_detail_data(acct, 'STOCK', 'order')`，并容忍 ~100ms 订单号分配延迟（**短轮询等待**；反查失败会静默断链：不登记 pending → 成交回写/撤单/重试全不触发）
- **订单反查过滤**：remark 只作候选优先级信号**不能硬过滤**；判方向用 `m_strOptName`（含中文"买入"/"卖出"）
- **策略时间**：一律用 QMT 行情时间 `C.get_current_time()`，**禁止 `datetime.now()`**（设备 CMOS 时钟可能错乱）；相对计时用 `time.time()` 不受影响
- **收盘触发**：15:00 后 handlebar 不再触发，收盘任务不得依赖 >15:00 的触发；"启动时执行一次"的任务放 `init` 末尾，两者用标志联动防重复
- **数据限制**：`C.get_market_data_ex` 缺财务字段，PE/PB/circ_mv 必须来自预生成 CSV；QMT Python 3.6.8 无 pyarrow，不能读 parquet，数据源一律 CSV
- **自包含**：config 读取不得依赖 `__file__`，读不到必须有完整 `_DEFAULT_CONFIG` fallback
- **模拟端限制**：`get_trade_detail_data` 只保留当日 deal/order，隔日查不到 → **每日导出 CSV 到 `D:/QMT_POOL/` 是刚需**
- 生产版不得混入 mock 或测试代码

**功能要点**：

- 使用 `xtquant`（`xtdata` 取数、`xt_trader` 交易）；支持 miniQMT 独立模式
- 全推/订阅行情、篮子交易、算法单（TWAP/VWAP 拆单）
- 本地运行：需常驻进程与断线重连机制
- 卖出风控评估前必须同步账户全量持仓纳管（孤儿持仓 = 止损/止盈永不触发）

### 6.3 Ptrade（恒生）——暂缓

后撤出范围（全仓库零实现/零数据/零账号实证，云端运行时/新 API 族/新频率限制对单人项目 L6 工作量翻倍且 QMT 经验不可迁移）。仅保留 §6.1 抽象；是否重建挂 **Q15**。

### 6.4 通用要求

- **对账（reconcile）一等公民**：以**账户 position 为唯一真相**的周期对账 + 账实不符处理协议（发现不符 → 只读核查 → 补记/暂缓 → 交叉校验；状态歧义期禁止重下单）；对账后补仓保护（防误判触发尾盘重复建仓）
- **持票账本安全**：holdings/state 文件必须内嵌 `account_id` 戳；加载时账号戳缺失或与当前策略 `ACCOUNT_ID` 不匹配 → 自动备份旧档 + 空仓起步（fail-safe），**严禁拿错账号的账本交易**
- **订单状态机**：买入 pending 超时 **300 秒 × 最多重试 3 次**（撤单 → 重新下单 → 更新 pending time/retry → 继续跟踪），约 15 分钟仍不成交才彻底放弃；**禁止"30 秒超时即撤单删 pending、永不补单"**；**回滚/恢复持仓（rollback）前必须先撤 QMT 活单**（防次日意外成交，P10 2026-08-14 修复范式）
- **跌停/停牌暂缓队列**：卖出遇跌停/停牌进暂缓队列，风控意图不放弃、次日续查
- **多账号约束**：账号 ID 硬编码、策略-账号严格对应、**禁止串用**（引用错号 = 废单）
- **资金隔离**：多策略共存于共享账户时，每策略锁定独立 `capital_base` 虚拟子账户，只能动自己 ledger 的票与额度，绝不抢占他人资金、绝不纳管/卖出他人持仓；**`Σ capital_base ≤ 账户实际总资产`（硬约束）**；唯一事实源（`config/capital_allocation.yaml` 范式）+ 部署前校验脚本**退出码 0 才许部署**
- **双环境**：模拟盘 → 实盘，最少模拟运行 N 个交易日（N 待定，Q6）；上线前跑 1 个交易日核对关键日志行（BUILD_TAG、对账行）
- 幂等与断点续跑：重启后能恢复持仓与信号状态
- 限频与限流：委托频率上限、失败重试上限（≤3 次）、重复下单拦截
- 时间同步：交易时段判断、集合竞价处理、节假日历
- 审计：每笔委托/成交落库，保留原始回报
