### 三处断点的根因与修复

**① Design 腿（`factor_design_weekend.ps1`，10,004 B，BOM 恰好 1 个，`PARSE_OK`）**

根因三层叠加：

1. `deveco.cmd` 走 `cmd.exe` 时引号被吞 → `'...deveco.cmd" run "读取任务书' 不是内部或外部命令`（`factor_design_de_err.log` 129B 实证）；
2. `Start-Process -PassThru` 不配 `-Wait` 时 `.ExitCode` **恒为 `$null`**，而 `$null -ne 0` 在 PowerShell 里是 `$true` → 任何结果都被判失败；
3. 成功判据 `$timedOut = -not $proc.HasExited` 把「跑完了但 ExitCode 读不出」也算超时 → **成功的 run 被丢弃**。

修复：改走 **native `deveco.exe`**（`...\@deveco\deveco-code\bin\deveco.exe`，182MB，路径无空格，绕过 `.cmd` shim）+
`--auto` + **.NET `ProcessStartInfo`** 直连（不依赖 `Start-Process` 的 ExitCode 语义）+
`$stillRunning` / `$timedOut = $stillRunning -and (-not $done)` 双变量 + `ReadToEndAsync` 防死锁。

> 实测：`deveco.exe --version` = **0.2.4**，`--auto` 与 `--dangerously-skip-permissions` **两种参数都接受**（rc=0、12.6s、JSON 正常、stderr 空）
> ⇒ 「0.2.4 不认这个 flag」这条旧推测**已推翻**，真正的坑只有 `cmd.exe` 引号与 ExitCode 语义。

**② Screen 腿（`run_latest_batch.py`）**

`print(line.rstrip()[:200])` 打到 `✅通过` 时，管道下 `sys.stdout` 默认 GBK → `UnicodeEncodeError: '\u2705'` → rc=1。
自 2026-09-19 起**连续 7 周** rc=1，ps1 据此推「S1/S2 周末批失败」假告警。
修复：`_safe_stdout()` → `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（py<3.7 用 `AttributeError` 兜底）。
> 实测：完整 40 行漏斗表（含 `✅通过`）输出正常，`EXIT=0`。

**③ Ablation 腿（`run_exclude_ablation.py`，29,237 B）**

旧报告每周重算的 +2.65pp 是**口径伪差**，不是 alpha：

- **缺陷 1**：`years = len(rets)/4.0` 把 6.00 年日历压成 4.75 年（把「缺期」当成整季）；
- **缺陷 1b**：各配置用**自己的期列表**（缺期时把两个季度链接成一段），基线 20 期 vs 单条件 19 期不可比；
- **缺陷 2**：**动量口径与生产不一致**——原脚本 `momentum_12_1` 用 `pos-1 / pos-252`（≈12-0），
  而生产 `atr_lowvol.py` L208 是 `close[-21] / close[-252]`（12-1）。这一条单独就能让同一份数据
  从 13.51% 跳到 21.30%、把增益从 +0.40pp 改成 +0.20pp。

修复后：共同网格（19 期 / 5.49 年）+ 真实日历年化 + 生产 12-1 动量 + 逐位复刻旧口径（表2 可复现旧数字）。
报告已重生成为 `exclude_ablation_report.md`（2026-11-01 03:07:32），开头带 4 行**撤回横幅**。

## 二、它产出的东西到底有没有价值（独立复核，不采信生成报告）

### 2.1 10 个 S2「通过」因子的成色

r2 批次 40 → 10 通过（全部 `direction_hint = -1` ⇒ **全是负向/排雷用途**，不能做多）。逐条体检后：

| 类别 | 因子 | 结论 |
|---|---|---|
| 真正有尾部区分度 | `PX_MAX20` / `PX_AMT_RATIO_20D` / `PX_VOL_STD20` / `PX_LISTED_NEW` | 4 个，**均已实测无可落地增益**（见 2.2） |
| 分位尾部不显著 | 6 个（`HK_*` / `RES_*` / `FIN_*` / `PX_LIMITUP_CNT20` 等） | `exclude_diag_report.md` 判「✗尾部不显著」⇒ 无排雷价值 |
| **字节级重复** | `LHB_AMOUNT_RATE_20D` 与 `LHB_BUY_RATIO_20D` | 分位数字**逐位相同** ⇒ 同一底层量换了名字，去一留一或全弃 |

> 另：`PX_LISTED_NEW` 在表5 的 drop 统计里是 **0.00/0.00/0.00** —— 它在 ATR 合格域内**一只都剔不掉**
> （域内全是老票），所谓「+1.00pp」纯属期数口径错觉。

### 2.2 三种口径下的增益（全部指向「不落地」）

| 口径 | 基线 | AMT@20% | 增益 | 来源 |
|---|---|---|---|---|
| **真实约束回测**（生产载体，2026-09-17） | 16.91% | 17.48%（**base/excl 逐位一致**） | **+0.00pp** | `amt_exclude_engine_结题.md` |
| **共同网格 + 真实日历**（legacy ≈12-0） | 13.51% | 13.91% | **+0.40pp** | `exclude_robustness_audit.md` 表1 |
| **共同网格 + 真实日历**（生产 12-1） | 21.30% | 21.51% | **+0.20pp** | `exclude_ablation_report.md` 表1 |

真实约束回测的关键证据：`cagr=0.1691 / mdd=-0.2480 / sharpe=0.898 / trades=666 / amt_excl_by_rebalance=[]`
—— **`amt_excl_by_rebalance` 是空数组**，即 31 个季度里**一次都没剔掉过任何票**。

**机制**：`amt_ratio ≈ 换手率`，而 ATR 载体已经卡 `turnover 1~8%` 且偏好均值 ~2.33%，
top-20% amt_ratio 均值 ~6% ⇒ 二者**天然正交**，域内再排除等于空操作。
（`diag_amt_overlap_results.json`：`prod_allcap` 全 31 季度重叠 **0**；`ablation_smallcap` 合计 **2**。）

**增益的物理来源**：表4 换名台账 —— AMT@20% 只有 **5/19 期**换过名、累计换出 **5 只**；
组合4 是 8/19 期、9 只。单次幅度从 −3.545pp 到 +2.220pp 随机摆动 ⇒ **单票运气，不是可复用的 alpha**。
换名方向一反转即转负（组合4 在 std 口径下就是 **−1.32pp**）。

**反例留档**：`PX_MAX20` 分位尾部判「✅」，但简化 ablation 实测 **−1.09pp**，
共同网格下却是 +0.42pp（legacy）/ +0.13pp（std）—— **符号随口径翻转**，不能当稳定因子用。

### 2.3 前视审计（干净）

`atr_pct` 取 `s.iloc[pos-15:pos]`、`px_*` 全部取 `s.iloc[max(0,pos-n):pos]` ⇒ **调仓当日 K 线被排除**，
无 look-ahead。`px_listed_new` 用 `list_date`（上市日）判 365 天，属确定性字段，无前视。

## 三、利用方案（判定）

### 3.1 因子层：归档，不进实盘参数

**判定：4 个 PX 排雷因子（`PX_MAX20` / `PX_AMT_RATIO_20D` / `PX_VOL_STD20` / `PX_LISTED_NEW`）
对 ATR 载体无可落地增益，不进入实盘参数。ATR 本体不受影响，继续按原参数运行**
（`atr_lowvol.py` 的 `max_exclude_pct` 保持 **0**，`EXCLUDE_FACTORS` 仅作研究留档）。

理由按优先级：

1. 生产载体真实约束回测 **+0.00pp**、`amt_excl_by_rebalance=[]`（一次没剔过）；
2. 口径修正后只剩 +0.40pp / +0.20pp，**未达 >+0.5pp 落地阈值**（且 < 单边成本 0.15%×双边 的噪声级）；
3. 增益来自极少数期换 1 只票，样本外（2024-26）不支持，符号随口径翻转；
4. 单源（仅 astock），备用源 gpsj 当前不可用，无交叉验证。

**其余因子**：`HK_*` / `RES_*` / `FIN_*` / `PX_LIMITUP_CNT20` 尾部不显著 ⇒ 无排雷价值；
`LHB_AMOUNT_RATE_20D` 与 `LHB_BUY_RATIO_20D` 字节级重复 ⇒ 去一留一（或全弃）。

### 3.2 管线层：修好并继续跑（这是真正「利用起来」的部分）

链路本身的价值不在这一批因子，而在**它是唯一能持续产出新因子假设的自动化入口**。
因此本轮的工作重心是把三处断点修好，让 R3 真的能被设计出来：

1. **Design 腿已修** → 下次真实触发（**2026-11-06 20:30**）应能真正拉起 DE、产出 `de_factor_mining_r3_*.md`；
2. **Screen 腿已修** → 拿到 R3 yaml 后能正常跑 S1+S2 并 rc=0；
3. **Ablation 腿已修** → 不再复读 +2.65pp，改为输出「口径声明 + 撤回横幅 + 共同网格」的可信报告。

**验证方式**：分支矩阵回归 `_test_factor_design_branches.py`（26 断言 / 0 失败，生产目录 1222 文件快照前后一致）。
