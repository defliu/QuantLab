### A.2 撤单安全合同（本轮核心，两阶段状态机）

```text
发出 cancel()
→ 进入 cancel_requested 确认态
→ 后续轮询原委托
→ 确认旧单进入终态
→ 才允许重下 / 回滚 / 移除 pending
```

委托状态合同：

| 状态 | 含义 | 处理 |
|---|---|---|
| 56 | 全成 | 终态，不可重下、不可回滚 |
| 53 | 已撤 | 终态，可按最终成交量处理剩余量 |
| 54 | 部撤 | 终态，可按最终成交量处理剩余量 |
| 57 | 废单 | 终态，可按最终成交量处理剩余量 |
| 55 | 部成 | **活跃态**，不可视为已撤 |
| 2 / 48 / 49 / 50 | 活跃态 | 继续轮询 |
| 状态缺失 | 未知 | 保守按活跃态处理 |

红线（违反=返工）：

- `cancel()` 返回成功只代表撤单请求**送达**，不代表旧单已撤成；
- 发撤单后**不得立即重下**；
- 旧单终态前**不得回滚账本**；
- **不得立即清空** `_pending_orders`；
- 查不到原委托时**必须隔离至收盘对账**；
- 每次重下必须建立**新的精确 attempt 标识**；
- 历史 attempt 成交量**不能串入**新 attempt；
- deal 数量领先委托快照时**只能保守上调**，不能因快照回退而下调。

### A.3 撤单 API 修正（T7 阻塞①已关闭）

旧写法是 **P16 于 2026-09-01~09-03 已实证推翻的错法**：

### A.4 ID 命名空间（反向红线）

```python
_ORDER_ID_NS = (
```

### A.5 attempt 成交量模型

```text
attempt_amount   本次委托量
attempt_traded   本次委托累计成交（m_nVolumeTraded 是累计量，不是 bar 增量）
filled_before    历史 attempt 累计成交
filled_amount    filled_before + attempt_traded
amount           attempt_amount - attempt_traded
```

- 委托快照可能滞后，deal 是柜台成交事实；
- deal 只能**上调** `attempt_traded`，后续快照回退时保留历史最大值；
- deal 超过 `attempt_amount` 时按委托量封顶；
- 不得把上一 attempt 的 deal 串入当前 attempt。

部分成交账本口径：

- 买入 1000 股成交 400 后撤 → 保留 400 股真实持仓，只返还 600 股对应估算现金；
- 卖出 1000 股成交 400 后撤 → 恢复 600 股未成交持仓，只扣回已成交 400 股对应估算现金；
- 收盘 deal 只能校准价格差，**不能再次按整笔成交额冲销现金**。
