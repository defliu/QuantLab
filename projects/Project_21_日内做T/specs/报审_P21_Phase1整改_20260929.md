## 二、整改① 性能诊断与修复

### 诊断结论
旧扫描 18h 仅推进 74/1566 交易日、0 事件，三重根因：**(a) 每事件重复计算**（退出价/中位量每事件一次 241 行 strftime 与遍历，占全扫描约 50% 耗时）**(b) 历史波动率每事件重算**（20 日均量滚动）**(c) 进程内死锁/静默错误**（DateParseError 走 FAIL-QUIET → 0 事件且不报错）。

### 修复清单
| 文件 | 修复 |
|---|---|
| `strategy/signals/base.py` | `ScanContext.__post_init__` 预计算 `_exit_price`（>=14:50 首根 bar close）与 `_median_vol`；`get_bar_time/get_bar_price` 改 `.iat`；`_estimate_shares` 用预计算中位量；去掉 `max(est,100)` 兑底（真正兑现零股跳过）；`ScanContext` 增 `df_auction_o_hist`/`df_5min_hist` |
| `research/scanner.py` | `_preload_batch` 预计算 `hv_dates`/`hv_vals`（`shift(1).rolling(20)` 日均量）+ 新增 `_lookup_hist_vol` O(log n) 查询；`F6_HIST_BARS=60` 跨日 5min lookback；`BatchStats` kwargs 修复；`_filter_auction_by_date` datetime 分支（修 DateParseError）；错误可见性 `_record_ctx_error/_record_sig_error/_print_error_summary` + 事件为 0 时 FAIL-LOUD；每批增量落盘 partial；`main(argv)` 支持 `--start/--end/--out`；ETA 修正为 `(len(pool)-e)*len(calendar)` |
| `strategy/signals/f1_auction.py` | 真实列名 + 全期竞价历史（原 0 信号） |
| `f3_vwap_dev.py` / `f5_gap_fill.py` | `params` 提前绑定（原引用错误） |
| `f6_pulse_regression.py` | 跨日 lookback 改用 `df_5min_hist`（原恒 0 信号） |
| `research/run_scan_waves.ps1` | 并行驱动：MaxConcurrent=2、MinFreeGB=15、每槽 7GB 余量、缺产物自动重试 ≤3、分年日志 |

**实测**：42.9 → **13.9 ms/stock-day**（exit 缓存贡献最大，hv 缓存次之）。
