## 二、共同基础设施

- **数据源**：面板特征 `data/feature_panel_v3.parquet`（V1.3/融合的 v3_enh 侧）+ `data_live/g2_latest_features.parquet`（G2 侧）；F2 主力资金 = 本地 Tushare moneyflow parquet（`D:/astock/moneyflow/`，每日 19:30 刷至 T-1）；行情实时 = 腾讯 API 优先，mcp_tdx/悟道直连降级（数据源降级链详见 `.qoder/repowiki/zh/content/数据源与基础设施/数据源优先级与降级链.md`）。
- **成本锚**：工作日 09:00 `Quant_P16_CfgPremarket_0900` 跑 `gen_positions_cfg_{g2,v13,ens}.py` 向三个执行端下发含费成本价（除权因子稳定化：主库 adj_factor 权威，09-15 修复）。
- **心跳巡检**：`Quant_P16_Heartbeat_Alarm` 每 30 分钟（盘中窗口）查三桥 `heart_<D>.json`，>600s 飞书告警（含午休感知）。
- **夜间检修**：01:00 `nightly_check.py`（FAIL 自动修 + 报告）；01:30 DE 夜审 `de_guard_runner.ps1 -Mode nightly`。
- **DE 五模式**：`health`（周五体检）/ `reconcile`（16:40 对账复核）/ `nightly`（01:30）/ `data`（19:45 断更诊断）/ `intraday`（盘中异动，每 30 分钟）。
- **复跑防覆写（09-28/29 修复）**：`compare_g2_daily.py`（20:10）、`compare_v13_daily.py`（20:12）、`test_g2_rerun.py`（周六 09:10）均备份→复跑→finally 兜底恢复原件，复跑产物不再落盘污染历史/次日活输入。
- **费率口径**：佣金万 2（最低 5 元）双边 / 印花税万 5 卖出 / 过户费万 0.1 仅沪市。

## 三、V1.3 详解（miniQMT 直连，账号 67014907）

**信号链**：09:15 预生成候选（幂等，已有则跳过）→ 09:25 集合竞价预判（F3 催化缓存 + crosscheck 交叉验证）→ 09:45 开盘实时复核：按职责分组采集 F2/F3/F5 写 `tdx_review.json` → `review_full.py` 生成 `<D>_selection_full.csv` → `market_tier.py` 定 T → `rebalance_daily.py --date <D> --top <T> --live`。

**执行链**：`rebalance_daily.py` 直连 miniQMT（xtquant）下单，先卖后买；`--top` 语义 = T 档（0 清仓 / 1 半仓 1 只 / ≥2 内部归一到 TOP_N=5）；plan json `data/rebalance_<D>.json` 含 `executed_live` 幂等标记 + 候选溯源 7 字段。

**风控**：三层——① rebalance 内置红线/到期/资金池校验 + 纸面降级闸；② QMT 内置风控策略（`p16_v13_risk` 桥，09:00 成本锚驱动）盘中秒级 STOP/TP/TRAIL；③ 10:05 guard 兜底（漏触发自动补跑全链，T=0 自动清仓）。

**注意**：09:45 任务 prompt 修改说明已生成（`specs/TRAE任务修改说明_0945开盘实时复核_20260929.md`，禁 agent 写 plan json），待 TRAE 执行。

**执行链**：09:50 TRAE 任务先 dry-run 核对（候选新鲜度/桥存活/红线/账本边界内置校验）→ `rebalance_g2.py --live` 写 `g2_bridge/cmd/orders_<D>.json` → **QMT 内置策略**（`strategy/strategy_p16_g2_bridge_src.py` 构建产物，GBK 单文件，BUILD_TAG 制）消费 orders、反查成交、回写 state。seq 幂等 + pending 状态机（300s/3 次重试）。

**风控**：桥内置 `_check_risk_signals`（账户持仓全量纳管防孤儿 + `get_full_tick` 秒级判断 + 触发即 passorder 卖出 + `peak.json` 跨日持久化 + `risk_sold` 防重复 + 心跳快照恢复）。

**对账**：15:45 `reconcile_g2.py`（fills/orders 一致性、pending 清零、positions_cfg 差额、孤儿仓预警）+ 16:40 DE 复核。

## 六、隔离红线（硬约束，违反=事故）

1. **账号隔离**：V1.3 只动 `67014907`；G2/ENS 只动 `70180771` 且各自只动自己账本的票，**绝不纳管/卖出他人持仓**。
2. **配置隔离**：`g2_config.py` 绝不 import `qmt_config.py`；`g2_ens_config.py` 绝不 import `g2_config.py`——三套配置物理隔离。
3. **账本 account_id 戳**：所有资金池/成交记录必须带戳；加载时戳缺失或不匹配 → 自动备份旧档 + 空仓起步（fail-safe，T-20260823-004）。
4. **文件桥边界**：G2 只写 `g2_bridge/`，ENS 只写 `p16_ensemble_bridge/`；互跳对方已持仓（重叠规避）。
5. **资金分配**：`config/capital_allocation.yaml` 是唯一事实源（g2_bridge 10 万 + p16_ensemble_bridge 10 万 ≤ 账户总资产 1000 万），改后必跑 `scripts/check_capital_allocation.py`。
