## 三、关键细节与坑（务必记住）

### 3.1 KV 通道

- **参数形态**：`save_py_key(key, value)` 两参数；返回 `(rc, msg)`，rc=0 表示调用成功。
- **返回值是三元组**：`get_py_key(key)` → `(value, rc, msg)`，**首元素才是值**。按裸字符串比较会误判。
- **缺失键**：返回 `('', 0, '')` —— **rc 也是 0**，无法用 rc 区分"存在"与"不存在"，只能靠值是否为空串判断。
- **长度上限**：1MB / 6MB 写入均返回 `(0,'')` 看似成功，**读回 `len=0` 空串**（静默丢数据）。
- **结论**：`rc=0` 完全不能作为"写成功"判据，必须读回校验；只适合存键值、水位、账本摘要等小状态。

### 3.2 sqlite 通道

- `sqlite3` 走自身 C 层 IO，**绕过 `Forbidden fileIO`**。
- 可用于 `D:/QMT_POOL/*.db`，需保证该目录可写（`-journal`/`-wal` 侧车文件同目录）。
- **⚠️ 调用位置限制（重要，2026-10-26 补记）**：探针里 sqlite 的**全部四项**（`:memory:` / file db / PERSIST write / PERSIST read back）都跑在 `_isolate()` 守护线程 + 6 秒超时内（探针源码 `broker/qmt_sandbox_probe.py` L586-660，`_persist_write`→`_isolate`、`_persist_read_back`→`_isolate`）。隔离只证明**主线程不会因此挂死**，**不证明在主线程同步调用也安全**——主线程同步调用 sqlite 至今**未测**。在策略里落地前必须补一轮"主线程直调"实测，或一律沿用 `_isolate()` 包裹。

### 3.3 `tempfile` 的双重失败模式（重要教训）

| 轮次 | 现象 | 危害 |
|---|---|---|
| 客户端 A 17:19 | 跑到 `io chmod` 后**整个进程消失**（无 WER 记录 → 非访问违例，是 abort/自终止） | 崩溃 |
| 客户端 B 18:16 | **静默中止 `init()`**：进程存活（PID 23504 全程在跑、CPU 正常增长），但此后无任何输出、无 traceback、后续段全部不执行 | **更阴险：进程活着、策略看似正常、实际已停摆** |

→ **任何一次性跑完的探针，必须把高危调用扔进 daemon 线程 + 超时（`_isolate()`），否则它会吞掉整轮结果。**

### 3.4 print 输出是批量 flush 的

客户端会按批（约 50-100ms 或按行数）将 print 汇总成一条日志写入。崩溃/中止时缓冲区内的结果**全部丢失**。

→ **每行必须 `sys.stdout.flush()`**；高风险项执行前必须先打印 `>> about to run: xxx`，崩溃时最后一行即为凶手。

### 3.6 启动日志里的权限位

客户端 B 的 `doRun` 行显示 **`m_bAllowOpenFile:1`**（文件位仍开）、Python 白名单/黑名单均 size=0。但实际 `open` 仍被 C 层拒绝 —— **权限位为 1 不等于文件可读写**。

**⚠️ 该证据直接推翻了「服务端下发权限位」的归因（2026-10-26 补记，重要）**：

- 原始日志：`D:\国金QMT交易端模拟\userdata\log\XtClient_20261026.log` 第 6149/6151/9218/9220 行，`doRun: ... m_bTrade:1, m_levelStatus:1, m_bAllowOpenFile:1, m_runMode:1`（当天 09:33 与 18:01 两次加载策略时均如此，全天 11 处命中，**无一处为 0**）。
- 同日同一客户端上，探针的 `open`/`os.open`/pathlib/makedirs 全部 `Forbidden fileIO`。
- **结论：文件 IO 拦截不来自券商服务端下发的权限位，而是客户端定制 `python36.dll` 的本地 C 层拦截**（与 `m_nPythonConnectNet` 网络位同样：网络位未收紧、网络实测全通）。这解释了为什么 **10-23 全量 deadline 已过、本机两台客户端策略仍照常运行、零 `Foribdden`**——因为服务端根本没有对模拟端下发收紧。
- **对诊断的意义**：不要再拿「等服务端权限位恢复」作为恢复路径；沙箱状态取决于**本地客户端进程**（重装/升级/重启会改变行为，两台客户端强度不同即为此故），恢复手段只有重启客户端进程。

### 3.7 `C` 上下文 API 清单（探针模式实测，供写策略时对照）

探针跑在「模型交易/回测」模式，`C` 的 API 面与实盘模式**不同**，写策略前必须先确认目标 API 在当前模式下是否存在：

## 五、对架构红线的影响（通道可用，按约束落地）

原 `specs/QMT沙箱自闭环改造方案_20261015.md` 的结论「文件桥无解 → 只能靠 `save_py_key`/`get_py_key`」**已被本次实测扩展为能力事实**：

| 原方案 | 本次实测修订 |
|---|---|
| 文件桥写 `state/*.json` | ❌ 确认死（`open`/`os.open`/pathlib 全拒；客户端 A 读也全拒 → 两端都出局） |
| 状态持久化唯一靠 KV | ✅ KV 可用但仅限小数据（1MB 起静默丢）；**sqlite 文件库是更好的选择，已验跨重启** |
| 未评估网络 | ✅ **HTTP(S) 全开**，可拉数据、推飞书 |
| 未评估子进程 | ✅ **subprocess 全开**，可调外部脚本 |
| L1 会话内存 / L2 账户即账本 / L3 期初快照 | 仍有效；**L3 期初账本快照可从"源码硬编码"升级为"sqlite 持久化 + 硬编码兜底"** |

### 参考架构（通道已实证可用；按下方约束落地）

```
数据输入   → HTTP(S) 拉预生成 CSV/JSON（零文件依赖；断网降级到内置行情 API）
状态持久   → sqlite（D:/QMT_POOL/*.db），已验证跨进程重启
            └ 兜底：KV save_py_key/get_py_key（仅小数据）
交易信号   → QMT 内置行情 API 自算（get_market_data_ex / get_full_tick）
告警推送   → HTTP POST 飞书 webhook
应急通道   → subprocess 调外部 Python 脚本
```

> **审计意见（2026-10-27，收录但不据此降级；诚哥拍板「先不降级」）**：上框为当前采用方向。**行情 API 两项已全部实证（2026-10-27，收口）**：`get_market_data_ex` 以 `stock_code=` 关键字复测通过（11:07 轮，`rows=5` 真实价，与 `get_full_tick` 一致）；`get_full_tick` 实调返回真实 tick（000001.SZ lastPrice=11.49 volume=847773 open=11.27；600000.SH lastPrice=9.78 volume=336056 open=9.56；volume 较 10:28 轮实时增长，盘中数据确认）。剩余未测项——HTTP POST/webhook、subprocess 外部进程写文件、sqlite 主线程/并发/崩溃恢复。这些是**待补测清单**，不改变「通道可用」的结论。

### ⚠️ 落地约束（2026-10-27 拍板「不降级」后的执行口径）

上面的"优先级 1 = HTTP(S) 最强通道"是**能力事实**，按 2026-10-27 拍板可直接用于落地，但须叠加以下约束：

1. **HTTP(S) 作数据/告警通道，断网必须能降级。** 依据：AGENTS.md 记录华鑫 2026-10-30 关闭 miniQMT、迅投社区 10-23 后部分券商网络全断，并明确写「网络路线仍不得作为长期方案」。→ 拉数据/推飞书可用 HTTP，但**关键交易决策不得依赖"能连外网"这一前提**；必须设计成网络断掉时策略仍能按内置行情 API 自闭环运行（降级而非停摆）。
2. **`subprocess` 标注不确定性。** 已验证「能启动外部进程并拿到 stdout」，**未验证外部进程写文件是否受同一沙箱约束**（见第七节遗留）。生产设计里若用到，需先补测或加失败兜底。
3. **sqlite 主线程同步调用未测**（见 3.2 节），落地要么补测、要么强制沿用 `_isolate()` 包裹。
4. **文件桥彻底出局是唯一无保留的结论**——`open`/`os.open`/pathlib/makedirs 全拒、`tempfile` 挂死，可直接据此废弃现有 `_read_json`/`_atomic_write_json`。
5. **落地优先级建议**：行情 API 补测**已收口（2026-10-27 11:07 v4.6 复测通过，`rows=5` 真实价）**——「内置策略自算信号」前提成立；下一步补 HTTP POST/飞书 webhook；sqlite 并发与崩溃恢复最后。缺口不影响先用起来。

### 10.4 输出契约与容错

- 每条记录一行：`[P47] {json}`，`ensure_ascii=True, sort_keys=True` → **纯 ASCII**，GBK/UTF-8 粘贴不变形。
- 三类记录：`meta`（begin/done，含 `tag` / `py` / `ctx` / `ts`）| `seg`（段边界 begin/end/abort）| `call`（单次 API 结果）。
- `call.ok=True` → `call.v` 为深转后的原值（dict/list/DataFrame/Series 有深度与长度上限，超限截断并标注）；`ok=False` → `call.err` 为 `"Type: message"` 或 `"HUNG >Ns"`。
- **每个 API 调用跑在 daemon 线程 + 硬超时**（v4.2 教训：单个 API 挂死会吞掉整轮结果）；每行 `print` 后立即 `sys.stdout.flush()`（v4.1 教训：print 是批量 flush，崩溃即丢缓冲）。
- 全程只读：无 `passorder` / 无撤单 / 无账户查询 / 无文件 IO / 无网络 / 无 subprocess。
