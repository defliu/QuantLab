## 二、三个决定性事实（代码级核实，非推测）

### 事实 1：回测验证的口径是精确可描述的

`scan_rotate_cost_real.py`（R8 / V1.4 网格全用它）：

```
LightGBM combo top10 定池（T-1 面板）
  → 池内用 scorecard_real.compute_real_scorecard 评分卡重排 + 红线 58（THRESHOLD）
  → 次日开盘价入场（open_next = open.shift(-1)，open→open 收益）
  → 一字涨停/停牌过滤（基于 T+1 快照）
```

评分卡各因子数据源 asof **全部是 T-1**：

| 因子 | 回测口径（scorecard_real.py） |
|---|---|
| F1（技术形态） | 面板代理分（T-1） |
| F2（主力资金） | **真实** T-1 主力净额 + 量比 |
| F3（新闻催化） | **面板代理分**（回测中不存在新闻） |
| F4（动量） | 面板代理分（T-1） |
| F5（行业） | **真实 T-1 行业涨幅**（不是 T 日盘中） |
| F6（估值） | 真实 T-1 PE + 换手 |

### 事实 2：实盘 09:45 层的偏差点可精确定位为三处 + 一个二阶时点差

| 因子 | 回测口径 | 实盘 09:45（review_full.py） | 对齐？ |
|---|---|---|---|
| F1/F4 | 面板代理（T-1） | 同 | ✓ |
| F2 | T-1 真实 | T-1 tushare 优先（主路径对齐），**当日盘中兜底**（不对齐） | 主路径✓ |
| F3 | 面板代理分（0 权重新闻） | **当日新闻 AI 催化分，权重 20%** | ✗ |
| F5 | **T-1 行业涨幅** | **T 日盘中行业涨幅** | ✗ |
| F6 | T-1 PE/换手 | 当日实时 PE（变化慢，近似对齐） | ≈✓ |
| 入场时点 | 次日开盘价 | 09:45–10:00（被采集复核耗时拖后 15–30 分钟） | ✗（二阶） |

评分权重（review_full.py SC_WEIGHTS）：F1×25% + F2×20% + F3×20% + F4×15% + F5×10% + F6×10%（×10 百分制）。

### 事实 3：重排不是摆设——每日置换最终名单约 43%

复现脚本 `research/v13_rerank_overlap_study.py`（正确配对：`<T-1>_model_top10.csv` vs `<T>_selection_full.csv`）截至 2026-09-30 输出：

```
valid pairs            : 30（8 天非子集=历史覆写污染，重合度仅供参考）
mean overlap (top5)   : 2.83 / 5
mean churn             : 43.3%（rerank 每日置换最终名单比例）
redline-empty days     : 6 / 30（n58==0，当日红线空仓）
n58 distribution       : min=0 max=9 mean=3.7
最近分布：09-23/24/28/29 连续 n58=0；09-30 n58=7（非空仓）
```

**解读**：V1.3 实盘实际买的是一个「回测从未验证过的变体」——池子来自已验证的 combo，但最终买谁主要由回测中**不存在**的 F3 新闻分（权重 20%）+ T 日盘中 F5 决定。这比执行时点偏差严重一个量级。

## 三、三方案评估

### 方案 A：保留盘中实时重排（现状）——不推荐

- 唯一辩护是「盘中资金/板块信息可能有增量」，但 P21 已用六年 3700 万条日内事件证伪同族信号（毛 alpha≈0，F1 每 stock-day 成对发出多空信号组内毛收益精确抵消）；且 F2 主源本来就是 T-1，「实时」名不副实。
- F3 新闻分**永远无法回测验证**（无历史新闻档案）——20% 权重押注在不可证伪成分上。
- 维持它就要维持整条 agent 依赖链（多源降级、会话中断、模型降级、inline 写 json）——09-15 零产出、09-29 覆写全是这条链的产物。
- G2 实盘 vs 纸面背离审计未找到任何「缺实时信息」的证据。

### 方案 B：删盘中重排，对齐回测口径——**推荐**

具体形态（核心函数全部现成，改动很轻）：

1. **16:30 盘后管道加一步**：`deploy_predict` 出 combo top10 后，直接跑现成的 `scorecard_real.compute_real_scorecard`（纯本地 T-1 数据，无任何盘中 API）→ **最终名单当晚定死**（含红线 58 过滤）。
2. **次日 09:31–09:35 纯脚本执行**：`market_tier`（只需沪深300 一个行情源）→ `rebalance_daily` 限价买入（锚开盘价），保留低开校验 + 一字板过滤。
3. **09:45 TRAE 任务退役**：多源采集链删除，agent 层只留告警/推送；10:05 guard 保留兜底（guard_backfill 已证明全链可脚本化，对齐后连取数都不需要）。
4. **F3 新闻催化降级为推送提示**（人工可见、不进分数）——对齐的必然代价（回测的 F3 本来就是代理分）。

收益：回归唯一被验证的口径；执行链从「agent+6 数据源+降级链」塌缩为一条确定性脚本，故障面砍掉大半；审计与回测逐日可比（asof 留档基建刚好支撑）。

代价：红线空仓频率会变（real scorecard 分布 ≠ review_full 分布）；失去「当日盘中弱市缓冲」的直觉安慰（T 档门控仍在）。

### 方案 C：当天尾盘算排名买入——现在不做，挂研究课题

- 先排除含义①「T-1 排名拖到 T 日 14:50 才买」：信号更陈旧还白担盘中波动，直接否。
- 有讨论价值的含义②「T 日 14:45 用 proxy 收盘数据算排名 → 14:55 买入」：
  - 卖点：信号新鲜度 +18 小时；
  - 代价：①proxy 面板（未收盘价/未完成量额）是又一个未验证口径，误差集中在量比/资金占比这类「全天才定」的特征；②**承担隔夜跳空，且失去低开校验闸**（对 N=5 小盘轮动，隔夜 gap 是显著风险源）；③T+1 持有期错位；
  - **可回测**：`D:/astock/min_1min` 分钟线齐全，可构造 14:45 proxy 特征 + 14:50 入场价重跑 R8——若真想评估先跑这个回测，别用实盘试；
  - P21/P18 教训都指向「日内/形态信息没有直觉想象的值钱」，优先级排在方案 B 之后。

## 四、开盘买入时点：09:31–09:35

- 回测入场 = 开盘价 → 对齐就是尽早贴近开盘。现行 09:45 是被采集复核耗时绑架的结果，不是最优选择。
- 不追 09:30:00 整：跳过第一分钟极端波动/最宽价差；且低开校验、T 档、一字板判断都需要开盘后数据。
- 不做集合竞价单（09:25 前）：T 档算不了、低开校验无成交参照。
- 限价锚开盘价。

## 五、Windows 任务能否完全胜任交易 + 是否需要大模型

**结论：能；交易环内零模型，且这正是 AGENTS.md「定时任务模型降级规范」已立的硬规则方向**（核心动作全部下沉纯 Python 脚本，agent 只做调脚本+核对+报告；真实下单「模型异常宁可不买也绝不冒险」）。

证据分层：

1. **交易闭环每环节今天已是脚本在干活**：候选生成（16:30/20:05 任务）、T 档（market_tier.py，T-20260914 明令禁止 agent 自行重算）、下单（rebalance_* --live / 写桥→QMT 内置策略消费）、盘中风控（QMT 客户端内置策略秒级 STOP/TP/TRAIL，连外部 Python 都不依赖）、对账/成本锚/心跳（Windows 任务）。`guard_backfill_v13.py` 已在真实交易日以纯脚本跑通「面板→候选→脚本化取数→review_full→rebalance --live」**全链**。
2. **agent 在交易环里剩下的职责恰好全是方案 B 要删的**：09:45 多源采集+重排、09:50/09:52 dry-run 核对（与 10:07/10:08 guard 完全冗余）、推送格式化（push_*.py 已接管）。
3. **agent 战绩是减分项**：09-03 漏触发、09-15 会话中断零产出、09-29 inline 覆写 plan json——近期 P0/P1 全出在 agent 层；39 个 Quant* Windows 任务 S4U 化后零事故（xtquant 在 session 0 实测可用）。TRAE 云任务同样跑在本机进程，机器不开机两边一样不跑——**Windows-only 无可靠性损失**。
4. **兜底结构不降级**：双源（09:32 主任务 + 10:05 guard，独立任务、不同幂等判据）+ 检测层（30 分钟心跳、15:45/50 对账、DE 只读核验）+ fail-safe（数据缺失 T=1/空仓早退、候选缺失告警不交易）。
5. **大模型保留位置——全在交易环外**：观察层报告（DE 午休/盘后/盘中异动归因，只读不动单）、研究与审计（DE/TW 分工）、可选顾问层（F3 催化新闻摘要推送，人工可见、不进分数不进订单）。

诚实注明两个硬依赖（TRAE 同样解决不了）：机器与 QMT 客户端须人工开机登录；QMT 策略粘贴部署是设计内人工动作。不让模型下单不是能力问题而是纪律问题——**模型输出的不可复现性就是回测口径的天敌**。

## 八、结论一句话

盘中实时复核这座「信息新鲜度」的账，账面诱人，但回测没验证过、同族信号已证伪（P21）、还附带整条 agent 故障链；对齐回测口径能买回「已验证」三个字，代价只是放弃一个 20% 权重押在不可回测新闻分上的幻觉。
