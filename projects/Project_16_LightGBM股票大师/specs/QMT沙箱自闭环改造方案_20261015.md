核心结论三条：

1. **持仓保护优先**：4 策略当前全部停摆（10-14/10-15 换仓指令 100% 未消费，事件说明:12），当务之急不是恢复买入，而是 10-23 前把「止损/止盈/追盈」以纯风控版恢复——纯风控版零信号依赖、零文件依赖，一天量级可上线。

3. **G2/ENS 信号内产的最大障碍不是 LightGBM 本身，而是特征**：现模型特征含资金流/催化/板块等外部数据，沙箱内不可算。可行路径 = **重训一个仅用内置可得特征的模型 → dump 成纯 Python 权重硬编码进源码**；直接硬编码现有模型不可行（特征断供）。

## 一、背景与沙箱约束

### 1.1 沙箱事实（已实证）

- 2026-10-13 20:53~20:54 服务端下发 `setPyFileIOAccess nAuthValue` 从 0 变 1，对应 `m_nPythonOpFile=1`（禁文件）+ `m_nPythonConnectNet=1`（禁网络），账户级授权、重启无效、无法本地绕过（根因定论:18-25,37-41；事件说明:12）。
- IO 非对称性（事件说明:34-36，实测表）：

| 操作 | 沙箱下行为 |
|---|---|
| `open()` 已存在文件（读/写/追加） | **拒绝**（`PermissionError('Foribdden FileIO')`） |
| 新建文件 / tmp + `os.replace` | 正常（但再读回被拒） |
| 枚举目录（os.listdir / exists） | 正常 |

- **本方案不利用「新建文件可写」作为任何业务正确性依赖**：写得出读不回的通道只能当 best-effort 留痕（见 §八），状态与去重一律走内存 + 账户（任务书:52「不得假设券商恢复权限」，同理不假设非对称窗口长期存在）。
- 官方升级 deadline 2026-10-23，灰度已提前生效（任务书:13；根因定论:23,83-84）。
- 券商客服确认：行业普遍趋势、无豁免；唯一不受影响的模式 = 「内置 Python、交易信号完全在 QMT 系统内部产生、不与外部环境进行任何交互」（任务书:12）。

### 1.2 沙箱内可用能力清单（自闭环物质基础）

全部为 C++ 侧实现或官方明示能力，不经 Python `open()`/socket，不受 `m_nPythonOpFile/m_nPythonConnectNet` 拦截：

| 能力 | 说明 | 依据 |
|---|---|---|
| `passorder(…, 2, …)` / `cancel` | quickTrade=2 立即下单；`cancel(orderId, accountId, accountType, C)` 官方撤单唯一入口 | FAQ「快速交易参数 quickTrade」「下单与回报相关」 |
| `get_trade_detail_data(acct, 'stock', position/order/deal/account)` | 读客户端本地缓存，有交易主推柜台 ~50ms 刷新；账户即账本 | FAQ「下单与回报相关」第 2 条 |
| `get_market_data_ex` / `get_full_tick` / `get_stock_list_in_sector('沪深A股')` / `get_stock_name` | 行情与静态池；全推数据无品种数量限制、50ms 更新 | FAQ「QMT 行情数据基础概念」；快速开始 run_time 示例 |
| `run_time` 定时器 / `subscribe` 订阅推送 | 策略内自调度（替代外部 schtasks 驱动的文件轮询） | 快速开始「三、运行机制对比」 |
| 内置库 NumPy / Pandas / SciPy / Statsmodels / TA-Lib | **LightGBM 不在白名单，不能装**；券商后台控制白名单 | FAQ「对第三方库的支持」「安装第三方 Python 库报错」 |
| `print` → `XtClient_FormulaOutput_*.log` | C++ 侧写日志文件，沙箱不拦，是监控替代主通道 | FAQ「如何找到软件运行日志」 |
| 全局变量 / `ContextInfo` 属性 | 会话内状态；ContextInfo bar 结束保存（同会话内 bar 间有效） | FAQ「ContextInfo 逐 K 线保存的机制」 |

**不可用**：任何已存在文件读写、网络（HTTP/socket/DB）、lark-cli 推送（自身依赖网络）、第三方非白名单库、subprocess 拉起外部信号管道（产物进不来）。

### 1.3 关键机制澄清：ContextInfo 不跨重启

ContextInfo 逐 K 线保存 = **同一策略运行会话内**「bar 结束保存、下一 bar 体现、深拷贝回退」（FAQ 机制原文）；**策略重启后 init 重跑、自定义变量重置，需 init 内重建**（任务书:16 明确）。因此：

- ContextInfo/全局变量只能承担**会话内**状态（峰值、当日风控计数、pending 字典）。
- **跨重启状态只有一条可靠通道：账户即账本**（position / 当日 order / 当日 deal）。注意 QMT 模拟端 order/deal 只保留当日（AGENTS 红线「QMT 模拟端 get_trade_detail_data 只保留当日」），**跨日字段（买入日期、历史峰值、期初账本）必须走「源码硬编码快照」**——由此引出 §3.1 的三层状态模型。

另一处官方约束：quickTrade=2 立即下单模式下，官方明确要求**用普通全局变量保存委托状态、不能存在 ContextInfo 属性里**（FAQ「ContextInfo 逐K线保存的机制」影响节；快速开始实盘示例 `class a(): pass; A = a()`）。四策略全部 quickTrade=2（G2 源码:373，V13 源码:278，V2 源码:497-499），**委托状态一律全局字典**，与现状一致。

## 二、改造原则（硬约束清单）

1. **零文件**：源码内禁止 `open()` 任何运行期路径；数据/模型/账本全部以**编译期字面量**（源码内嵌）或**运行期内存**存在。`os.path.exists` 探测允许但不作为业务分支依据。
2. **零网络**：禁止 requests/socket/lark-cli；告警走 §3.4 旁路。
3. **信号内产**：评分、候选、风控信号全部由策略内 `get_market_data_ex`/`get_full_tick` + 内置 pandas/numpy 计算；外部数据只允许以「部署时人工粘贴的源码快照」形态进入（更新频率 = 策略换仓频率，见 §5.2）。
4. **账户即账本**：跨重启状态从 `get_trade_detail_data(position/order/deal)` 重建；账户 position 是持仓唯一真相（对齐 2026-08-14 P0 结论「6+2 账户 position 唯一真相」）。
5. **委托管理范式（官方 FAQ 推荐）**：全局字典 + 唯一 userOrderId（投资备注）做 key + `get_trade_detail_data` 轮询回报；待报状态挂起该品种后续报单防超单（FAQ「下单与回报相关」第 3 条）。四策略现状已符合，保留。
6. **去重水位**：sid 格式含日期+序号（现状 `P16_<date>_RSK%04d`，G2:1377-1385；V13:1140-1148），重启后从当日 order 表反查本策略 remark 的最大序号重建水位（§5.3）。
7. **风控常量硬编码**：止损/止盈/追盈/激活阈值全部源文件常量（G2:51-55，V13:48-51，V2:18-19），不依赖任何外部配置；账号 ID 硬编码 + 账本 account_id 戳校验逻辑保留（红线 T-20260823-004）。
8. **单线程禁阻塞**：QMT 所有策略共用一个线程，禁止 sleep/死循环（FAQ「下单与回报相关」第 4 条）；调度用 handlebar 时间闸门或 `run_time`，轮询间隔 ≥ 秒级。
9. **继承既有 QMT 红线**：Python 3.6 语法、GBK + `# coding=gbk` 首行、BUILD_TAG 版本标记、人工粘贴部署 + 日志核对、「passorder 全局函数」「策略时间用 C.get_current_time()」等全部不变。
10. **fail-safe 方向固定**：任何状态重建失败 → 转被动（不买只看）+ 大声 print，**绝不「活跃实例 + 状态缺失 + 持仓=0」盲跑**（2026-10-14 重复建仓实证形态；V2 `_io_preflight` 范式，strategy_v2.py:1060-1081 迁移复用）。

## 三、通用改造模式（四策略共用）

### 3.1 状态三层模型

| 层 | 载体 | 生命周期 | 存什么 |
|---|---|---|---|
| L1 会话内存 | 全局变量（`class a(): pass` 实例或模块级 dict） | 策略本次运行 | pending 委托字典、当日峰值、当日风控计数、暂缓队列 |
| L2 账户即账本 | `get_trade_detail_data` position/order/deal | 当日（order/deal）/实时（position） | 持仓与可用量、成本价（`m_dOpenPrice`）、当日已下委托（去重水位）、当日成交 |
| L3 期初账本快照 | **源码硬编码字面量**（每次人工粘贴时更新） | 直至下次粘贴 | 跨日业务字段：买入日期、历史峰值、策略归属白名单、静态数据快照（财务/估值/行业/池） |

规则：L1 丢失 → 从 L2+L3 重建；L2 只保当日 → 跨日字段必须落在 L3；**任何字段找不到归属层就不做该动作**（fail-safe）。

### 3.2 委托与去重

- 下单：`passorder(op, 1101, ACCOUNT_ID, code, prtype, price, vol, remark, 2, "", C)`，remark = 策略前缀 + sid（现状已如此：G2:373 `ORDER_REMARK="P16G2桥"`，V13:278，V2:497-499）。
- 回报：`get_trade_detail_data(acct,'stock','order')` 轮询，五条硬过滤（code/volume/status/direction/time），remark 只作候选优先级不作硬过滤（实盘红线）。
- 重启重建：init 扫当日 order 表，凡 remark 命中本策略前缀的委托 → 恢复 pending 字典 + 重建当日 sid 水位（取最大序号+1）。
- 活跃单状态码口径不变：活跃={48,49,50,51,52,55}，终态={53,54,56,57}（G2:46-48，V13:43-45）。

### 3.3 风控自闭环模式（止损/止盈/追盈）

三策略共用同一套语义（STOP -7%/-8% → TP → 追盈「激活阈值+回撤+保本底线」），数据源替换为：

| 数据 | 旧来源（文件） | 新来源 |
|---|---|---|
| 成本锚 | positions_cfg*.json | `position.m_dOpenPrice`（QMT 持仓成本价）；当日新买入用 deal 均价 |
| 追盈峰值 | state/peak*.json 跨日延续 | L1 全局 dict（会话内）+ L3 期初快照（跨日）；重建缺失时**当日 high 重锚**（偏保守，见 §5.6） |
| 行情 | get_full_tick（现状已是，G2:1358，V13:1121） | 不变 |
| 已风控卖出去重 | heart json 的 risk_sold | L1 set + 当日 order 反查重建 |

### 3.4 监控替代：print 主通道 + 外部旁路

- **策略内**：所有关键事件 print（现 `[P16G2][CMD]`/`[hb]` 等前缀约定保留），由 C++ 落 `XtClient_FormulaOutput_YYYYMMDD.log`。任务书:45 指定「监控替代 = QMT 日志文件本身」。
- **外部旁路（沙箱外，不受限）**：Windows schtasks 定时任务 grep FormulaOutput log 关键行（如 `[ALERT]`/`[RISK]`/`[FATAL]`）→ `push_alert_card.py` 推飞书。**策略进程本身零外部交互**，旁路只是单向读日志文件，符合「信号内部产生+零外部交互」豁免口径。
- 心跳替代：策略每 N 分钟 print `[HEART] <时间> <持仓数> <nav>`，旁路任务检测心跳行超时 → 告警（替代原 heart_*.json 文件心跳，G2:1511-1553 / V2 telemetry:743 一并砍掉）。

## 四、逐策略改造设计

### 4.1 V13 风控桥（strategy_p16_v13_risk_src.py）

**现状架构一句话**：无信号消费，纯风控——外部管道写 `cmd/positions_cfg_v13_<date>.json`（FIFO 含费成本锚）进，策略写 `state/peak_v13.json`（追盈峰值跨日延续）出（源码:8-11，:195-196，:231-232）。

**沙箱致命点**：positions_cfg 读被拒 → 成本=0 → 风控全天静默（源码:215 注释自认该症状：`cost=0 风控全天静默（peak_v13.json=0.0）`）；peak_v13 读写被拒 → 追盈历史丢失。

**目标架构**：信号（无）+ 风控全内闭：

- 成本锚：`get_trade_detail_data(67014907,'stock','position')` 的 `m_dOpenPrice`。注意口径差：外部 cfg 是「FIFO 含费成本」，position 成本是券商口径（含费均价）——两者语义同源（都是持仓成本），差异幅度 = 费用计入方式，对 -7%/+15% 阈值影响 <0.1pp，可接受；如需严格对齐，期初快照携带旧 cfg 成本，新仓用 deal 均价+费用计算复刻 FIFO 含费口径。
- 持仓归属（**本策略特有难点**）：账号 67014907 上 V13 与 V2 共存，原先靠外部 cfg 文件圈定 V13 管哪些票。替代 = **L3 白名单硬编码**：源码常量 `V13_CODES = {...}`（当前持仓，v13 持仓数 ≤2 只，qmt_config.py:34 `MAX_POSITION_NUM=2`），换仓日人工粘贴时更新；init 时「白名单 ∩ 账户 position」= 纳管集，白名单外持仓绝不触碰（资金分配红线：绝不纳管他人持仓）。
- 峰值：L1 dict + L3 期初快照（粘贴时写入当前各票 peak）；当日重建缺失 → 当日 high 重锚（§5.6）。

**状态重建**（init）：

1. `position` 表 → 白名单交集 → cost/m_dOpenPrice、vol/m_nCanUseVolume；
2. L3 快照 → 各票历史 peak（只升不降，对齐 T-20260910 语义，源码:1292-1294）；
3. 当日 order 表反查 remark="P16V13风控"（源码:35）→ 重建 risk_sold 去重 + 当日 RSK 序号水位；
4. 任一步异常 → 被动模式（只 print 不下单），保留 `_io_preflight` 式大声告警（参照 G2:1654-1680 探针模式，探针对象从文件改为 position 接口返回长度）。

**风控自闭环**：`_check_risk_signals`（源码:1048-1148）三规则（止损 48 / 止盈 49 / 追盈 51）逻辑零改动，仅 `_g_positions` 的填充源从「成本表+peak 文件」改为上述重建；`_write_peak`（:999-1004）删除文件写、改为内存维护 + print 留痕。pending 管理（`_check_pending_orders`:904、超时重试、撤单确认）不动。

**砍掉**：positions_cfg 读取/回退（:199-229）、peak_v13.json 读写、heart json（:1225-1230）、fills 文件。

### 4.2 G2 桥（strategy_p16_g2_bridge_src.py）

**现状架构一句话**：外部 Python（LightGBM 管道 deploy_predict/rebalance_g2）写 `cmd/orders_<date>.json`（seq 幂等），桥轮询消费 → passorder → 反查 → 回写 state/fills/heart（源码:9-14，`_process_orders_cmd`:1574-1609），并内置实时风控（成本锚=外部 positions_cfg，峰值=peak.json，`_check_risk_signals`:1285-1390）。

**沙箱致命点**：orders/cancel cmd 读被拒 → 换仓指令 100% 未消费（事件说明:42：10-15 G2 2 笔 SELL 写入未消费，重载后 ≈330 次/秒硬撞 orders 文件）；positions_cfg/peak/heart 读写全被拒 → 风控同时失效。

**目标架构**（两步走）：

**Step 1「纯风控自闭环版」（保持仓保护，S 工作量）**：

- 完全停用 orders/cancel 消费与回写（不买不换仓），仅保留 `_check_risk_signals` + pending 管理；
- 数据源替换同 §4.1：成本锚 = position.m_dOpenPrice（70180771 账户），峰值 = L1+L3，risk_sold = 当日 order 反查；
- 持仓归属：70180771 是多策略共享账号，G2 持仓圈定同样用 **L3 白名单**（G2 当前持仓数小，`g2_ens_config.TOP_N=5` 量级）；
- 该版本消除「停摆期间持仓无保护」的当前最大风险敞口。

**Step 2「信号内产版」（恢复买入能力，L 工作量）**：

- 信号引擎内移：在策略内以 `run_time`/handlebar 时间闸门在固定时点（对齐原 09:50 G2 换仓时点）执行「取数 → 特征计算 → 模型打分 → 目标持仓 diff → 走既有订单执行链（`_do_passorder`:364 + `_lookup_order`:674 + pending 重试）」。
- **LightGBM 处置（关键难点，详见 §5.1）**：直接硬编码现有模型不可行（其特征含资金流/催化/板块等沙箱外数据）。推荐路径 = **重训「内置可算特征版」模型**（仅价量/换手/波动等 `get_market_data_ex` 可得特征）→ LightGBM dump 成纯 Python 树结构字面量硬编码 → 自写 predict（numpy 向量化）。打分通过率需回测对齐验证（重训模型的样本外表现须先在 QuantLab 侧回测验收，达标才部署——**不在本方案内假设达标**）。

## 五、关键难点与备选（每条给推荐项）

### 5.1 LightGBM 模型怎么办（G2/ENS 信号内产）

| 备选 | 评估 | 结论 |
|---|---|---|
| a. 现有模型权重硬编码 | **不可行**：模型特征含资金流（moneyflow）/催化（新闻）/板块等沙箱外数据，特征断供，权重硬编码了也没输入 | 排除 |
| b. **重训「内置可算特征版」模型 → dump 纯 Python 硬编码** | 模型规模：G2 LightGBM 数百树 × 数十叶 → dump 为嵌套 tuple 字面量约 50-200KB；推理：TOP 候选池数百样本 × 数百树，numpy 向量化毫秒级，单线程无压力；重训模型样本外表现须先在 QuantLab 侧回测验收 | **推荐**（附验收门槛：样本外不劣于基准才部署；不达标则该策略停在纯风控版） |
| c. 降级线性评分卡（BP+小市值，内置可算，BP 因子 IC=0.069） | 等于换策略，G2 语义大变，需全量回测重验；且与 V2 同质化 | 备选（b 不达标时再评估） |
| d. 信号留在沙箱外，改走 miniQMT/xtquant 外部进程执行 | xtquant 进程不受公式引擎沙箱限制（P16 V1.3 即此形态）；但违背「QMT 内自闭环」任务方向，属架构级备选 | 兜底备选，需诚哥拍板 |

**推荐：b，门槛不达标则维持纯风控版 + 呈报 c/d 裁决。**

### 5.2 评分 CSV / 财务估值字段怎么办（V2 及 G2 特征快照）

| 备选 | 评估 | 结论 |
|---|---|---|
| a. **静态快照源码内嵌**（构建脚本生成字面量 → 人工粘贴） | 财务字段 QMT 无 PIT 接口（红线：`C.get_market_data_ex` 缺财务字段，PE/PB/circ_mv 必须来自预生成数据——内嵌即「预生成进源码」）；更新频率对齐换仓频率（2 月级），运维成本可控；策略语义零变化 | **推荐** |
| b. 全部因子改内置实时自算 | 无财务/股本数据源，BP/市值因子算不出来；等于放弃 BP 因子（V2 主力因子），策略证伪重来 | 排除 |
| c. `get_instrument_detail` 取股本/行业自算市值 | 股本字段口径（总/流通）与 circ_mv 不一致风险，行业字段可用性未验证；只能作快照的降级兜底，不能当主源 | 列入 §九 实测项 |

### 5.3 跨重启去重水位（防重复下单）

**推荐**：sid = `<前缀>_<YYYYMMDD>_<序号>`（日期天然隔离跨日重复）+ init 扫当日 `get_trade_detail_data(acct,'stock','order')`，按 remark 前缀过滤取最大序号重建水位；同日重启后已下委托按 §3.2 恢复 pending。依据：官方 FAQ 委托管理范式（全局字典 + 投资备注 key + 轮询回报）；模拟端 order/deal 只保当日（红线）→ 日期编码进 sid 使「隔日查不到」不再构成风险。任务书:41 同方向。

### 5.4 候选池 / 股票池来源

**推荐**：`C.get_stock_list_in_sector('沪深A股')`（官方快速开始 run_time 示例原句）作全市场底池 → 内嵌快照过滤（E1 筛选在快照字段上执行）。不推荐 `set_universe`（官方已标注「不再推荐使用」，无法反订阅）。V2 现状 `_load_pool`（:149）读的外部池本身就来自 E1 筛选——内嵌快照 = 同一产物换个载体，口径不变。

### 5.5 持有天数 / 买入日期（position 无此字段）

**推荐**：L3 期初账本携带 `entry_dates`（每次粘贴时写死）+ 当日 deal 增量；重建缺失时以快照粘贴日为保守下界。60 天上限容忍 ±1 天（偏保守=提前一天卖，方向安全）。V2 的 60 天是「最长持有」上限而非精确事件（:1201 `days_held >= MAX_HOLDING_DAYS`），保守偏差可接受。

### 5.6 追盈峰值跨日延续

| 备选 | 评估 | 结论 |
|---|---|---|
| a. **当日 high 重锚**（峰值丢失时 peak=当日 high） | 追盈线 = max(成本, peak×0.92)（G2:1370）：重锚当日 high ≥ 成本时线偏松（晚触发）、< 成本时不影响（激活阈值未到，G2:1368 `peak >= cost*1.08` 才追踪）；方向 = 少卖不乱卖，保守可接受；实现零成本 | **推荐默认** |
| b. L3 期初快照携带各票 peak | 精确延续，但每次粘贴需人工同步，漏更风险 | 推荐叠加（有快照用快照，缺失走 a） |

### 5.7 同账号多策略归属（V13+V2 @67014907；G2+ENS+他策略 @70180771）

**推荐**：每策略 L3 白名单硬编码 + 下单前当日 deal 反查互斥（对方 remark 已买/已持有的票跳过）+ 资金分配表约束不变（`capital_allocation.yaml` 校验流程照旧，沙箱外动作）。白名单漏更的风险敞口 = 新买入不在白名单 → 风控漏管；缓解 = 买入成交后当日内白名单自动失效告警（print `[WARN] 新持仓不在白名单，请更新粘贴`）+ 旁路告警。此风险需在验证清单里专项核对。
