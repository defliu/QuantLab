## 1. 背景与终极目标

### 现象（三条，均来自看板 `T-20261018-003`，执行方须独立复核）

1. **G4 观察期闸空转**：`data/g2_live_model.json` 存在 `trial`（promoted 2026-09-15 00:38:37，`prev_top2_ret=+0.00953`，`ends_after_days=10`）。`rollback_check_g2.py --auto` 每日 16:47 在跑，已打印「promoted 后已过 12 交易日」「观察期候选 2 笔，前向 ret 均值 = -0.0919」，但随后走 **`样本不足（<3 笔），暂不判定，继续观察。`**（exit 0）→ **0915 从未被 G4 复核**。
2. **日志具误导性**：外层 ps1 对「无待观察 trial / 观察期通过 / 深度劣化已回退」三类情形统一打印 `[G4观察期] … OK`，掩盖了第 4 类「样本不足未判定」。
3. **前向纸面回填停摆**：09-15 之后 `paper_forward_live.csv` 的 `ret` 几乎不再回填（看板口径：最后回填日 2026-09-16）。**数据源不缺**：`data_live/merged_daily_full.parquet` 已到 2026-10-16（1476 万行），非行情断更。

## 5. 必须做的检验（含竞争假设判别）

### 5.1 竞争假设

- **H1 覆写假说**：`paper_forward.py` 与 `deploy_predict_g2.py` 的 `_append_live_dedup` 均用 `drop_duplicates(subset=["date","code"], keep="last")`（已核：两处实现一致）。若 `deploy_predict_g2` 对**同一日期复审/复跑**再次追加候选行（`ret` 必为空），按 `keep="last"` 会**覆盖已回填的 ret** → 表现为"回填过又消失"。
  - ⚠️ 已核事实：`load_open_panel()` 的 docstring 明确记录过 2026-09-04 另一类同族故障（主库停更 → 候选天天产生、收益永远算不出、63 笔回填 0 笔），说明该链路**有静默失效前科**。
- **H2 静默空产假说**：`--backfill` 每日被调用，但**产出 0 笔**（到期窗口判定 / 数据源合并口径 / 异常被吞），CSV 从未被写过 → 表现为"回填停摆"。
- **H3 其他**：请自行列举（如调度未触发、编码/BOM 导致读失败、`_append_live_dedup` 从 `paper_forward.py` 调用时 `log_csv` 指向错误路径等）。

### 5.2 判别方法（必须全部执行）

- [ ] **日志-产物对账（决定性证据）**：从 `data/real/paper_forward_daily.log` 逐日抽取 `--backfill` 的输出（回填笔数）。**某日输出 N>0 但 CSV 对应行 ret 仍为空 → 支持 H1；逐日输出 0 笔 → 支持 H2。**
- [ ] **代码路径审计**：两条 `_append_live_dedup` 的调用点、`log_csv` 实参、写目标文件是否为同一路径；`keep="last"` 在同日重跑场景下的实际行为。
- [ ] **独立复算（外部裁判）**：写 `research/diag_paper_forward_ret_20261018.py`，**不读 CSV 的 ret 列**，直接从 `merged_daily_full.parquet` 按 §3 口径重算每个候选的 ret，与 CSV 逐行对比，输出三分类：一致 / CSV 缺失 / CSV 与独立复算不符。
- [ ] **交叉参照**：`paper_forward_exit_live.csv` 同期有已平仓记录（说明到期数据存在）——用它的候选集合与 live 做集合差，验证"到期候选数"是否真的不足以触发判定（即 G4 的「样本不足」是真样本不足还是样本被吞）。
- [ ] **三态区分验证**：`rollback_check_g2.py` 的四种结局（无 trial / 通过 / 回退 / 样本不足）在外层 ps1 输出上是否可区分；给出最小改法（仅建议，不实施）。
- [ ] **时间分段**：把 08-17~09-14 与 09-15~10-16 两段做差分，定位"哪一天开始变"。
