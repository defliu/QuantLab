## 1. 架构总览

```
qmt_monitor.py 盯盘循环
    │  触发信号 / 心跳
    ▼
qmt_card.py  build_signal_card() 生成 Card 2.0 交互卡片
    │  send_lark_card()  →  lark-cli.exe
    ▼
~/.lark-cli/config.json（App 身份，secret 存系统 keychain）
    │  清理注入 + 关 strict-mode → 回退本地 bot 凭据
    ▼
POST /open-apis/auth/v3/tenant_access_token/internal  → tenant token
POST /open-apis/im/v1/messages  → 私聊刘诚（2026-08-29 起仅私聊，群发已取消）
    ▲
    │  用户点击卡片按钮（加入关注）
    └── card_webhook.py（HTTP :9001，守护脚本 + 任务计划自愈）
            落库 data/qmt_watch_cards.json
```

### 3.2 重新配置（换 App / 重置 Secret 后）

```powershell
# ① 清掉旧的 config.json（可选）
Remove-Item -Force "$HOME\.lark-cli\config.json"

# ② 关键：必须临时清掉 Agent 上下文信号，否则 lark-cli 拒绝 config 管理
Remove-Item Env:HERMES_HOME,Env:OPENCLAW_HOME,Env:LARK_CHANNEL -ErrorAction SilentlyContinue

# ③ 用 stdin 传入 secret（避免进进程列表）
'<APP_SECRET>' | lark-cli config init --app-id <APP_ID> --app-secret-stdin --brand feishu --lang zh_cn

# ④ 验证
lark-cli whoami   # 期望 identity: bot / tokenStatus: ready
```

> ⚠️ **不要在对话/命令行明文贴 App Secret**。本对话中出现的多个 Secret 已按规范视为泄露，建议全部在开放平台重置。

## 7. 故障排查（踩坑记录）

| 现象 | 根因 | 解决 |
|---|---|---|
| `hermes context detected but lark-cli is not bound` | `HERMES_HOME` 等 Agent 上下文信号存在，lark-cli 只认 hermes 绑定、忽略本地 config.json | 推送代码 `_env_for_cli("bot")` 清理 `HERMES_HOME/OPENCLAW_HOME/LARK_CHANNEL`；服务器无此变量不受影响 |
| `"config" is not supported: credentials provided externally` | Agent 环境下 `config` 系命令全部锁定 | 同上，清掉 Agent 信号后再用 `config init` |
| `invalid config format: no apps` | 手写 config.json 缺 `apps` 数组 | 用 `config init` 生成标准 schema，勿手写 |
| `open_id cross app`（99992361） | open_id 是应用维度，发给了错误应用的 open_id | 换用目标应用下的 open_id（见 §4 获取方法） |
| `unknown property: corner_radius (column)` | Card 2.0 的 `column` 组件不支持 `corner_radius` | 从 column 移除该字段，圆角交容器 |
| `app_scope_not_applied`（查群成员失败） | 应用未在开放平台申请 `im:chat.members:read` 等 scope | 需应用管理员在开发者后台申请并发布版本；RequestAuthorization 无法替代 |

## 8. 安全注意事项

- App Secret 通过 `--app-secret-stdin` 配置，存系统 keychain，**不落盘、不进进程列表**
- 本对话中已明文的 Secret 一律视为泄露，建议全部重置
- 回调服务公网部署必须配置 `LARK_ENCRYPT_KEY`，否则可被伪造回调
- 推送失败仅记录、不重试、不影响盯盘主流程（容错设计）
