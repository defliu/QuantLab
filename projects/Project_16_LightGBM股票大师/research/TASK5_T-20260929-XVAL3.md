## 5. 工作包 C：红线作用池差异 → 实际部署结果偏差量化

### 5.1 背景事实（已确证）

同一名义"红线 60"，两端作用在**不同母池**上：

**回测引擎**（`scan_rotate_cost_real.py`，`PRE_POOL=100` / `TOP10=10`）：

```python
pre = day.nlargest(PRE_POOL, "prob")     # 概率 Top100
per_day[d] = pre.nlargest(TOP10, "prob") # 再取概率 Top10
cand = cand[cand["total_new"] >= THRESHOLD]   # 红线在 Top10 内生效
```

**部署端**（`deploy_predict_g2.py`）：

```python
pre = day.nlargest(args.pool, "prob")                    # 概率 Top100
pre = pre[pre["total_new"] >= args.threshold]            # 红线在 Top100 内生效
picks = pre.nlargest(args.top, "total_new")              # 再按总分取 Top10
```

即：

```text
引擎：Top100 → Top10 → 红线 → 持仓
部署：Top100 → 红线 → 位置过滤 → total Top10 → 持仓
```

已知候选数量差：引擎 Top10 内过线**日均 3.38** 只，部署 Top100 内过线**日均 33.78** 只。

### 5.2 核心要求

**只比候选数量是不够的。** 必须做严格 apples-to-apples 反事实，量化**实际部署结果**的偏差。

两个口径必须锁定以下**全部**条件一致，仅红线作用池不同：

- 同一模型（0915）、同一日频数据面板
- 同一 F3 补算（`_fill_f3_events`）、同一 F6 数据源
- 同一交易日集合（516 日）、同一持有期与退出规则
- 同一持仓上限、同一成本假设、同一初始资金

### 5.3 必须输出的偏差量化

**候选层**：

- 日均候选数、候选身份重合率（Jaccard / 交集 / 并集）

- 被引擎口径漏掉、但部署口径会选中的票的性质（prob 分布 / total 分布 / F5 分布）
