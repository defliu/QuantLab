## 〇、结论先行

**V2.0 的收益数字（年化 75.88%、日超额 +0.149%、夏普 1.86）不能直接采信。**

原因不是造假，而是**归因链断裂**：这个数字属于一个模型（g2 / 43 特征 / 1964 树），
而 8/31 被 promote 为"V2.0"上线的是另一个模型（33 特征 / 3017 树），后者**从未跑过任何可执行口径回测**。
叠加"回测期 = 模型测试集 + 500 组合全期寻优未校正"与"样本外 12 笔 t=0.51、剔除极值即转负"，
V2.0 目前应定位为**待验证候选**，而非已验证策略。

**真实性综合评级：3.1 / 10**
（回测方法学中上，收益归因与验证链断裂）

最硬的一条实盘对照：`data/strategy_capital.json`（8/31 09:53）——
剥离 8/24 超买标的后，策略真实口径 **start 100,000 → capital 98,505.35，即 -1.49%**。
回测年化 +75.88% 与实盘 -1.49% 之间，隔着一条尚未被任何证据填补的鸿沟。

## 一、六项裂缝（按严重度）

### 裂缝 1【P0】收益数字与上线模型错位 —— "V2.0"名下挂着两个不同模型

| 项 | 回测收益归属的模型 | 8/31 实际上线的模型 |
|---|---|---|
| 文件 | `versions/models/lgb_model_v3_g2_strong_real_20260825_1964t.txt` | `versions/models/lgb_model_v3_V20_live_20260831.txt` |
| 树数 | **1964** | **3017** |
| 特征数 | **43** | **33** |
| test IC | **0.082** | **0.070** |
| 可执行回测 | ✅ 有（`param_thr60_real.md` / `ANNUAL_RESULT.md`） | ❌ **零** |

核实方式：直接 grep 两个模型文件的 `feature_names=` 行与 `Tree=` 计数，结论确凿。

`data/real/` 下与 V2.0 / v20 / 0831 相关的回测报告**一份都没有**（唯一命中是无关的腾讯行情 txt）。
这意味着：**75.88% 年化属于 g2 模型，而线上跑的 33 特征模型没有任何可执行收益证据。**

自证矛盾：同一份 `周一实盘运行检查清单_20260831.md` 里，
第 184 行写"V2.0 资产备份：3017 树/**33 特征**"，第 188 行写"信号层（LightGBM/**43特征**）"——
连文档自己都说不清 V2.0 是哪个模型。

### 裂缝 2【P0】V2.0 已回滚，文档仍标"已上线"

- `data/model_panel_binding.json`：`"note": "2026-08-31 回滚 V2.0→V1.2（用户确认）: V1.2 正式模型 2837树/27特征/面板8-27"`
- `周一实盘运行检查清单_20260831.md` 第 5-7 行：正式模型 = **V1.2（2837 树，27 特征，面板 8/27）**
- `run_scheduled.ps1:102`：生产选股 = `deploy_predict.py --model v3 --top-k 10`，`deploy_predict.py:174` 默认红线 **58**
- `VERSIONS.md:24`：V2.0 仍标 **"✅ 已上线（promote 2026-08-31）"**，无回滚记录

**净结果：V2.0 至今零实盘成交。** 其"收益"100% 是回测数字。
且当前生产跑的是 V1.2（27 特征 / 红线 58），与 V2.0 收益数字的产生配置（43 特征 / 红线 60）无一处相同。

### 裂缝 3【P0】回测期 = 模型测试集，500 组合全期寻优未做多重检验校正

回测期 `2024-07-01 ~ 2026-08-14` 恰为 `train_optuna.py` 的 test split 终点。
参数在该区间内**同时**寻优，组合空间：

```
红线 5 档（50/55/58/60/62） × N 4 档（1/3/5/10）
× 止损止盈 5 组 × 持仓数 5 档（2/3/5/8/10） = 500 组合
```

`BIAS_AUDIT_20260825.md` 自认"红线 60 与持有期 N 为测试期全期寻优，存在参数过拟合成分"。

**决定性证据 —— 红线 58→60 的符号翻转**（同一模型、同一期间、N=10）：

| 区间 | 红线 58 | 红线 60 | 差 |
|---|---|---|---|
| 全程 | +0.055% | +0.149% | +0.094pp |
| 前半 2024-07~2025-06 | **-0.027%** | **+0.132%** | **+0.159pp** |
| 后半 2025-07~2026-08 | +0.173% | +0.180% | +0.007pp |

阈值提高 2 分，前半段结果由**负**翻**正**，日超额差 0.159pp ≈ 年化 38pp。
这种量级的不连续跳变只有一个解释：**结果由极少数个股驱动，不是稳定的横截面 alpha。**

在 500 重检验下，Bonferroni 校正后需 p < 0.0001 才算显著。表面 t≈4.5 看似过关，
但按下节有效样本量折算后 t 仅约 1~2，经不起校正。

### 裂缝 4【P1】有效样本量远小于表面

`param_thr60_real.md` 中 N=10 的**成交笔数是 102**，`ANNUAL_RESULT.md` 却写"交易数 516"。

两者其实不矛盾，但表述极易误读：

- 516 = **交易日数**（`ANNUAL_RESULT` 表头误标为"交易数"）
- 102 = **成交笔数**，对应 516/11 ≈ **47 个独立轮次**（N=10 满仓 2 只 → 每轮 2 笔）

**关键点**：每笔持仓贡献 10 个连续日收益，日收益序列存在强自相关，
515 个日观测的**有效样本量只有约 47**，不是 515。按 47 折算，t 值约为表面值的 √(47/515) ≈ 0.30 倍。

另有口径冲突：`paper_forward.py --replay` 报 **806 笔**（每日滚动、重叠建仓），
与 `scan_rotate_cost_real.py` 的 **102 笔**（非重叠轮次）是两套口径，
却都被引用来描述"V2.0 的 N=10 表现"。806 笔之间大量重叠，统计独立性更差。

### 裂缝 5【P1】前向验证口径错配，且单票运气主导

**① 口径错配**：前向验证记的是"**次日 open→close**"，而回测的 alpha 来自 N=10。
回测自己给出的短持有期结果是：

| 持有期 | 日超额（滑点 0.1%） |
|---|---|
| N=1 | **-0.141%（负）** |
| N=3 | +0.010% |
| N=5 | +0.095% |
| N=10 | +0.149% |

即：**用次日收益去验证一个"持有 1 天是亏的"策略，逻辑上无法验证其 alpha 来源。**

**② 统计不显著**：12 笔（`REPLAY_FINAL_20260825.md`）
均值 +0.54%、标准差 3.686%、标准误 1.064% → **t = 0.51**，完全无法区分于零。

**③ 剔除单笔极值即转负**：

| 口径 | 笔数 | 均值 | 胜率 |
|---|---|---|---|
| 全样本 | 12 | +0.54% | 58.3% |
| 剔除 603032（+8.13%） | 11 | **-0.147%** | 54.5% |

**12 笔收益全部来自一只票的 +8.13%。** 这与 P12 RPS 主升浪被证伪的机理完全同构 ——
候选池只有 2 只/天，样本极薄，单票运气即可主导全部结论。

**④ 样本积累停滞**：`paper_forward_live.csv` 最新日期停在 8/28（文件 mtime 8/31 09:40），
且 8/28 的 2 只**重复追加 4 次**（去重逻辑缺陷）。实际有效样本 9 个交易日，
距自定判据 N>30 尚需 2~3 个月。

### 裂缝 6【P1】回测引擎可执行性处理不对称 + 生产数据时效事故

**① 卖出侧缺可执行性过滤**（`scan_rotate_cost_real.py`）：
买入侧有完整的 `_executable()` 过滤（一字涨停 / 停牌 / 零成交），
**卖出侧没有一字跌停 / 停牌过滤**。而止损 -7% 触发日往往正是暴跌日，一字跌停概率不低 ——
卖不掉却按开盘价成交，**系统性高估收益**。

**② 持仓冻结隐患**：盯市时若 `open_map` 取不到价（退市 / 长期停牌），代码 `continue` 跳过，
该持仓**既不盯市也不卖出、市值锁死**。`BIAS_AUDIT` 称 462 只买入中退市/停牌 0 只（未触发），
属潜在隐患而非既成事实，但方向上偏乐观。

**③ 生产链路数据时效事故（8/31 实锤）**：300456 因 TDX 503 降级 iFind **前一日**口径，
用"8/28 主力净流入 +5.26 亿"打出 **F2=10** 冲上 TOP1；
实际东财 8/28 = **-2.79 亿**、8/31 当日 = **-1.25 亿**，**方向完全相反**。
真实 F2 应为 1 分，总分 86 → 68，直接**跌出 TOP3**。

{"account_id":"67014907","start":100000,

实盘样本太短，不足以证伪；但这条鸿沟必须由样本外证据来填补，而不是由回测数字来掩盖。

## 三、公正评价：回测引擎确实做对的部分

不因结论否定工程质量。以下七项经源码逐行核实，在仓内属中上水平：

1. **时间对齐正确**：T 日特征 → T+1 开盘建仓（`open_map[(dates[buy_i+1], c)]`），盯市用全市场 open，无经典前视偏差。
2. **建仓日不计收益**：新买入当日 value=invest 直接入账，不参与当日盯市；次日开盘价 = 执行价，缩放后仍为 invest。逻辑自洽。
3. **成本口径真实**：佣金万 2 双边（最低 5 元）+ 印花税万 5（卖出）+ 过户费万 0.1（沪市），与 `qmt_config.py` 实盘费率一致，全项目统一。
4. **滑点敏感性三档全披露**（0 / 0.1% / 0.2%）。
5. **买入侧可执行性过滤**：一字涨停、停牌、零成交全部剔除。
6. **幸存者偏差已审计**：测试期 70 只提前终止股中面板含 45 只（1.05%），462 只买入标的退市/停牌 0 只。
7. **诚实自曝过拟合**：`BIAS_AUDIT_20260825.md` 主动标注时期依赖与参数过拟合，并给出子区间数据 —— 这是加分项，比多数项目做得好。

**问题不在引擎，在于：引擎跑出的数字被错误地归属给了另一个模型，并被当作上线依据。**

## 五、建议行动路径（按优先级，均需人工确认后执行）

### P0-1 · V2.0 身份澄清与改名（不改代码，只改登记口径）

- **V2.0-g2** = 43 特征 / 1964 树（回测收益 75.88% 的真实归属）
- **V2.0-live** = 33 特征 / 3017 树（8/31 promote，无任何收益证据）
- `VERSIONS.md:24` 状态由"✅ 已上线"改为"**⏸ 已回滚（8/31）→ 待大QMT 链路验证**"，补一行回滚记录
- `周一实盘运行检查清单` 第 188 行"43特征"与第 184 行"33特征"的矛盾需统一

### P0-2 · 给 33 特征 V2.0-live 补跑可执行回测

用**同一引擎、同一区间**（`scan_rotate_cost_real.py` + `BT_MODEL` 指向 V2.0-live）：

- 红线 **58 / 60 双档**，N ∈ {5, 10}，滑点 0 / 0.1% / 0.2%
- 与 g2 基线（+0.149% / 年化 75.88%）同口径对照

**判据**：若 V2.0-live 日超额显著低于 g2（例如 < +0.08%），
则大QMT 迁移的信号层应直接用 **g2 模型（1964 树 / 43 特征）**，弃用 33 特征版。
**没有这一步，V2.0-live 就是裸奔上线。**

### P0-3 · 年化 75.88% 降级表述

在所有看板 / 汇报中，该数字必须附带完整限定语：

> "回测口径：g2 模型（43特征/1964树），测试期 2024-07-01~2026-08-14（即模型 test split），
> 红线 60 / N=10 / TOP2 / 滑点 0.1%，成交 102 笔 ≈ 47 个独立轮次，
> 参数经 500 组合全期寻优，**未经多重检验校正**，**非上线模型**结果。"

**禁止**把 75.88% 与"V2.0 上线"并列呈现。

### P1-1 · 重做前向验证口径（关键）

- 从"次日 open→close"改为：**记录选股日 Top2，跟踪未来 10 个交易日 open→open 收益**，与 N=10 的 alpha 来源对齐
- 修复 `paper_forward_live.csv` 重复追加（8/28 重复 4 次）
- 判据升级为三条同时满足：**N>30 笔** + **剔除最大单笔后均值仍 >0** + **t > 2**

### P1-2 · 补统计显著性检验

- 对 102 笔成交做 bootstrap，报告日超额 95% 置信区间
- 对 500 组合寻优做 Bonferroni 校正（α = 0.05/500 = 0.0001）
- 报告"剔除最优 5 笔后的年化"（尾部依赖检验）—— 这是识别单票运气最直接的手段

### P1-3 · 回测引擎卖出侧补可执行性过滤

- 与买入侧对称：卖出时校验一字跌停（`open <= down_limit`）、停牌、零成交
- 持仓取不到价时，按"最后可用价 + 退市损失假设"处理，而非冻结市值

### P1-4 · 红线参数改用 walk-forward 重定

当前 58 / 60 为全期寻优，且前半段 58→60 从 -0.027% 翻到 +0.132%。
建议改为"前半段定参 → 后半段验证"，或滚动前推，避免事后选参。

### P2-1 · 生产链路数据时效硬校验

8/31 的 300456 事故（iFind 前一日口径打出 F2=10，实际方向相反）说明降级路径仍在污染选股。
建议：**非当日资金数据一律按缺失处理（F2 = 5 分中性），不参与 TOP 排序**，
宁可少选，不可用错方向的数据打高分。

### P2-2 · 统一口径表述

- `ANNUAL_RESULT.md` 表头"交易数 516"改为"**交易日数 516 / 独立轮次 47 / 成交笔数 102**"
- `paper_forward` 的 806 笔（重叠）与 `scan` 的 102 笔（非重叠）必须各自标注口径，不可混用
