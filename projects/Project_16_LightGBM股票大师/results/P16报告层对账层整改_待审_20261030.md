## 2. P0-1｜报告解析：续行 + `FILL?`

### 2.1 根因（我上一轮引入的回归）

`18be561` 为修「V13 面板把 G2 成交算成自己的」，把 `_scan_log` 从「扫全部行」改成 `key not in line` 过滤。实测代价：

| 实现 | 捕获事件行 | 后果 |
|---|---|---|
| 改动前（`3cded59`，无 model 过滤） | **90 条** | 能抓到续行，但串读所有策略 |
| 我改后（`18be561`，子串过滤） | **43 条**（G2） | 串读修好了，**续行全丢** |

真实日志统计（可复现）：
```
P16SIG 事件行 90 条：带时间戳前缀 76、续行 14（15.6%）
  ORDER   2 条 → 续行 2（100%）
  FILL    3 条 → 续行 3（100%）
  FILL?   9 条 → 续行 6
  INIT    8 条 → 续行 0（今天恰好都带前缀，属运气）
```

### 2.2 改法

`_scan_log` 改为**归属状态机**：
- 命中 `reqid = 0<路径>\python\<模型>.py_NNN` ⇒ 切换当前归属模型 + 记录时间戳；
- 不命中归属标记的行 ⇒ 视为**上一条 print 的续行**，继承模型与时间戳；
- 归属 == 本模型 且命中 `[P16SIG][EXEC]` ⇒ 计入事件。

模型名用正则提取后**等值比较**（不用子串），同时解决 `_G2_EXEC` 吃 `_G2_EXEC_SBX` 的隐患。

`_summarize_events`：`kind == "FILL"` 才计入 fills，`FILL?` 单独计入 `foreign_fills`。

`p16_close_report.py:94` 的时间窗**不需要单独改**——状态机让 `e[2]` 变成真实时间戳，`[11:16]` 自然就是 `HH:MM`（旧实现对续行切出 `EC] F`，字符串比较恒 False）。
