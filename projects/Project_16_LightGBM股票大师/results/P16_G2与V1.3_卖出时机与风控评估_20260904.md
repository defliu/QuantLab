## 三、风控：逐项体检

### 3.1 V1.3 · 实锤「假止损 + 重复触发」

300684 事故仓的成本 85.74，-7% 止损线应为 **79.74**。实际触发记录：

| 时间 | 卖出价 | 相对成本 | 相对止损线 | 判定 |
|---|---|---|---|---|
| 08-25 09:45 | 85.00 | -0.93% | 高 6.6% | ❌ 假信号 |
| 08-25 10:30 | 86.00 | +0.24% | 高 7.9% | ❌ 假信号（盈利也止损） |
| 08-25 11:00 | 84.91 | -1.03% | 高 6.5% | ❌ 假信号 |
| 08-25 14:00 | 85.98 | +0.21% | 高 7.8% | ❌ 假信号 |
| 08-25 14:30 | 85.13 | -0.78% | 高 6.8% | ❌ 假信号 |

5 笔合计 -982 元，全部在 ±1% 噪声区间内触发，距真实止损线 6~8 个百分点。

**两个候选根因（至少其一成立，需补日志确认）：**

- **成本锚污染**：`qmt_monitor.py:133` 在 FIFO 成本缺失时回退 `getattr(p, "open_price", 0)`（QMT 当日开盘价）。若 8/25 该股开盘价 ≈ 91.5，则止损线 = 85.1，与实际触发价位吻合。
- **跨进程无幂等**：`qmt_monitor.py:313` 的 `sold = set()` 是**纯内存**变量。定时任务以 `--once` 模式每次启动新进程 → `sold` 归零 → 同一信号重复下单。5 次触发的时间点（09:45 / 10:30 / 11:00 / 14:00 / 14:30）正是多个不同调度点，高度吻合。

### 3.2 V1.3 · 大盘门控在空仓档失效

`rebalance_daily_guard.ps1:91-100` 实现了档位判定：沪深300 ≤ -1.5% → T=0。但：

```python
# rebalance_daily.py:215
if not target:
    print(f"!! 当日清单过红线(>{REDLINE:.0f})的票为 0，本日不换仓（宁缺毋滥）")
    return          # ← T=0 时 target 为空，直接 return：不买，也不卖
```

`load_selection(sel_path, 0)` 返回 `stocks[:0]` = `[]` → `target` 为空 → **直接返回，持仓原封不动**。
即：**大盘破位信号触发时，策略不清仓。** 门控形同虚设。

（兜底脚本 `rebalance_daily_guard.ps1:100` 在 T=0 时 `exit 0` 不调用换仓，掩盖了这个缺陷，但 09:45 主流程若传入 `--top 0` 就会踩中。）

### 3.3 G2 · 无大盘门控 + 仓位闭环缺失

**① 完全无大盘过滤**：`g2_config.py` 无 tier / MA / 指数相关字段，`rebalance_g2.py:build_plan` 无条件满仓。9/2 在 moneyflow 缺 11 天的过期数据下仍建仓 15.76 万，无任何刹车。

**② 仓位超配 65.9%**：

| 日期 | G2 持仓市值 | 资金池×95% | 偏离 |
|---|---|---|---|
| 09-02 | 600262 10.05 万 + 300964 5.70 万 = **15.76 万** | 9.5 万 | **+65.9%** |
| 09-04 | 300475 3.40 万 + 001266 4.43 万 = **7.67 万** | 9.5 万 | **-19.3%** |

- 超配根因：`build_plan` 用 `capital × 95% / n_slots` 计算目标市值，**从不校验账户已有持仓市值**。9/2 因 `status==55` 误判导致双倍建仓后，无任何环节发现并刹车。
- 欠配根因：**高价股整手取整**。300475 单价 170 元，1 手 = 1.7 万 = 单票目标仓位（4.75 万）的 **35.8%**。`int(47500/170.02/100)*100 = 200` 股 → 实际买入 3.40 万，取整损失 28%。

**③ 成本锚当日缺失 → 次日风控可能瞎**：9/4 由纠错脚本建仓，docstring 明确「不生成 positions_cfg（等 15:40 reconcile 以 QMT 真相为准）」。而 `cmd/` 下最新只有 `positions_cfg_20260903.json`。若 9/4 15:45 的 `reconcile_g2` 未成功生成 9/4 的成本锚，则 9/5 开盘时 `_check_risk_signals` 读到 `cost = 0` → `if cost <= 0: continue` → **300475 / 001266 的止损止盈完全不生效**。

### 3.4 两侧共同的缺口

| 缺口 | 说明 |
|---|---|
| **无组合级回撤熔断** | 只有个股 -7% 止损。Top2 等权 = 单票 50%，两票同时 -7% 即组合 -7%，无组合层上限保护 |

## 五、优化建议

### P0-1 · 删除 V1.3 的 PK_OUT，改为「期满 + 止损 + 止盈」三规则（对齐回测）

- **定位**：`rebalance_daily.py:241-253`（`sell_plan` 构造）
- **改法**：`sell_plan` 只保留「持有满 HOLD_DAYS 个交易日到期」的持仓；未到期不卖。与 G2 的 `rebalance_g2.py:280-302` 完全一致。
- **HOLD_DAYS 取值建议**：
  - 若保持红线 58 / V1.2 模型 → **N=5**（红线 58 口径下唯一接近零的档位 -0.023%，且样本 212 笔是 N=10 的 1.9 倍，统计功效更好）
  - 若切到红线 60 / g2 模型 → **N=10**（日超额 +0.149%，盈亏比 1.97，回撤最小）
- **验收**：改后跑 `scan_rotate_cost_real.py` 的 PK_OUT 开关 ablation，确认「有 PK_OUT」与「无 PK_OUT」两版日超额差异 ≥ 0.1pp（若差异不显著，说明样本不足以支撑，需先看 P2-3）

### P0-2 · 修复 V1.3 假止损与重复触发

- **定位**：`qmt_monitor.py:133`（open_price 兜底）、`312-313`（peak/sold 内存态）
- **改法（三步）**：
  1. **成本锚强制 FIFO**：删除 `open_price` 兜底，成本取不到就剔除盯盘（277-287 行已有剔除逻辑，删掉 133 行的兜底即可）
  2. **信号状态持久化**：`sold` 写 `data/cache/monitor_sold_<date>.json`，进程启动时恢复；每日开盘清空
  3. **二次确认**：连续 2 个 tick（间隔 ≥ `MONITOR_INTERVAL`）均满足条件才下单，防瞬时插针
- **验收**：模拟盘构造「成本 100、现价 99」→ 不触发；「现价 92.9」→ 触发一次且仅一次；重启进程后不重复触发

### P0-3 · 修复 V1.3 空仓档不清仓

- **定位**：`rebalance_daily.py:215`
- **改法**：`target` 为空时改为「卖出全部策略持仓（清仓）+ 0 条买入」，而非 `return`
- **验收**：dry-run `--top 0` → 生成全部持仓 SELL、0 条 BUY

### P0-4 · G2 补大盘门控

- **定位**：`g2_config.py`（新增 `TIER_RULES`）、`rebalance_g2.py:257`（`build_plan`）

- **验收**：注入 hs300 = -2.0 的 mock，dry-run 确认只出 SELL、0 条 BUY

### P0-5 · G2 仓位闭环硬校验

- **定位**：`rebalance_g2.py:312-322`
- **改法**：
  1. 买入前先算 `当前 G2 持仓总市值 + 本次买入额 ≤ capital × deploy_pct`，超限则缩减股数或跳过并 fail-loud 告警
  2. 高价股取整容差：单价 > 100 元时，若 `目标市值 / 单价 / 100 < 3`（即不足 3 手，取整误差 > 33%）→ 跳过该票并告警
- **验收**：构造「已持仓 15 万 + 资金池 10 万」场景 → 0 条 BUY + 告警；构造 300475 场景 → 跳过或按容差买入

### P1-2 · G2 成本锚生成前移

- **验收**：次日盘前检查项出现「成本锚缺失」告警时，当日禁止买入

### P1-3 · 加卖出冷却期

### P1-5 · 卖出侧加可执行性过滤（回测 + 实盘）

- **同时修回测**：`scan_rotate_cost_real.py:162-196` 卖出侧补 `_executable()` 对称过滤（V2.0 评估报告 P1-3 已提，尚未落地）

### P2-1 · 组合级回撤熔断

- **改法**：组合市值从峰值回撤 ≥ 8%（≈ 2 只票同时触发止损）→ 当日停买 + 次日强制减半仓，人工确认后解除

### P2-2 · 两策略卖出规则收敛

- **改法**：抽出公共模块 `strategy/exit_rules.py`（止损 / 止盈 / 到期 / 冷却 / 大盘门控），V1.3 与 G2 只传参不同

### P2-3 · 前向验证口径对齐（承接 V2.0 报告 P1-1）

### 最重要的判断

**不建议在 G2 的第一轮 N=10 实盘完成前，同时推进 P2 的重构。**

理由：G2 至今 0 笔策略自身驱动的卖出，N=10 的证据全部来自回测。当前最高价值动作是**让 G2 干净地跑完一轮 N=10（建仓 → 持有 10 日 → 到期卖出）**，用真实成交验证卖出规则，而不是继续叠加新规则。

V1.3 则应立刻止血：删除 PK_OUT、修复假止损、修复 T=0 清仓——这三项都是**零成本且有回测证据支撑**的改善。
