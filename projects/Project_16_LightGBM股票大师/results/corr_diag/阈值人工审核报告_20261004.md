### 关于 `PASS=935 FAIL=0` 的准确含义

这**只**证明「审计脚本用原始数据独立复算的结果」与「生产 Core 的输出」逐字段一致，
即实现口径无偏差。它**不**证明：

- 阈值取值合理；
- 阈值已被批准；
- 诊断结果可用于阻断交易。

17 项核对清单：

```
ind_top1_ratio  ind_hhi  ind_miss_ratio  ind_n_industries
idx_top1_ratio  idx_n_indexes
sty_coverage  sty_top1_ratio  sty_n_loaded  sty_n_buckets  sty_stale_days
cor_n_passed  cor_n_pairs  cor_max  cor_mean  cor_n_high_pairs  cor_largest_cluster
```

其中 `cor_largest_cluster` 的独立复算**刻意不复制 Core 的并查集实现**，改用
「邻接表 + 迭代 DFS 连通分量」。目的是让两种算法路径互证：若 Core 的路径压缩、分组或
`size>=2` 过滤写错，独立实现会暴露不一致。实测 55 个批次全部一致，说明 Core 的
并查集实现无误。

### 独立实现自身的专项测试（PASS=28 FAIL=0）

审计脚本的独立实现本身也需要被验证，否则「独立」只是声明。专项测试
`research/tests/test_corr_diag_audit_graph.py` 覆盖四组共 28 项，全部通过：

| 组 | 项数 | 内容 |
|---|---:|---|
| A 边界 | 7 | 空输入 / 无边 / 单孤立点 / 自环 / 单边 / 边含未知代码 / 孤立点+配对 |
| B 图结构 | 10 | 链、环、重复边不重复计数、桥接合并簇等 |
| C 与 Core 互证 | 400 图 + 2 断言 | 随机图逐个与 Core 并查集比对，**零分歧**；并反向断言「随机图中确实产生 `size>=3` 的簇」，防止两边同时返 0 造成假通过 |
| D 键名契约 | 9 | 行为级断言 `cor_largest_cluster` 存在、旧键 `cor_n_clusters` 不复现；源码级断言防回归 |

其中 D 组最初写成用 `__code__.co_names` / `co_consts` 检视字节码判断返回字典的键，
连续失败两次——这类断言依赖解释器实现细节，不是语义验证。已改为**直接调用函数检查
返回值**，既不依赖字节码布局，也真正锁住运行语义。

术语说明：上述实现是显式栈的**迭代 DFS**（`stack.pop()` 取末元素），不是 BFS。
连通分量的节点集合与 BFS 等价，结果不受影响，此处仅订正术语以免文档与代码不符。

### 分母差异说明（审阅 CSV 时易误判，务必注意）

- `sty_top1_ratio` 仅 39 个有效值 → 16 个批次风格覆盖率为 0，此时无 top1 桶可比；
- `idx_top1_ratio` 仅 49 个有效值 → 6 个批次候选与宽基成分**零交集**。

两者为 `None` 是**正确行为**，不是数据缺失或计算失败。

### 一个易被误读的现象

```
g2/20260928  cand=1  overall=WARN  四 section 全空
ens/20260928 cand=4  overall=WARN  四 section 全空
```

这不是「候选数不足被误判为正常诊断」，而是 Core 的**日期状态升级**设计：
候选数不足时只写 `sections["_skip"]`、`overall=SKIP`；但若 `date_info` 为
WARN/FAIL，则整体升级为该日期状态。这两批次的
`signal_date=20260928` 而 `market_last_date=20260924`，日期滞后触发 WARN。
属预期行为，无需修改。

## 三、逐条阈值审核意见

### 3.1 `min_candidates = 5` —— 建议保留

- 触发：11/66 批次短路（16.7%）。
- 短路批次集中在候选池枯竭日（如 20260914~20260917 连续多日 cand=1~2）。
- 小样本下 HHI、最大相关等统计量会剧烈失真，跳过判定是正确取舍。
- **保留现值。** 是否按策略分别设定，留待观察样本积累后再议。

### 3.2 `industry_top1_ratio = 0.40` —— 建议保留但标记「可能漏报」

- 触发 2/55 = 3.6%；分布 p90=0.40、max=0.50。
- 阈值恰落在 p90 位置，属于**偏保守**设定：只捕捉最极端的集中。
- 代价是 p75~p90 区间的「中高集中」批次不会告警。
- **本轮不建议自动修改。** 若后续要提高召回，建议改用 p95 附近的取值，而非拍脑袋放宽。

### 3.3 `industry_hhi = 0.25` —— 建议保留

- 触发 4/55 = 7.3%；分布 p75=0.22、p90=0.24、max=0.32。
- 鉴别力优于 top1_ratio（能捕捉「 top1 不高但整体分散度仍差」的情形）。
- 与 3.2 构成互补，**两条同时保留比只留一条更合理**。

### 3.4 `industry_miss_ratio = 0.20` —— 建议「暂停采用」，先查数据质量

- **55 个诊断批次全部为 0**，触发率 0.0%。
- 当前样本**无法支持**该阈值的实际触发能力：既不能证明它有效，也不能证明它多余。
- 0 缺失说明行业映射在这批数据上是完整的，但样本量不足以标定。
- **建议**：暂不改动，改为在数据质量巡检中单独跟踪。若连续扩大样本后仍恒为 0，
  应重新审视该指标的定义是否有意义，而不是简单收紧或放宽。

### 3.5 `style_min_coverage = 0.50` —— **暂停采用：基准集合与候选池结构性不匹配**

这是本次审核**最重要的发现**，不建议按「偏严→放宽」的常规思路处理。

证据链：

1. 触发 52/55 = **94.5%**，几乎所有批次都判为异常 → 噪音远大于信号；
2. 覆盖率分布：min=0.00、p25=0.00、**med=0.10**、p75=0.275、p90=0.40、max=0.60；
3. **16/55 个批次覆盖率为 0**（v13=3, g2=7, ens=6）；
4. 全部 55 个诊断批次 `sty_n_loaded = 6` → **风格数据加载全部成功**，
   不是数据缺失，而是**候选股票压根不落在这些基准里**。

结论：当前 6 个正式风格基准

```
000918.CSI 300成长   000919.CSI 300价值
399630.SZ  1000成长  399604.SZ  中小价值
399371.SZ  国证价值  399372.SZ  大盘成长
```

以大中盘为主，而实际候选池规模小、偏小盘 → 结构性覆盖不匹配。
把 `0.50` 放宽到 `0.10` 只会让阈值迁就数据，掩盖真正的口径问题。

**建议人工决策三选一（本轮不执行）**：

- (A) 更换/扩充风格基准集合，纳入小盘风格基准（如中证 2000、国证 2000 等）；
- (B) 将风格维度由**绝对覆盖率**改为**相对覆盖**（例如与宽基覆盖率的比值），
  使不同市值层的候选可比；
- (C) 暂时停用风格维度的阈值判定，仅作观测字段输出，不参与 `overall`。

**在拍板前，`style_min_coverage` 不应被解读为「选股池风格不分散」的证据。**

### 3.6 `style_member_max_stale_days = 45` —— 建议保留数值，但需人工确认容忍度

- 触发 25/55 = 45.5%；分布 med=42、p75=53.5、p90=60、max=69 天。
- 45 天线把**接近一半**批次标为快照偏旧。
- 这条与 3.5 不同：它反映的是**数据刷新节奏**，不是口径错配。
- 若上游风格成分确实按季更新（月/季末调仓），45 天可能天然偏紧。
- **需人工确认**：上游刷新频率与业务可容忍滞后天数。确认后再定，本轮不改。

### 3.7 `style_top1_ratio = 0.60` —— 建议「重新审视定义」

- 仅 39 个批次有有效值，触发 0/39 = 0.0%。
- 最大值远低于 0.60 → 该阈值在当前口径下**无鉴别力**。
- 但根因大概率在 3.5：若候选根本不在风格基准里，就谈不上「集中于某风格」。
- **建议**：先解决 3.5 的基准集合问题，再回头评估本条是否有意义。

### 3.8 `index_top1_ratio = 0.50` —— 建议「偏松，暂无鉴别力」

- 仅 49 个批次有有效值，触发 0/49 = 0.0%；**最大值仅 0.4444**。
- 阈值 0.50 高于历史最大值 → 在当前样本下**永远不会触发**。
- 与 3.4 不同：这条不是数据质量问题，而是**阈值明显宽于分布上界**。
- **建议**：若保留本维度，阈值应下移至分布 p95 附近；否则该条等同虚设。
  本轮不自动修改。

### 3.9 `corr_pair = 0.70` —— 建议保留（当前最有鉴别力的指标之一）

- 触发 26/55 = **47.3%**，处于合理区间：既能发现问题，又不至于普遍命中。
- 分布：cor_max med=0.6877、p75=0.7680、p90=0.7890、max=0.9215。
  0.70 恰落在中位数略上，位置合理。
- **保留现值。** 但需注意分策略差异显著（见第二节），后续应考虑分策略标定。

### 3.10 `corr_cluster_min = 3` —— 建议保留，标记「偏严」

- 触发 8/55 = 14.5%；分布 med=0、p75=2、p90=3、max=4。
- 要求「≥3 只股票形成同一高相关连通簇」确实较严，多数批次达不到。
- 但这类事件**本身就是真风险信号**（一簇同涨同跌会放大组合回撤），低触发率可接受。
- **保留现值。** 独立复算（邻接表 + 迭代 DFS）已确认 Core 簇规模计算正确。

### 3.11 数据质量类阈值 —— 无需改动

`corr_window=60`、`corr_min_obs=30`、`corr_max_zero_ratio=0.50`、
`corr_min_std=1e-9`、`style_effective_buckets=1`

这些是**计算口径参数**而非风险阈值，不适用「触发率高低」的判读逻辑。
本轮审核范围内未发现异常，保持原值。
