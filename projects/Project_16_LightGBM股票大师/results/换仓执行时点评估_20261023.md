## 四、关键结论：完整换手时该漂移**精确对冲**

回测买卖**都在开盘价**，实盘买卖**也同在 09:45/09:50**：

```
实盘完整换手收益 = 卖出价(09:50) / 买入价(09:50)
                = [open_sell ×(1+5bp)] / [open_buy ×(1+5bp)]
                = open_sell / open_buy          ← 与回测完全相同
```

5bp 在买卖两端**同向出现 → 在收益率上抵消**。

真实的净成本只落在「**净仓位变化**」上：

| 场景 | 净成本 |
|---|---|
| 空仓 → 建仓（首次/清仓后重建） | 1 个资金池 × 5bp ≈ **50 元**（一次性） |
| 加仓（半仓 → 满仓） | 增量部分 × 5bp |
| 清仓（T=0 / 全部卖出） | **负数**（卖出价更高，反而受益） |
| 满仓轮动（卖旧买新） | **≈ 0** |

反过来说：回测按 10bp/边 计提共 20bp，实盘时序滑点 ≈ 0bp，**实盘比回测假设有利约 20bp/完整换手**。口径不但没吃亏，还偏保守。

**→ 为省这 5bp 去改调度，收益不支持改造与回归测试成本。建议不动。**

## 五、真正值得处理的两个非时序问题

### 5.1 【P1】gap_guard 量比阈值永不满足 → 「低开放量承接放行」是死代码

`position_filter.gap_guard()`：

- `GAP_HARD_PCT=-5%`：`open_pct ≤ -5%` → 硬拒（今日 001395.SZ 低开 -5.6% 被拦，**行为正确**）
- `GAP_HARD_PCT < open_pct ≤ GAP_OPEN_PCT(-3%)`：要求 `vr ≥ GAP_VR(2.0)` 才放行

而 `vr = 当日累计成交量(手) / 近5日日均成交量(手)`，**未按已开盘分钟数归一化**。实测（2026-10-23 全量 5 日数据）：

| 时点 | 301536.SZ | 600000.SH | 000001.SZ |
|---|---|---|---|
| 09:32 | 0.011 | 0.011 | 0.010 |
| 09:35 | 0.027 | 0.026 | 0.025 |
| 09:45 | 0.080 | 0.079 | 0.075 |
| 09:50 | 0.107 | 0.105 | 0.099 |
| 10:07 | 0.198 | 0.195 | 0.184 |

**任何时点都 < 0.2，永远达不到阈值 2.0** → `-3% ~ -5%` 低开的票**一律被拒**，"强势承接放行"通道自上线以来从未生效。

正确口径应为**时间归一化量比**：

```
vr = (累计成交量 / 已开盘分钟数) / (5日日均成交量 / 240)
```

正常日 ≈ 1.0，放量日才 > 2.0。修好后该区间才会真正按量能区分。

#### 5.1.b 修复落地与实测（T-20261023-007，2026-10-23 当晚完成）

**代码改动（实盘与回测同口径）**：

| 文件 | 改动 |
|---|---|
| `position_filter.py` | 新增 `elapsed_session_min()` + `gap_volume_ratio()`；`GAP_VR` 默认 2.0 → **3.3** |
| `rebalance_g2.py` / `rebalance_ens.py` / `rebalance_daily.py` | 3 个调用点改用 `PF.gap_volume_ratio(code, vol_lot)`（内部自取 5 日均量） |
| `g2_config.py` / `g2_ens_config.py` / `qmt_config.py` | `GAP_VR` 常量同步 2.0 → 3.3（防误导） |
| `backtest_b21_strategy.py` | `_volume_ratio_0950()` 改时间归一化；`VOL_RATIO_MIN` 2.0 → 3.3（可用 `BT_GAP_VR` 覆盖） |

**阈值 3.3 的定档依据**（实测：119~200 只随机股票 × 最近 40~45 交易日，全量分钟线）：

| 口径 | median | p75 | ≥2.0 占比 |
|---|---|---|---|
| 旧：09:50累计量 / 前5日**全天**均量 | 0.193 | 0.277 | **0.49%** |
| 新：单位时间量比 | 2.32 | 3.32 | 63.1% |

**关键发现——低开日集合本身量能就偏高**：

低开 `-5%~-3%` 子集（n=197，占全样本 2.64%）内，单位时间量比 `median = 3.21`、`p75 = 5.08`，
显著高于全样本 median 2.32 → **低开当天开盘 20 分钟普遍是恐慌性放量**。
因此阈值必须在**低开子集**上定，不能套用全样本分位：

| 阈值 | 低开子集放行率 | 占全样本比例 |
|---|---|---|
| 2.0 | 75.6% | 2.00% |
| 3.0 | 55.3% | 1.46% |
| **3.3（采用）** | **46.7%** | **1.23%** |
| 4.0 | 37.6% | 0.99% |
| 5.0 | 25.9% | 0.68% |
| 旧口径 2.0（对照） | **1.02%（2/197）** | 0.03% |

取 3.3 ≈ 低开子集中位数，语义为「**低开的票里，只有成交节奏强于该类样本中位水平的才放行**」，
既恢复了分档能力，又保持防守性（过半低开仍拒）。

**回归测试**：`tests/test_gap_guard_20261023.py`，25 项全 PASS —— 覆盖 gap_guard 四分支 +
边界（-3.0% / -5.0%）+ fail-open + `elapsed_session_min` 10 个时点（含午休/收盘后）+
量比量纲（常态 1.0 / 3.3倍 3.3 / 缩量 0.5）+ 阈值单调性与分界点。

**回测影响 = 0（已实证）**：`backtest_b21_strategy.py --arm g2 --model live --slips 0.001`
在 `BT_GAP_VR = 2.0 / 3.3 / 99`（99 = 完全关闭 gap_guard）三档下结果**逐位相同**：
总收益 +26.94% / 年化 +11.82% / 夏普 0.82 / 回撤 -15.0% / 124 笔。
→ 该窗口内 G2 路径**没有任何一笔落在 -5%~-3% 低开带**，本改动是**纯前瞻性加固**，
不改变任何历史结论，也不影响 110.08% 官方锚点（该锚点走 `scan_rotate_cost_real`，不含 gap_guard）。

**部署**：gap_guard 属**外部执行层**（`rebalance_*.py` 在 QMT 之外跑），
不进入 QMT 内置单文件产物 → **无需重新粘帖 QMT**，次日 09:50 换仓自动生效。

### 5.2 【P2】V1.3 的 F5 用「执行日开盘 15 分钟」，回测用「信号日全天」

| | 回测 | V1.3 实盘 | G2 实盘 |
|---|---|---|---|
| F5 行业涨幅 | **信号日 T 全天** | **执行日 T+1 前 15 分钟** | 信号日 T 全天（夜间快照） |
| 数据来源 | 面板 `ind_pct_ths` | `review_full.py` 实时（`f5_source=realtime`） | 快照 `ind_pct_ths` |

**不同日 + 不同时间尺度**。回测中 F5 是「昨日板块强弱」，实盘 V1.3 是「今日开盘 15 分钟板块强弱」。

实例（2026-10-23）：10 只候选的实时 `industry_pct` 全为 **-2.38 ~ -3.95**，全部落入 F5=2 最差档；
而当日全市场实际中位数 **+1.56%**、**77.3% 个股上涨**（09:53 时点大盘正处于日内低点，之后单边上行）。

> 注：该日两种口径**恰好**都得 F5=2.0（因为 10-22 是真实普跌日，信号日全天口径同样是 2.0），
> 故当日最终分数不变。但这**不能**掩盖结构上的跨日偏差——其他日子两者会明显分歧。

F6 同病：实盘用实时 PE/换手，回测用信号日 `daily_basic`。F2 已通过「T-1 Tushare 权威源」对齐 ✅。

**两个选项（需拍板）**：

- **A 对齐回测**：V1.3 的 F5/F6 改用信号日（T-1）全天口径 → 实盘即等于已通过 110% 验证的回测行为；代价是放弃"开盘动量确认"这一层实盘独有过滤。
- **B 保留实时**：承认这是独立设计，但**必须用实盘口径重新回测验证**（现有 110% 不可直接作为预期）；否则回测数字与实盘不可比。

**✅ A 方案已落地（T-20261024，诚哥拍板）**，改动与验证结果：

- **改动**：`review_full.py` 的 F5/F6 选源逻辑重写——F5 主源唯一为 `sw_l1_pct_map` 信号日自算（缺失→中性 5.0，与回测 `score_f5(nan)` 一致，不再用实时/SC_F5 面板兜底）；F6 主源为 Tushare `daily_basic`（信号日）→ 缺失回退候选 CSV `SC_F6`（与回测 est 缺失回退同构），实时 PE 降为仅展示、差异>50% 才提示。同步修复 `sw_l1_pct_map` 忽略 asof 的**周一新鲜度陷阱**（旧逻辑 lag≤2 → 周一跑周五信号日 lag=3 必落中性；新逻辑按 asof 精确取数 + lag 0~4 容错）。
- **10-23 主源失效定性**：函数本身无问题（10-24 复测 10/10 全命中），10-23 09:52 失败为当时态问题（大概率增量库未就绪，无日志可回溯）；缺失→中性本就是设计内 fail-safe，不阻塞。
- **回归验证（20261023 候选重跑）**：10/10 只 `f5_source` 全部从 `realtime` → `sw_l1_20261022`；F5 分值 10/10 不变（该日两口径恰好同档，普跌日）；F6 7/10 从 7.0→10.0（实时 PE 口径偏紧，信号日 daily_basic 更准）；总分变化 -6.0 ~ +25.0，**过线(≥58)集合从 0 只 → 2 只（300014.SZ 68.5、300841.SZ 60.5）**。总分变化主因是 F2 执行日权威源滚动（10-24 重跑取 10-23 moneyflow，旧跑取 10-22），属预期数据滚动而非回归失败。
- **旧口径产物备份**：`data/selections/20261023_selection_full.csv.bak_realtime_20261024`（旧实时口径基准留存）。
