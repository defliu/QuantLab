# G4 观察期回滚闸修复 + 0915 模型回退裁决（T-20261018-003）

> 生成 2026-10-18 | 缘起：T-20261018-002（0825 vs 0915 模型实证）排查中发现 G4 闸空转
> 改动文件：`paper_forward_daily.ps1`、`rollback_check_g2.py`、`run_scheduled.ps1`（G4 日志分支）、新增 `research/tests/test_rollback_check_g2.py`

## 一、现象与影响

G2 live 模型 2026-09-15 换版到 `0915_1522t` 时写入了「10 交易日观察期」trial（设计上由 `rollback_check_g2.py` 到期复核前向，劣化即回退/自动回退）。实际：

- `rollback_check_g2.py --auto` 每天 16:47 都在跑，但永远走 `样本不足（<3 笔），暂不判定` 分支（exit 0）；
- 外层 `run_scheduled.ps1` 把 exit 0 统一打印为「无待观察 trial / 观察期通过 / 深度劣化已自动回退，OK」→ **看起来一切正常**；
- 结果：**该模型的观察期回滚保护从未生效**（单票/模型劣化防护空转），纸面降级闸（需 n≥30 到期样本）同样吃不到样本。

## 二、根因链（三层，全链可复核）

1. **解释器**：`paper_forward_daily.ps1`（16:45 纸面管道）把 `$py` **硬编码**为 TRAE SOLO 内置解释器
   `C:\Users\Administrator\AppData\Roaming\TRAE SOLO CN\...\python.exe`，该解释器已损坏
   （`Fatal Python error: init_fs_encoding ... No module named 'encodings'`）。
   → 它是 T-20261012-001（同日修 `run_scheduled.ps1`/`nightly_check_task.ps1`/`heartbeat_alarm.ps1`）**漏掉的第 4 个脚本**。
2. **管道**：`build_g2_daily.py` 立即失败 → ps1 打 `[2026101x_...] BUILD-ALERT build_g2_daily 异常退出 (exit=1)` → `exit 2`，
   后续全部步骤（含 `paper_forward.py --backfill`）**从未执行** → 纸面数据自 2026-10-12 起停更
   （`data/real/g2_pipeline_daily.log` 最后一条成功记录为「合并后 2026-10-09 / 回填 133/222」）。
   **日志实测量化**：日志中 `No module named 'encodings'` / `Fatal Python error` 各出现 **40 次**（每个步骤各崩一次），
   `BUILD-ALERT build_g2_daily 异常退出 (exit=1)` 出现在 **09-28 与 10-12~10-16**（连续段 10-12 起）→ 与「最后成功回填 10-09」吻合。
   （注：该内置解释器损坏属间歇性——09-28 有告警、09-30~10-09 又能跑通，疑与 TRAE 侧升级/替换有关，故不宜按"某日一刀切"理解。）
3. **判定**：`paper_forward_live.csv` 的 `ret` 停在 09-16（09-17 起其实**已经可算**的候选一笔都没回填，实测 09-17/09-18 两组 8 笔 entry/exit 都能取到价）→ `rollback_check_g2` 永远样本不足 → 外层假 OK。
   （`data_live/merged_daily_full.parquet` 与 `data_live/incremental_daily.parquet` 均新鲜到 2026-10-16，**不是行情断更**。）

## 五、G4 只读裁决（**重大结论，待拍板**）

修好后立刻只读跑 `rollback_check_g2.py`（未加 `--auto/--apply`，指针未动，备份 `g2_live_model.json.bak_20261018`）：

```

观察期候选 67 笔，前向 ret 均值 = -0.0775（源: paper_forward_live.csv ret）

VERDICT=deep_worse → 深度劣化连续 1/3 日 → VERDICT=suggest_rollback（exit 2）
```

**按设计自动化会自己走到回退**：`rollback_streak.json` 今日已记 `streak=1`；若下一个交易日 16:30 的 daily 链继续判 `deep_worse`，**第 3 个交易日（约 10-21）`--auto` 会自动把 live 指针回退到 `0825_1964t` 并推飞书**。这是既有设计行为（"回退方向永远安全"），但属**生产策略变更**，须诚哥确认：

- **选项 A（推荐）**：让自动化按设计执行（前向 -7.75% vs 基线 +0.95% 是 8.7pp 量级的深度劣化，且与 T-20261018-002 的策略层结论同向）；
- **选项 B**：先暂停自动回退（例如临时 `--check` 或清 trial），等纸面双轨 A/B（0825 vs 0915 并行 15~20 交易日）出结果再拍板；
