## 四、op 自身两处审计错误（方法论教训）

这一节比结论更重要——**结论对不代表推理对**，必须留档。

### 4.1 f-string 正则判定法有缺陷

- **错误方法**：`re.findall(r'f["\']', text)` 判定 f-string
- **错误结果**：在 6 个桥文件上**误报 `fstr=6`**
- **正确方法**：`ast.JoinedStr` 节点判定（语法树层面唯一可靠）
- **正确结果**：**6 个桥文件全部 `fstring=0`**
- **教训**：**语法级判定必须走 AST，正则只做粗筛**。正则会把 `for attr in (...)` 的 `f"`、`"SELL_STOP", "` 等无关字符组合计入。
- **延伸风险**：`build_p16_g2.py` 内的禁用语法扫描同属正则粗筛，**存在同类假阳/假阴风险**，DE 复核时须留意（本轮以独立 AST 脚本复核为准，未修改该构建脚本）。

### 4.2 函数归属判错

曾称 `_resolve_fill_avg` / `_adverse_slippage`「不存在」。**实际存在于三个 QMT 桥内部**（自包含实现，因 QMT 单文件不能 import 外部模块），不在 `order_guard.py`。

**结论对、理由错**。教训：断言「某函数不存在」前，必须先确认它**应该存在于哪个文件**。

### 4.3 由 4.2 查出的真实设计口径差异（非缺陷）

```text
桥内：fill_avg → order_obj → ref_price → unresolved   （四级降级）
外部：fill_avg → ref_price → unresolved               （三级降级）
```

桥内多一级 `order_obj` 兜底（桥在 QMT 内拿不到 `traded_price`），且 `strategy_p16_g2_bridge_src.py` 明确要求 **`price 恒 > 0` 才可记账**，**比外部侧更严**。这是合理设计，**勿误判为不一致**。

## 五、构建一致性复核（2026-10-03 全量重算，**两处口径订正**）

### 5.1 实测结果（重新读取当前文件、按各自正确编码完整解码后逐行比较）

```text
g2   src=1773  build=1773  len_equal=True  full_decode_diff=2  差异行=[1, 25]
v13  src=1365  build=1365  len_equal=True  full_decode_diff=2  差异行=[1, 22]
ens  src=1763  build=1763  len_equal=True  full_decode_diff=2  差异行=[1, 24]
```

每对**恰好 2 处**差异，且两处都是构建器的**设计转换**：

| 位置 | 差异内容 | 性质 |
|---|---|---|
| L1 | `# coding=utf-8` → `# coding=gbk` | AGENTS.md QMT 红线强制要求 |
| BUILD_TAG 行 | 源码占位时间戳 → 本地构建时间戳 | 构建器每次构建自动替换 |

```text
g2 : L25 src BUILD_TAG="20260831-000000"  → build BUILD_TAG="20261002-193332"
v13: L22 src BUILD_TAG="20260907-000000"  → build BUILD_TAG="20261002-193451"
ens: L24 src BUILD_TAG="20260831-000000"  → build BUILD_TAG="20261002-200314"
```

### 5.2 归一化后完全一致（两种独立方法互证）

```text
方法一：把「编码头行」与「BUILD_TAG 行」替换为占位符后逐行比较
        g2 / v13 / ens  →  normalized_diff_lines = 0

方法二：difflib.SequenceMatcher（归一化后）
        g2   ratio=1.000000  non-equal blocks=0
        v13  ratio=1.000000  non-equal blocks=0
        ens  ratio=1.000000  non-equal blocks=0
```

### 5.3 订正记录（两处旧口径均作废）

| 旧口径 | 问题 | 本次订正 |
|---|---|---|
| `src=1613 / 1253 / 1603`、`DIFF_LINES=1` | 行数与差异数都错。1613/1253/1603 **无法**由任何"仅跳过头部"的完整逐行比较得到（当前实际 1773/1365/1763）；且差异不是 1 行而是 2 行（漏算了 `BUILD_TAG` 替换） | 以 5.1 实测为准 |
| 「唯一差异为编码头」 | 漏了 `BUILD_TAG` 这一处**按设计就不同**的转换 | 差异恰为 2 处，均为设计转换 |

### 5.4 正确判据（三层，缺一层就会误判）

```text
第 1 层  原始字节比对        → 不一致（UTF-8 vs GBK，设计如此，不是缺陷）
第 2 层  完整解码逐行比对    → 每对恰 2 处差异（编码头 + BUILD_TAG）
第 3 层  归一化后逻辑文本    → 完全一致（difflib ratio=1.0）
```

> **准确结论：三对 src/build 逻辑完全同步，原始字节不一致，且两处字节差异均为构建器的设计转换（GBK 转码 + BUILD_TAG 注入），不是构建缺陷。**
>
> DE 复核提示：不要用「`DIFF_LINES` 是否等于 0」或「字节是否相同」做判据，两者都会得到错误结论；必须显式归一化编码头与 `BUILD_TAG` 后再比较，并按三层分别陈述。

## 十二、审计方法论沉淀（供后续复用）

1. **语法级判定走 AST**，正则只做粗筛（f-string 误报实例）。
2. **构建一致性判据要写「除首行编码头外无差异」**，不能简单用 `DIFF_LINES == 0`。
3. **「结论对」不等于「推理对」**：op 自身两处错误须与结论一并留档，否则错误方法会被复用。
4. **断言某函数不存在前，先确认它应该存在于哪个文件**（QMT 桥自包含实现 vs 外部模块）。
5. **双 tag 语义必须分清**：本地构建版本 ≠ QMT 实际运行版本，「改了没部署」≠「改了没重建」。
6. **委派任务书的事实前提必须 op 先用原始数据验证**，且文件范围写死绝对路径、要求首行 `SCOPE_ACK` 回显范围。
