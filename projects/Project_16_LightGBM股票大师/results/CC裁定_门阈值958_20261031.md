## 2. 改法（精确到行）

### 2.1 `rebalance_g2.py:44-48` —— 常量拆成两个

**现状**：

```python
# --plan-only 的落盘截止时刻（HHMM）。必须早于执行壳窗口起点（G2 窗口 09:50–09:58，
# 见 build/strategy_p16_g2_exec.py 的 EXEC_HM_START=950）。
# 取 950 表示「窗口一开就不再写新计划」——计划在窗口内才落盘的话，执行壳要么已错过、
# 要么拿到的是一份与当日实际下单不一致的文件。
PLAN_ONLY_DEADLINE_HM = 950
```

**替换为**：

```python
# --plan-only 的落盘截止时刻（HHMM）= 执行壳窗口**终点**（G2 窗口 09:50–09:58，见
# build/strategy_p16_g2_exec.py 的 EXEC_HM_START=950 / EXEC_HM_END=958）。
# 取 958 而非 950：窗口内每 5 秒轮询（同日 POLL_MIN_SEC），09:50–09:58 落盘的计划
# 仍会被执行壳消费，按 950 卡会白丢这段；窗口关后再写则只剩「污染当日记录」的坏处
# （2026-10-30 19:22 时钟跳变补跑就是这一路）。
PLAN_ONLY_DEADLINE_HM = 958

# 窗口内**不覆盖**已就位计划的 mtime 阈值（HHMM）= 执行壳窗口**起点**。
# 必须与上面的 958 分开：signal_id 是「策略-日期-计划内容哈希」（qmt_signal_hub.py:171），
# 而执行壳只对同一个 sid 去重（placed_sids + already_applied）。窗口内把计划内容换掉
# ⇒ 新 sid ⇒ 同一批腿再下一遍单。mtime >= 950 说明这份计划是窗口内写的、可能已被消费，
# 一律不覆盖。（09:40 正常落盘的计划 mtime < 950，不受此限，仍可在 09:5x 被修正。）
PLAN_ONLY_FROZEN_HM = 950
```

### 2.2 `rebalance_g2.py:622-628` —— 门里加冻结判据

**现状**：

    if args.plan_only and not args.date:

**替换为**：

```python
    if args.plan_only and not args.date:
        _hhmm = int(time.strftime("%H%M"))
        if _hhmm >= PLAN_ONLY_DEADLINE_HM:
            print("[SKIP] 已过执行窗口（现在 %04d >= 截止 %04d）——不生成计划，避免覆盖当日正式计划"
                  % (_hhmm, PLAN_ONLY_DEADLINE_HM))
            print("        若这是补跑，属正常跳过；若每日都如此，排查任务触发时点（应 09:40）。")
            return 4
        # 窗口内也不覆盖「已就位」的计划：mtime 落在 950 之后 = 它是窗口内写的，
        # 执行壳可能已经消费过。换掉内容会得到新的 signal_id，导致同一批腿二次下单。
        _pp = os.path.join(G.DATA_DIR, "rebalance_g2", "rebalance_g2_%s.plan.json" % date)
        if os.path.exists(_pp):
            _mt = int(time.strftime("%H%M", time.localtime(os.path.getmtime(_pp))))
            if _mt >= PLAN_ONLY_FROZEN_HM:
                print("[SKIP] 当日计划已就位（%s mtime %04d 落在窗口内）——不覆盖，避免执行壳二次下单"
                      % (os.path.basename(_pp), _mt))
                return 5
```

**返回码约定**：`4` = 过窗口；`5` = 窗口内已冻结。**两者都是「正常跳过」，不是故障。**
若外层（计划任务/巡检脚本）有 `rc != 0 即告警` 的逻辑，需把 4/5 一起放行——请顺带核一遍

### 2.4 新增 G6 —— 冻结判据必须有行为用例

`run_main` 已把 `G.DATA_DIR` 指向 tmp，可直接在里面预制文件：

```python
    # --- G6 窗口内已就位计划不得被覆盖（G6 是 §9-6 选 B 的配套前提）---
    tmp6 = tempfile.mkdtemp()
    try:
        d6 = os.path.join(tmp6, "rebalance_g2")
        os.makedirs(d6, exist_ok=True)
        p6 = os.path.join(d6, "rebalance_g2_%s.plan.json" % time.strftime("%Y%m%d"))
        with io.open(p6, "w", encoding="utf-8") as f:
            f.write(u'{"marker": "frozen"}')
        # 把 mtime 拨到「今天 09:52」= 窗口内
        _t = time.localtime()
        _ts = time.mktime((_t.tm_year, _t.tm_mon, _t.tm_mday, 9, 52, 0, 0, 0, -1))
        os.utime(p6, (_ts, _ts))
        rc6, f6 = run_main(["--plan-only"], 945, tmp6)
        _body = io.open(p6, encoding="utf-8").read()
        check("G6 窗口内已就位计划 => rc=5 且原文件未被覆盖",
              rc6 == 5 and "frozen" in _body)
    finally:
        shutil.rmtree(tmp6, ignore_errors=True)
```

**注意两个坑**：

1. `_test_g2_plan_gate.py` 没 import `time`，G6 需要 `import time`。
2. `run_main` 的 `_fake_strftime` 只拦 `"%H%M"`，`time.localtime`/`os.path.getmtime` 走真实时钟——所以 mtime 必须真的拨到当天 09:52，不能靠假时钟。
