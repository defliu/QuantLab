## 一、审计对象与范围

策略一句话：**LightGBM 模型输出次日上涨概率（信号增强），叠加 F1-F6 评分卡过滤（位置/资金/催化/技术/板块/估值），模型分与评分卡加权综合排序，每日换仓持有 Top2，由 QMT 自动执行。**

审计范围覆盖完整链路，目标是找出"纸面回测收益"与"实盘真实收益"之间可能被高估的环节：

| 环节 | 对应代码 | 核心风险 |
|---|---|---|
| 数据与股票池 | `data_config.py`、`build_features_v2.py` | 幸存者偏差、复权口径 |
| 特征与标签 | `build_features_v2.py` | 前视偏差、标签与执行错位 |
| 模型训练与评估 | `train_optuna.py`、`rolling_eval.py` | 泄漏、过拟合、验证集滥用 |
| 选股规则 | `deploy_predict.py`、`review_full.py` | 阈值/权重来源、代理评分失真 |
| 回测验证 | `backtest_dual.py`、`scan_rotate_cost.py` | 成本/滑点/可交易性假设、数据窥探 |
| 实盘执行与结算 | `rebalance_daily.py`、`qmt_trader.py`、`strategy_capital.py` | 成交价偏差、废单、结算口径 |

## 三、策略全貌速览

**数据管线**：主库日线 `E:/astock/daily/stock_daily.parquet`（索引 `(trade_date, ts_code)`），股票池 `D:/QuantLab/data/universe_all_a.csv`（`enabled` 标记），剔除未启用 / ST / 科创板(688) / 北交所(4、8开头)。财务与事件表（业绩预告/快报/分红/股本变动）按公告日 `ann_date` 对齐。

**特征与标签**：35 个特征（20 量价 + 10 财务 + 8 事件，v3 精简为 27）。量价特征全部用 `groupby.shift` 滞后构造；财务/事件特征用 `merge_asof(direction="backward")` 对齐到公告日，防未来函数。标签 `label = (fwd_ret > 0)`，其中 `fwd_ret = T+1收盘/T收盘 - 1`，即"T 收盘建仓、持有 1 日"。

**训练**：LightGBM 二分类，walk-forward 时序切分（train 2020-01-01~2023-06-30 / valid 2023-07-01~2024-06-30 / test 2024-07-01~2026-08-14），OPTUNA 优化目标 = 验证集 IC（Spearman），强正则化（`min_child_samples` 500-2000、`lambda_l2` 可到 2000），精调后 `learning_rate=0.02`。产出模型 `D:/QuantLab/models/lgb_model_v3.txt`。

**选股（双轨）**：模型概率预选池（前 100）→ 评分卡总分 ≥ 58 红线 → 综合分 `0.6×模型概率 + 0.4×(评分卡/100)` 排序 → 取 Top5 候选；评分卡权重 F1 0.25 / F2 0.20 / F3 0.20 / F4 0.15 / F5 0.10 / F6 0.10。F2(资金)/F3(催化)/F5(板块) 是离线代理分，开盘后由 TDX 实时数据复核生成完整版清单。

**执行**：每日 9:45 `rebalance_daily.py --live`，卖"不在目标 Top2 且今日可卖"的持仓（T+1 锁定不卖），买"目标内未持有"的票（等权，预算 = 可用资金 95%）。委托默认 dry-run，加 `--live` 才真实下单。价格风控由六档盯盘负责。

**风控**：大盘风控（沪深300 ≤-1.5% 空仓 / -1.5%~-1.0% 降半仓 / >-1.0% 正常，目标 0/1/2 只）；个股止损 -7% / 止盈 +15% / 移动止盈 8%（高点回撤）。资金池 = 初始 10 万 + 已实现盈亏（FIFO 配对、按实盘费率扣费）+ 策略持仓浮盈。

## 四、审计维度与核查点

### 4.1 数据与股票池

- **幸存者偏差（重点关注）**：`universe_all_a.csv` 是当前时点快照，历史回测直接用该清单过滤，已退市/长期停牌股票被排除。核查：面板 2019-2026 各年份股票数量是否明显缩水，收益统计是否因剔除退市股而虚高。
- **复权口径**：README 标注"后复权前原始价"。核查 `close` 是否含除权影响，`fwd_ret` 在除权日是否会失真，量价特征（动量/均线/RSI/MACD）是否受复权方式影响。
- **财务/事件表完整性**：`fina_indicator` 等表是否有大量缺失或异常值；`ann_date` 是否可信（公告日 vs 报告期）。

### 4.2 特征与标签（前视偏差核心）

- **标签与执行错位（重点关注）**：标签是 T 收盘到 T+1 收盘的收益，实盘却是 T+1 开盘（9:45）买入、次日 9:45 卖出。核查两者口径差（隔夜跳空、开盘滑点）是否会让回测高估。
- **量价特征滞后**：确认所有量价特征都用 `shift(n)`（n≥1）构造，没有用到当日收盘后才可得的信息之外的未来数据。
- **财务特征防未来**：`merge_asof` 按 `ann_date` backward 对齐是否覆盖"财报公布 vs 数据可得"的时滞；财务太旧（>400 天）置缺失是否合理。
- **截面特征**：`rel_mom_20` 用当日全市场动量中位数做截面基准，无前视但会引入市场整体趋势信息，注意其与大盘风控的关系。
- **可交易性未建模**：标签是"次日正收益"，但次日一字涨停买不进、跌停卖不出未在特征或回测中体现。

### 4.3 模型训练与评估

- **切分有效性**：确认时间切分严格 walk-forward，无随机 K 折；`--split-*` 只按 `trade_date` 过滤，检查是否有同一股票跨段泄漏。
- **验证集滥用（重点关注）**：OPTUNA 在验证集上做多轮寻优（`n_trials=20`），验证集实际被反复使用，最优 IC 有正向偏差；真正无偏的是测试集与滚动评估。核查报告中是否清楚区分各段指标。
- **滚动评估严格性**：`rolling_eval.py` 是否真的"只用历史训练、季度外推"；`rolling_eval_report.json` 的 ICIR 1.40、95% 季度正 IC 是否在严格 walk-forward 下得到。
- **正则化**：确认 `min_child_samples`、`lambda_l2` 为强正则设置，`num_leaves` 受 `max_depth` 约束，避免深树过拟合噪声。
- **评估指标**：IC/ICIR/分位收益是否单调；`verdict` 阈值（test IC>0.02 判 PASS）是否过松。

### 4.4 选股规则

- **阈值来源（数据窥探风险）**：评分卡红线从 65 下调到 58 的依据是 `scan_threshold_pool_report.md` 的样本内/样本外扫描。核查 58 是否在测试期上选取，存在"用测试期调参"的过拟合风险。
- **双轨权重**：`0.6/0.4` 权重与 `pool_size`、`top_k` 的取值来源；评分卡 F1-F6 阈值/权重继承自 Project_15，是否与当前模型在同一测试期验证。
- **代理评分失真**：F2/F3/F5 为离线代理（量比/事件/相对动量），与 TDX 实时口径有差异。核查 `review_full.py` 复核后的修正逻辑是否真的作用于最终清单。

### 4.5 回测验证

- **理想化回测（关键）**：`backtest_dual.py` 明确假设"T+1 收盘买入、无成本、无涨跌停限制"，其胜率 54%/盈亏比 1.38/日均超额 0.53% 只能证明信号排序能力，不能代表实盘收益。核查是否有任何人把该指标当作实盘预期。
- **含成本回测**：`scan_rotate_cost.py` 更接近实盘。核查成本模型（佣金万2 双边最低5 / 印花税万5 卖出 / 过户费万0.1 沪市）是否与 `qmt_config.py` 及真实券商一致；滑点敏感性（0/0.1%/0.2%）结论如何。
- **数据窥探（重点关注）**：`scan_*.py` 对持仓数、阈值、池大小等做了大量组合扫描（`scan_topk`/`scan_threshold`/`scan_sortkey`/`scan_newsc` 等），报告里的最优参数是在大搜索空间里挑出的。核查是否存在"用同一段样本反复调参、再拿最优参数当稳健证据"的问题；是否有真正独立的样本外验证。

### 4.6 实盘执行与结算

- **成交价与记录价（重点关注）**：`rebalance_daily.py` 下委托后直接按计划价写 `qmt_trade_log.csv`，而实际成交价（尤其市价卖出、限价买入滑点）可能不同。`strategy_capital.py` 的 FIFO 已实现盈亏用记录价计算。核查记录价 vs 真实成交价的偏差是否会累计扭曲资金池。
- **废单与未成交**：买入用 FIX 限价（当前价），若价格上行可能不成交且无追单/重试逻辑；卖出用市价。核查 9:45 后是否有确认成交、未成交回补的机制。
- **委托量取整**：买入 `vol = int(预算/(价×100))×100`，预算不足一手则跳过；核查等权分配下 2 只票的仓位是否真的均衡。
- **T+1 与已有持仓抵扣**：确认当日买入不可卖（T+1）被正确识别（`can_use_volume`/日志 `_locked_today`）；"买入只补到目标数"是否彻底防止超配（历史上曾超配 37%，见 4.8）。
- **费率真实性**：`qmt_config.py` 佣金万2 双边最低5 元 / 印花税万5 仅卖出 / 过户费万0.1 仅沪市。已与模拟盘成交截图核对一致；核查实盘账户费率是否相同（券商可能不同）。

### 4.7 风控与资金

- **盯盘逻辑**：`qmt_monitor.py` 的止损/止盈/移动止盈基于什么价格（最新价/成本价/最高价），移动止盈的高点如何维护（跨日还是盘中）；非交易时段持仓查询为空时如何回退。
- **大盘风控**：沪深300 当日涨跌的阈值切分逻辑；降半仓时 `rebalance_daily.py --top 1` 的传递是否正确。
- **资金池结算**：FIFO 配对、买入含费成本、卖出净回笼的口径；`price<=0` 的 SELL 被跳过；浮盈查不到按 0 保守计。核查该口径与实盘账户对账（`data/audit_trade_report.md`）。

### 4.8 已知问题与已修复记录（供交叉验证）

最近一次审计 `data/audit_strategy_20260821.md` 记录：

- 仓位超配违规：当日买入 3 只后实际 5 只持仓、总仓约 13 万，超资金池 95% 上限约 37%。已修复：9:45 买入任务新增"已有持仓抵扣"。
- F6 估值口径偏差：评分卡用面板 asof PE，与实时 PE 差异大（朗特 789 / 福莱特 160 仍高分）。已修复：F6 优先用 TDX 实时 PE，PE<0 或 >100 得 1 分。
- 红线 65 过严：样本外回测 17% 空仓天。已下调至 58（0 空仓天、胜率 55%、盈亏比 1.46）。
- T+1 制度性滞后：当日买入当日不可精简卖出，已标记次日处理。

`QMT避坑指南.md` 记录了实盘踩坑：孤儿持仓（`volume=0` 仍显示）、`query_stock_positions` 非交易时段不稳定、`query_stock_trades` 非交易时段阻塞、市价清仓 SELL 价格可能为 0、挂单冻结 `can_use_volume` 等。
