# 研发-生产隔离规范（Research/Production Isolation）

> 目的：研发与定时流程不得覆盖/破坏上线版（V1.x）依赖的基础设施文件，杜绝「研发流程静默写生产文件」类事故。
> 触发事故：2026-08-24 17:20 周更重训定时任务 `train_optuna.py --panel v3` 直接覆盖正式模型 `lgb_model_v3.txt`（1962 树 → 3689 树），且 8/23 研发面板重建覆盖了生产面板（未复权 → 复权）。
> 关联：`VERSIONS.md`（版本登记）、`SERVER_DEPLOY.md`（部署）、`run_scheduled.ps1`（定时任务）。

---

## 一、生产区 vs 研发区（第 2 层 · 目录隔离）

| 区域 | 内容 | 可写方 |
|---|---|---|
| **生产区（只读语义）** | `D:/QuantLab/models/lgb_model_v3.txt`（+ v1/v2 正式模型）<br>`deploy_predict.py`、`qmt_config.py`、`run_scheduled.ps1`<br>`data/feature_panel_v3.parquet`（生产面板，由盘后链路更新） | 仅 `promote_model.py`（模型）/ 盘后链路（面板）/ 人工显式解除只读（脚本） |
| **研发区（可写）** | `D:/QuantLab/models/lgb_model_v3_<tag>*.txt`（候选模型，带后缀，工作池）<br>`data/feature_panel_v3_<tag>.parquet`（实验面板，带后缀）<br>`data/real/`（实验报告）<br>`versions/models/`（模型保留池/备份） | 研发脚本、定时重训 |

**铁律**：
1. 研发脚本（`train_optuna.py`、`build_features*.py`、`scan_*`）**不得写裸生产文件名**（`lgb_model_v3.txt`、`feature_panel_v3.parquet`）。
2. 实验面板/模型一律带 tag：`feature_panel_v3_<tag>.parquet`、`lgb_model_v3_<tag>.txt`。
3. 生产面板 `feature_panel_v3.parquet` 只由盘后链路（`merge_live_features.py` → `deploy_predict.py`）更新。

## 二、代码守卫（第 1 层）

1. **`train_optuna.py` 一律输出候选文件**：`--model-tag` 为空时自动追加 `_cand_YYYYMMDD`；任何分支都不再产生裸名 `lgb_model_v3.txt`。
2. **唯一写生产模型的入口 = `promote_model.py`**：候选 → 校验（特征数/树数/测试集 IC）→ 备份当前正式模型 → 原子替换 → 写只读 → 登记 VERSIONS.md。
3. 研发脚本如需"上线"，只允许：生成候选 → `promote_model.py` 显式提升，禁止直接改正式文件。

## 三、文件级只读保护（第 3 层）

已对以下**静态**生产文件设只读（`attrib +R`），任何写入立即报错（fail-loud）：
- `D:/QuantLab/models/lgb_model_v3.txt`（+ `lgb_model.txt`、`lgb_model_v2.txt`）
- `deploy_predict.py`、`qmt_config.py`、`run_scheduled.ps1`

**解除只读（仅人工确认后）**：
```powershell
attrib -R "D:/QuantLab/models/lgb_model_v3.txt"
attrib -R "<项目>\deploy_predict.py"
```
> 注：生产面板 `feature_panel_v3.parquet` **不设只读**（盘后链路每日追加数据），其保护靠第 2 层归属权约束。

## 四、版本与上线门禁（第 4 层）

1. **候选不占正式版本号**：未上线模型记 `V<x>.<y>-候选`（如 `V2.0-候选`），上线当天才正式占号。
2. **定时重训只产候选**：`run_scheduled.ps1 -Mode retrain` 重训前备份正式模型到 `versions/models/lgb_model_v3_pre_retrain_<stamp>.txt`，输出 `lgb_model_v3_retrain_YYYYMMDD.txt` 候选文件，**不自动上线**。
3. **上线流程**（必经步骤）：
   1. 生成候选模型（`train_optuna.py --panel v3 --model-tag <tag>`）
   2. `promote_model.py --model-file <候选路径> --suffix v3` 校验并提升
   3. 校验项：特征数一致（对照 `features_v3.json`）、树数>0、测试集 IC 报告存在
   4. 提升后自动：备份旧正式模型 → 替换 → 写只读 → 追加 VERSIONS.md 记录
4. **上线前自查清单**：
   - [ ] 候选模型训练日志/参数存在（`data/optuna_report.json` 或报告）
   - [ ] 特征数 = 27（v3 面板）一致
   - [ ] 候选在可执行口径回测 ≥ 阈值（如有门槛）
   - [ ] 生产面板与候选模型口径一致（同未复权/同复权）
   - [ ] `deploy_predict.py --model v3 --date <最新交易日>` 试跑通过
