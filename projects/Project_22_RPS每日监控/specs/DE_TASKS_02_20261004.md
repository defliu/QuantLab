## 二、任务 1：修复 verify_rps.py（必做）

### 2.1 崩溃根因（已由主助手定位，不要重新排查）

`pyarrow.parquet.read_table(...).to_pandas()` 在本机 pandas 3.0.5 / pyarrow 25.0.1 环境下，
会把 `trade_date + ts_code` 恢复成 **Pandas MultiIndex**，导致这两列从 `df.columns` 消失，
后续 `df.sort_values("trade_date")` / `base["trade_date"]` 抛 `KeyError: 'trade_date'`。

实测报错（主助手已复现）：
```
File "verify_rps.py", line 77, in check_ret20
    ok = diff < 1e-6 and base["trade_date"] <= target
KeyError: 'trade_date'
```

### 2.2 修复方式（照抄，不要自行发挥）

在你**每一个** `pq.read_table(...).to_pandas()` 之后，立刻插入：

```python
df = df.reset_index() if isinstance(df.index, pd.MultiIndex) else df
```

`verify_rps.py` 中以下位置全部需要处理（请自行 grep 确认无遗漏）：
- `load_local_calendar()` —— 读的是 `trade_date` 单列，用 `tbl.column(...).to_pandas()`，当前侥幸可用，但仍建议统一防御
- `check_ret20()` 内的 `rows = pq.read_table(...).to_pandas()` —— **崩溃点，必修**
- `_adj_at_or_before()` 内的 `rows = pq.read_table(...).to_pandas()` —— **必同样处理，否则修完崩溃点会在下一行再崩**
- `check_pit()` 内的 `scan = pq.read_table(...).to_pandas()` 和 `pre = pq.read_table(...).to_pandas()` —— 同样必处理

### 2.3 顺手修掉的一个真实逻辑 bug（必做）

`check_ret20()` 里基准日的取法是错的：
```python
target = cal[-21]                      # T 前 20 个交易日
rows = pq.read_table(..., filters=[..., ("trade_date", "<=", target)])
base = rows.iloc[-1]                    # 取的是 <= target 的最后一行，不是 target 当天
```
当股票在 `target` 当天停牌时，`base` 会静默退化成更早的交易日，`ret_manual` 口径随之偏移。

**注意：主程序 `rps_daily.py` 用的是 `piv.ffill()`（前收盘价口径），是正确的。
验证脚本要复现同一口径**，请改为：按 `trade_date` 升序排序后，
用 `series.ffill()` 取 `target` 当天的前收盘价，与主程序对齐。

同时保留"停牌股"的显式判定与打印（把停牌股单列出来说明口径），不要静默。

### 2.4 ffill 口径必须与主程序一致（重要，否则误报 FAIL）

`rps_daily.py` 对复权价格做了 `ffill()`，所以停牌股在池内也有有效 RPS。
验证脚本若不做同样的 ffill，会把停牌股算成 NaN，导致误报不一致。
**请在验证脚本里复现 ffill**，否则 check 1 会误判。
