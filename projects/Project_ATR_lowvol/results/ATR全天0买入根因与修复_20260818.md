## 二、根因（代码实证 + 复现）

`_run_screening` 换手率处理有 **3 个叠加 bug**，任何一个都会把候选杀到 0；实际三者同框：

### Bug1：无条件 `×100`（单位错误）— 旧代码
```python
# 旧 build（等权版）~L725/738
if 'turnover_rate' in df.columns:
    s = df['turnover_rate'].dropna()
    if len(s) > 0:
        turnover_map[code] = float(s.iloc[-1]) * 100.0   # 无条件 ×100
```
- 国金 QMT `get_turnover_rate`/行情列返回**百分比**（如 `2.5` 表示 2.5%），`2.5 × 100 = 250 > _MAX_TURNOVER(8)` → **全市场被换手过滤杀光**。
- 对照：`src/strategy_atr.py:316` `_scale_turnover` 是**尺度自适应**（`raw < 1.0 才 ×100，≥1 视为已是百分比`），等权 build 未同步该逻辑。
- 佐证：`src/strategy_atr.py:326` 注释明言「提取单只股票最新换手率（百分比，如 2.5=2.5%）」，即 API 返回百分比。

### Bug2：fail-open 语义反了（缺数据杀票）— 旧代码
```python
if _g_turnover_available:
    to = turnover_map.get(code, -1.0)
    if to < 0:
        continue          # 该票无换手数据 -> 直接淘汰（本应 fail-open 放行）
    if to < _MIN_TURNOVER or to > _MAX_TURNOVER:
        continue
```
- 违反 AGENTS「取不到放行，绝不让换手率把股票误杀」。对照 src：`if turnover_rate is not None:` 才过滤（缺数据跳过该票）。

### Bug3：`_g_turnover_available=True` 默认 + 数据全空 → 空 map 全杀
- `_g_turnover_available` 默认 `True`（build L79）。若列不存在且 `get_turnover_rate` 返回 `None`（不抛异常）→ `turnover_map` 空、flag 仍 `True` → 每只票 `to = -1 < 0 → continue` → **0 候选，与数据质量无关**。
- 旧代码只在 `get_turnover_rate` **抛异常**时才置 `False`。

### 复现实锤（astock 全市场，数据至 2026-08-14，`E:/astock/daily/stock_daily.parquet`）
| 场景 | 候选数 | 入选 |
|---|---|---|
| A：换手列缺失/fail-open（本地 08-14 审计实际路径） | 833 | 100 |
| B：换手存在、值为百分比、不 ×100（正确口径） | 618 | 100 |
| C：换手存在、值为百分比、×100（**旧 bug 路径**） | **2** | 2 |

→ 只有场景 C 复现「近零候选」，与线上 0 一致。

### 对照：为什么 08-14 本地审计能选出 8 只？
本地审计 `src/_atr_ew_local_test.py` 把 `get_turnover_rate` mock 成**抛 AttributeError** → 触发旧代码的 `except AttributeError: _g_turnover_available = False` → 换手过滤被整体跳过 → 才选出 8 只（审计报告 line 152/158）。线上真实 API 存在且返回百分比 → Bug1 生效 → 0。

## 三、修复内容

### Fix1（build `20260818-225254`，commit `7352cd2`，已部署）
1. **新增 `_scale_turnover(raw)`**（build L223，对齐 src）：`raw < 1.0 → ×100；≥1 → 视为已是百分比`；非数值/None → 返回 None。
2. **turnover_map 构建重写**（L746-776）：
   - 列路径与 API 路径均经 `_scale_turnover`；
   - API 调用加 `hasattr(C, 'get_turnover_rate')` 能力探测（不依赖抛异常）；

3. **个股级 fail-open**（L829）：`to = turnover_map.get(code)`；`to is not None` 才判 [1,8]，缺数据跳过该票过滤。
4. **筛选过滤明细日志**（L891）：`长度<252/价<=0/ATR平填/ATR>=6%/换手/ST/动量/异常` 各自淘汰数，下次部署一眼定位。
5. **对账调用修复**（L335）：`C.get_trade_detail_data`（远程无此方法）改为**全局 `get_trade_detail_data`**（V2 同款，已实证远程可用），fallback `getattr(C, ...)`，都没有则打印跳过不崩。

### 关键发现：src/strategy_atr.py 的 passorder 参数颠倒

src L677 卖出旧代码：
```python
C.passorder(24, 1101, acct, code, 5, -1, price, code, 1)
#                             pos6=-1   pos7=price ← BUG! 应为股数shares
```
src L777 买入旧代码：
```python

#                             pos6=max_shares  pos7=price ← BUG! 参数6/7全反
```

**这是防坑指南坑1的精确复现**：「把第 6 位传成股数、第 7 位传成价格 → QMT 收到非法委托必废单」。

# 买入：pos6=modelprice(-1), pos7=max_shares(股数)
passorder(23, 1101, _ACCOUNT_ID, code, 5, -1, max_shares, 'ATR_EW', 2, '', C)

### 影响评估

- **src 的 passorder 参数颠倒**：本地测试不经过 QMT 下单（mock），不会暴露；远程部署用的是 build 而非 src，build 的 11 参数格式顺序恰好正确（pos6=price, pos7=shares），所以线上没踩到。但 src 作为逻辑参考源，必须修正。
- **build 的 `_lookup_order` 用 C.method**：线上 QMT `__PyContext` 对象确实有 `get_trade_detail_data` 属性，所以 `C.get_trade_detail_data()` 碰巧能跑；但 AGENTS 红线 + V2 范式都要求用全局函数，未来 QMT 版本可能移除 C 上的属性。

### 根因

**Bug4a：10万/100只=1000元/只，买不起1手（核心问题）**

`_execute_buys_equalweight` 计算：
- `nav = 100000`, `n_target = 100`, `target_value = 1000元/只`
- `desired = int(1000 / price / 100) * 100` — 这些大盘股(601985/600023等)价格普遍>10元
- `int(1000/15/100) = 0` → **delta=0，全部 continue 跳过**
- 10万资金买100只等权，每只仅1000元，A股1手=100股×价格，绝大部分股票1手>1000元

**Bug4b：再平衡死循环**

- 买入0只 → `_g_my_codes` 为空
- `_g_last_rebalance_key` 不更新（原逻辑要求 `_g_my_codes` 非空才刷新）
- `force_retry = (len(_g_my_codes)==0) and (_g_last_attempt_date != today_y)` — 每bar都满足
- → 每个心跳(3秒)重新选股+买入+跳过+循环

**Bug4c：`C.get_account_info()` 不存在**

QMT `__PyContext` 无此方法，fallback 返回 `1e18`（不设上限），日志每bar刷屏。虽非根因但干扰排查。

### 修复

| # | 修复 | 内容 |
|---|---|---|
| 4a | **仓位自动缩减** | 资金不足均分N_HOLD只时，按最低价排序，算出最多能买几只（每只至少1手100股），截取前N只买入。例如10万只能买8只（每只约1.2万/1手），就只买8只 |
| 4b | **死循环修复** | 选股成功即刷新 `_g_last_rebalance_key`，不再要求持仓非空才刷新；`force_retry` 每天只触发一次（`_g_last_attempt_date` 已控制） |
| 4c | **账户现金查询** | 三级 fallback：① `C.get_account_info()` → ② `get_trade_detail_data(acct,'stock','account')` 查 `m_dAvailable`/`m_dCash` → ③ `C.get_cash()` 查 `m_dAvailable` → 全失败才 fallback `1e18` |

### 数值验证

10万资金 / N_HOLD=100：
- `target_value = 1000元/只`
- 最低价候选股约10元 → 1手=1000元，刚好；>10元全买不起

修复后（仓位缩减逻辑）：
- 按最低价排序，逐只扣除1手成本，直到资金用完
- 预计能买8-12只（取决于具体股票价格）
- 每只约 `100000 / 8 = 12500元` → `int(12500/price/100)*100` 手数合理
