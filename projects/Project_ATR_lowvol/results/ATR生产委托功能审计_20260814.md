## 一、结论（先看这里）

**ATR 等权版的隔离设计整体是对的（比 V2 干净），但有两个生产级缺口需要补，否则双策略同时跑有真实的资金/股票串扰风险：**

1. **缺 `is_last_bar` 守卫 + 缺撤单机制**（V2 都已有）→ 历史K线回放可能触发真实下单；挂单无撤销手段
2. **卖出确认失败即删 ledger → 制造孤儿仓位**（停牌/部分成交场景，2026-06-29/30 回测已见全停牌）→ 与 V2 当年 5 只孤儿股同款

3. **跨策略最大风险点在 V2 侧**：V2 买入对账"账户持仓兜底"在"重叠票 + deal 漏记"时会把整只票的账户持仓（含 ATR 份额）记进 V2 ledger，V2 后续卖出会多卖 ATR 的票。两个策略同时跑前**必须评估重叠票概率 + 收紧 V2 兜底口径**。

## 二、隔离机制核查（逐项 PASS/FAIL）

| 隔离维度 | ATR 现状 | 判定 |
|---|---|---|
| **状态文件分离** | ledger=`atr_ew_holdings.json` / nav=`atr_ew_nav.json` / 日志=`atr_ew_trade_log.csv`；V2=`v2_holdings_state.json` | ✅ 无碰撞 |
| **选股/持仓互不接管** | `_reconcile_own_holdings` 只移除"本策略 ledger 里账户已不存在"的票，绝不接管账户其他持仓 | ✅ |
| **卖票只卖自己的量** | `_execute_sells`/`_partial_sell` 均按 `_g_my_codes[code]['shares']`（本策略记录量）下单，**从未用 -1（全部）** | ✅ 核心隔离成立 |
| **资金不越额度** | `spendable = min(virtual_cash, acct_cash)`，`virtual_cash = max(持仓市值,10万) - 持仓市值`（本策略滚动 NAV 预算） | ✅ 不会花掉 V2 的额度 |
| **共享现金只作上限** | `acct_cash` 仅当硬上限用，取不到则降级为 1e18（只靠虚拟额度） | ✅ 安全 |
| **对账频率** | reconcile 只在 `init()` 跑一次（非每 bar），避免 V2"每 bar 对账清场"灾难 | ✅ 设计优于 V2 旧版 |
| **非调仓日** | 非调仓日只做间际止损卖出，不建仓（无 V2"非调仓日建仓 67 只"问题） | ✅ |
| **重复下单防护** | 调仓成功即写 `_g_last_rebalance_key`；买入乐观写 ledger 使 delta=0；空仓兜底限每日一次 | ✅ 常规路径无重复 |
| **T+1 卖可用量** | 未显式校验卖出量 vs 可用量（当日买入次日才可卖） | ⚠️ 边缘场景 |
| **成交归属识别** | 9 参 passorder 的 strategyName 传的是**股票代码**（非 "ATR"），交易无策略标识；V2 对账按 remark 含 "V2" 过滤 → ATR 成交不会被算进 V2 资金池 | ⚠️ 对隔离无害，但 ATR 自己无法按 remark 反查归属 |

## 四、风险清单（按严重度）

### R1（高）V2 买入对账"账户持仓兜底"会越权接管 ATR 的票
- **场景**: ATR 与 V2 同时持有股票 X（重叠票）→ V2 当日对 X 下买单 → V2 的 deal 反查为空（模拟端漏记 remark/时序）→ `_get_acct_position` 兜底读到账户 X 的**全部持仓**（含 ATR 份额）→ 记入 V2 ledger → V2 后续卖出按此量下单 → **多卖 ATR 的票**。
- **触发条件**: 重叠票 + V2 当日买 X + deal 漏记。窄但真实。
- **位置**: `strategy_v2.py` `_reconcile()` 买入分支账户持仓兜底（T-20260814-002 修复引入）。
- **建议**: (a) 兜底改为 `min(acct_vol, 当日下单量)` 或按当日 V2 估算买入量封顶；(b) 或兜底仅恢复"V2 记录中曾有、账户仍持有"的量，不取整只票。

### R2（高）ATR 无 `is_last_bar` 守卫（V2/src 已有）
- QMT handlebar 对历史 K 线回放也会回调；ATR `_main_loop` 只有 weekday 判断 + init 后 60s cooling，**没有 `is_last_bar()` 守卫**。启动回放时间跨过 60s 冷却窗口时，可能基于历史 bar 触发再平衡/真实下单。
- src 尾盘版有 `if not C.is_last_bar(): return`，等权 build 漏了。
- **建议**: handlebar 入口加 `if not C.is_last_bar(): return`（对齐 src 版）。

### R3（高）ATR 无撤单机制
- 挂单无法撤销。prType=5（对手价）一般立即成交，但停牌/涨跌停/价格偏离时会挂单滞留到收盘。
- V2 有完整撤单函数（17 处引用）。
- **建议**: 补 `_cancel_order`（对齐 V2：`passorder(24,1101,acct,code,5,order_id,0,...,2,"",C)`），买入确认失败且订单仍挂时撤单。

### R4（高）卖出确认失败即删 ledger → 孤儿仓位
- `_execute_sells`/`_partial_sell` 在 `_lookup_order` 失败时**立即 `del _g_my_codes[code]`**（乐观）+ 登记 pending；pending 30s 超时后"放弃"且 ledger 已删。
- 若卖出真实失败（停牌整日 / 部分成交），账户仍持有该票，但 ATR ledger 已无 → **孤儿仓位**，与 V2 当年 5 只孤儿同款；且 ATR reconcile 是单向移除，**不会把孤儿接回来**（只能手动清理）。
- 回测已见 2026-06-29/30 五只持仓全停牌，真实盘必然触发。
- **建议**: 卖出确认失败时**不删 ledger**（保留持仓，等下一调仓日重试卖出），pending 超时也保留 ledger；或对账改为"账户有货则保留 ledger"。

### R5（中）reconcile 只校存在、不校份额数
- ATR ledger 声称 1000 股、账户实际 500（外部部分卖出/历史偏差）时，reconcile 不校正；后续卖出 1000 → 账户只有 500 → 部分成交 → `_lookup_order` 10% 量差判负 → pending → 走 R4 的删 ledger → 500 孤儿。
- **建议**: reconcile 对 ATR ledger 内每只票，若账户有货则把份额数校准为 `min(ledger, acct)`（保守向下取，防多卖）。

### R6（中）资金预算对 V2 并发支出无感知
- `spendable` 计算时 `acct_cash` 读一次；若 V2 同秒消费账户现金，ATR 的下单可能因账户现金不足被 QMT 拒 → 走乐观写 ledger → 幻影持仓（ledger 有、账户无）。
- 当前账户 1000 万虚拟、闲置 980 万，实际不太会触发；但"幻影持仓"路径（买入被拒仍写 ledger + 设 `_g_last_rebalance_key` 不再重试）是真实的账实不符源。
- **建议**: 买入时若 passorder 返回明确失败（非 0），不要写 ledger；或买入前再查一次账户可用现金。

### R7（低）策略标识缺失
- ATR passorder strategyName 传股票代码；多策略共账时日志/成交无法按策略归类（V2 靠 remark="V2" 过滤，ATR 成交恰好不含 "V2" 所以不会被误算，但 ATR 自己无法反查）。
- **建议**: strategyName 统一改 "ATR_EW"，与 V2 的 remark 过滤机制对齐，可互相识别。

### R8（低）9 参 vs 11 参 passorder 混用
- ATR 用 9 参（无 userOrderId/C），V2 用 11 参。若将来需要按 userOrderId 撤单/对账，ATR 没有该 ID。
- **建议**: 统一为 11 参带 userOrderId（如 "ATR_<ts>"），便于精确撤单与成交归属。

**两个本地环境发现（非策略 bug，但值得记录）：**

1. **本地 miniQMT 日线数据退化**：大量股票最近约 25 根 K 线为同价平填（high==low==close，如 600000 最后 25 根全 8.76）→ 近 14 日 ATR%=0 → 被策略 `atr_pct<=0` 正确淘汰。**本地选出的 8 只只是数据可用的那批，不等于生产真实选股**；真实选股须在 QMT 模拟盘（数据完整）确认。
2. **ROE 空结果 = 过滤全部（潜在设计点）**：`_batch_get_roe` 调用成功但返回空 dict 时不抛异常，`_g_roe_api_ok` 保持 None → `_run_screening` 走"按 roe_map 过滤"，全部 `roe is None` → 0 只。生产 QMT 有真实财务数据不触发；但若接口空转，策略会整季空仓。与策略"接口不可用即 fail-open"的既有哲学不一致，**建议后续把"空结果"也当 fail-open（R9 候选，需拍板）**。
3. **注意**：本地入选的 `000809 和展能源` 恰是 V2 当年 5 只孤儿股之一（000809/600248/601668/603187/603797）——两策略存在真实重叠票可能，R1 封顶修复的必要性再次被验证。
