## 一、P0 编码腐蚀：完全认账，我的错

GLM审计指出的 4168 个 `?` 腐蚀，我已实证确认：

| 行 | 当前（腐蚀） | 应为 | 后果 |
|---|---|---|---|
| L779 | `'????A??'` | `'沪深A股'` | 取不到宇宙→0候选→永久0买入 |
| L836 | `'????????'` | `'风险警示板'` | ST过滤静默失效 |
| L394 | `'????'`/`'????'` | `'买入'`/`'卖出'` | 订单反查方向永不匹配→买入全进pending→30s丢弃→重复建仓 |

**根因**：我的编辑流程有致命缺陷——

1. 先用 `edit` 工具写入含中文的新代码（UTF-8编码）
2. 然后用 PowerShell `[Encoding]::UTF8.GetString(gbk_bytes)` → `[Encoding]::GBK.GetBytes(utf8_text)` 转码
3. 第1步：edit 工具把 GBK 文件当 UTF-8 读入，**旧中文全部解码为 U+FFFD（替换字符）**，变成 `?`
4. 第2步：`?` 是合法 ASCII，GBK 转码不会报错，腐蚀被"合法"写入
5. 我的验证只查了 `# coding=gbk` 头、Python 语法、无MOCK，**没查关键中文字符串是否完整**

**教训**：GBK 文件不能用 `edit` 工具直接编辑。正确做法是：先以 GBK 解码读出原文，在原文基础上做替换，再以 GBK 编码写回。或者：从 git 取 044755 原版，仅重放 Fix4 的逻辑改动。

**补救**：必须从 `849e08d`（044755）版本重放 Fix4 改动，而非在腐蚀版上修补。重放后：
- R9 单测 2/2 PASS
- 关键字符串断言（`'沪深A股' in txt`, `'风险警示板' in txt`, `'买入' in txt`）
- `txt.count('?') < 10` 总量闸

## 三、Fix4a 数值声称不成立：认账

我用 n_hold=8 的心智模型算出"10万/8只≈1.25万/只，预计买8-12只"，但远程实际跑的是 n_hold=100。

**n_hold=100 下 Fix4a 的真实行为**：
- 100只候选价分布：min 1.58 / 中位 10.00 / max 47.12
- 100只1手成本合计 124,222 > 100,000 → 截断触发，affordable_n≈93
- 但 100000/93≈1075元/只，>10.75元的股票仍买不起1手
- 实际只会买 ~50只低价股各1手（动用3-4万），其余资金闲置

**不是"集中8只每只1.25万"，是"散买50只各1手、大量资金闲置"。** 我的报告声称错误。

## 四、Fix4a 设计本身的问题

GLM没有展开这一点，但我自己反思认为 **Fix4a 的截取逻辑有设计缺陷**：

1. **按最低价排序截取** → 截出来的是"最便宜的N只"，不是"ATR%最低的N只"。ATR策略的核心选股逻辑是ATR%排序，缩减后持仓偏离策略意图。
2. **正确的做法**应该是：先按ATR%排序选top-K，然后只买资金够1手的票。不够的跳过、不缩减总数——让持仓数量自然少于N_HOLD，而非改变选股排序。
3. 更根本的方案是 **Fix4e（同步远程n_hold=8配置）**，n_hold=8时10万/8只≈1.25万/只，绝大部分低波股1手<1.25万，缩减逻辑不触发。

**建议**：Fix4a 改为"买得起就买、买不起就跳过"而非"重新排序截取"，让实际持仓数自然少于N_HOLD。

## 七、自省

这次Fix4的实施暴露了我在GBK文件编辑流程上的系统性缺陷：

1. **edit工具不适合GBK文件**：edit工具内部以UTF-8处理，GBK中文在读写间必被腐蚀。这不是偶发事故，是流程bug——只要对GBK文件用edit，每次都会腐蚀旧中文。
2. **验证矩阵缺失关键项**：我验证了语法/编码头/MOCK/Python36兼容性，但**没有验证中文字符串完整性**。对QMT策略文件，板块名/方向名是功能性字符串，应作为断言项。
3. **"已部署"声明草率**：复制到本机E:盘不等于部署到线上。以后声称部署必须附远程日志实证。
4. **数值推演脱离实际口径**：用本地n_hold=8算数，远程跑n_hold=100，数值声称必然不成立。应先确认线上口径再推演。

**根因**：我对QMT策略文件的特殊性（GBK+中文功能性字符串）认知不足，用了通用文本编辑流程，没有针对性的编码保护和验证。
