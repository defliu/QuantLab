## 二、根因分析

### Bug4a：10万/100只=1000元/只，买不起1手（**核心P0**）

**代码路径**：`_execute_buys_equalweight` → 等权计算 → delta=0 → 全部跳过

```
nav = max(holdings_value, _STRATEGY_CAPITAL) = 100000
n_target = 100
target_value = 100000 / 100 = 1000元/只

对每只候选股：
  desired = int(target_value / price / 100) * 100
  
  例：601985.SH 价格≈8.5元
    desired = int(1000 / 8.5 / 100) * 100 = int(1.17) * 100 = 1 * 100 = 100股 ✓
  例：600030.SH 价格≈18元
    desired = int(1000 / 18 / 100) * 100 = int(0.55) * 100 = 0 → delta=0 → continue跳过
```

**100只候选中**：仅极少数<10元低价股能买到100股，>10元全部跳过。ATR低波选出的恰是大盘股（电力/银行/公用事业），价格普遍10-25元。

**本质矛盾**：10万资金 × 等权100只 = 每只1000元，A股最小交易单位1手=100股，大部分股票1手>1000元。

### Bug4b：再平衡死循环（**P0**）

**代码路径**：`_main_loop` → `force_retry` 逻辑

```python
# 原逻辑
if selected:
    _rebalance_to_target(C, selected)
    if _g_my_codes:                    # ← 问题：持仓为空就不刷新
        _g_last_rebalance_key = key
_g_last_attempt_date = today_y

# 下一个bar
force_retry = (len(_g_my_codes) == 0) and (_g_last_attempt_date != today_y)
#            ↑ 仍然为空        ↑ 同一天today_y==today_y → False...
```

**等等**—— `_g_last_attempt_date = today_y` 在同一天内应该阻止循环？让我重新检查：

```python
today_y = now.strftime('%Y%m%d')  # e.g. "20260819"
force_retry = (len(_g_my_codes) == 0) and (_g_last_attempt_date != today_y)
```

- 第一次执行：`_g_last_attempt_date=""` → `force_retry=True` → 执行后 `_g_last_attempt_date="20260819"`
- 第二次执行（同一bar或3秒后）：`_g_last_attempt_date="20260819" == today_y` → `force_retry=False`

但日志显示**每3秒都在执行再平衡**，且 `is_rebalance_day=True`（因为 `_g_last_rebalance_key` 不刷新）！

```python
is_rebalance_day = (key != _g_last_rebalance_key)
# key = "2026Q3", _g_last_rebalance_key = "" (初始值)
# → is_rebalance_day = True → 每个bar都进入再平衡分支
```

**死循环路径**：
1. `is_rebalance_day=True` → 进入再平衡 → 选股缓存命中 → 再平衡完成0持仓
2. `_g_my_codes为空` → `_g_last_rebalance_key` 不刷新
3. 下一bar `is_rebalance_day` 仍为True → 重复1

`_g_last_attempt_date` 只控制 `force_retry`，不控制 `is_rebalance_day`。

### Bug4c：`C.get_account_info()` 不存在（**P2**，非根因但干扰排查）

QMT `__PyContext` 无 `get_account_info` 方法，fallback 返回 `1e18`。这意味着：
- `spendable = min(virtual_cash, 1e18) = virtual_cash`（策略虚拟现金）
- R6 检查 `_acct_cash_now = 1e18` 永远不拦截
- 日志每bar刷屏"取账户现金失败"

**不影响Bug4a**（即使返回真实现金≈百万，10万/100只=1000元/只仍然买不起），但多策略共存时可能超额占用资金。

### Bug4d（遗留）：对账 `CPositionDetail` 的 `.get()` 属性（**P1**）

08-18 Fix2已修对账字段访问（`m_strInstrumentID`），但日志仍报 `'CPositionDetail' object has no attribute 'get'`。说明Fix2版(build `20260819-000525`)未成功部署到远程，当前跑的仍是 `20260819-044755`（Fix3版）。本次Fix4会一并覆盖。

## 三、修复方案

### Fix4a：仓位自动缩减（_execute_buys_equalweight）

**思路**：当资金不足以均分 N_HOLD 只时，按最低1手成本排序，截取可买数量

**修改位置**：`_execute_buys_equalweight` 函数，在等权计算前新增缩减逻辑

**伪代码**：
```python
def _execute_buys_equalweight(C, target_codes, prices):
    # ... 计算 nav, target_value, spendable ...
    
    # 新增：资金不足时自动缩减持仓数
    min_lot_costs = []
    for code in target_codes:
        p = prices.get(code, 0)
        if p and p > 0:
            min_lot_costs.append((code, p * 100))  # 1手成本
    min_lot_costs.sort(key=lambda x: x[1])          # 按成本升序
    
    affordable_n = 0
    remaining_cash = spendable
    for code, lot_cost in min_lot_costs:
        if lot_cost <= remaining_cash:
            remaining_cash -= lot_cost
            affordable_n += 1
        else:
            break
    
    if affordable_n < n_target:
        affordable_codes = [c for c, _ in min_lot_costs[:affordable_n]]
        print("[ATR_EW 仓位缩减] 资金%.0f仅够买%d只(原目标%d只), 截取最低价%d只"
              % (spendable, affordable_n, n_target, affordable_n))
        target_codes = affordable_codes
        n_target = max(len(target_codes), 1)
        target_value = nav / n_target
        spendable = min(virtual_cash, acct_cash)
    
    # ... 原有等权买入逻辑 ...
```

**风险评估**：
- ⚠️ **截取"最低价"而非"ATR%最低"**：缩减后持仓是候选中价格最低的N只，不是ATR%最低的N只。在n_hold=100→8的场景下，选出的8只可能偏离策略原意。
- ✅ 但在n_hold=8的正常场景下，10万/8只≈1.25万/只，大部分低波股1手<1.25万，缩减逻辑不触发或极少触发。
- 建议配合Fix4e同步远程配置，确保n_hold=8。

**替代方案**（未采纳）：不改买入逻辑，只修远程配置n_hold=8。但这样如果将来资金更少（如5万）且n_hold=8，仍可能出现买不起1手的情况，缺少防护。

### Fix4b：再平衡死循环（_main_loop）

**思路**：选股成功即刷新季度键，不要求持仓非空

**修改位置**：`_main_loop` 函数中的再平衡后处理

**伪代码**：
```python
if is_rebalance_day or force_retry:
    selected = _run_screening(C)
    if selected:
        _rebalance_to_target(C, selected)
    else:
        print("[ATR_EW] 选股无候选，跳过再平衡")
    # 修改：选股成功即刷新季度键，不再要求持仓非空
    if selected:
        _g_last_rebalance_key = key
    _g_last_attempt_date = today_y
```

**风险评估**：
- ✅ 季度键刷新后，同一季度内不再重复选股（仅靠 `force_retry` 每天1次空仓兜底）
- ⚠️ 如果选股成功但0成交（如Fix4a修复前），季度键已刷新，本季度不再重试。需靠 `force_retry` 机制在次日再次尝试。
- `force_retry = (len(_g_my_codes)==0) and (_g_last_attempt_date != today_y)` → 空仓时每天会再试1次，合理。

### Fix4c：账户现金查询三级fallback（_get_account_cash）

**思路**：`C.get_account_info()` 不可用时，依次尝试 `get_trade_detail_data('account')` 和 `C.get_cash()`

**修改位置**：`_get_account_cash` 函数

**伪代码**：
```python
def _get_account_cash(C):
    # 方法1: C.get_account_info() (QMT模拟端无此接口)
    try:
        info = C.get_account_info()
        # ... 原有逻辑 ...
    except Exception:
        pass
    
    # 方法2: get_trade_detail_data 查账户资金
    try:
        f_get = globals().get('get_trade_detail_data') or getattr(C, 'get_trade_detail_data', None)
        if f_get:
            accts = f_get(_ACCOUNT_ID, 'stock', 'account')
            if accts:
                for a in accts:
                    avail = getattr(a, 'm_dAvailable', None)
                    if avail is not None:
                        return float(avail)
                    avail = getattr(a, 'm_dCash', None)
                    if avail is not None:
                        return float(avail)
    except Exception:
        pass
    
    # 方法3: C.get_cash()
    try:
        c = C.get_cash()
        if isinstance(c, dict):
            avail = c.get('m_dAvailable', c.get('available', None))
            if avail is not None:
                return float(avail)
        elif c is not None:
            return float(c)
    except Exception:
        pass
    
    print("[ATR_EW] 取账户现金全部失败(降级:不设上限): 无可用接口")
    return 1e18
```

**风险评估**：
- ⚠️ `get_trade_detail_data(acct, 'stock', 'account')` 的字段名 `m_dAvailable`/`m_dCash` 需要在QMT模拟端实证。如果字段名不同，会走fallback到方法3或最终1e18。
- ✅ 1e18 fallback 保证不卡死（降级为不限资金），策略虚拟预算(_STRATEGY_CAPITAL=10万)仍然约束总仓位。

## 六、遗留与风险

1. **仓位缩减选股偏移**：n_hold=100→8时，缩减后是"最低价8只"而非"ATR%最低8只"。建议同步Fix4e后n_hold=8，缩减逻辑仅在极端情况触发。
2. **`get_trade_detail_data('account')` 字段未实证**：`m_dAvailable`/`m_dCash` 是基于QMT文档推测，需下次部署后从日志确认。
3. **`is_last_bar()` 效用不明**：日志显示策略每3秒执行（QMT 3秒K线），`is_last_bar()` 在实盘模式下要么不存在要么返回False，导致每bar都执行 `_main_loop`。Fix4b通过季度键刷新已控制频率，但非交易时段仍在空跑（只有心跳日志，计算量小可接受）。
4. **Fail-open叠加**：08-19日志中换手率/ST/ROE三个门控全部fail-open，意味着选股实质上只靠ATR%+价格+动量三重过滤。远程QMT数据环境需改善。
