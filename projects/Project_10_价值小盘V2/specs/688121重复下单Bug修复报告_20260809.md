# 688121重复下单Bug修复报告

> **日期**: 2026-08-09
> **策略**: 价值小盘V2 (`strategy_v2.py`)
> **账号**: 67014907
> **严重度**: P0（实盘资金风险）

---

## 1. 事故现象

2026-08-06模拟盘首跑，688121.SH 出现10次重复卖出委托：

```
11:19  止损触发 → 下卖单(100股)
11:19~14:50  卖单未成交（流动性差）
14:50后  _reconcile每bar执行 → 恢复持仓 + 清空_pending_orders
下tick  止损再次触发 → 再次下卖单
... 循环10次
```

**连锁后果**：
- 持仓数跳变 67→2→69（_save_state写了估算态，QMT重启读到中间态）
- 非调仓日建仓67只（_reconcile恢复的"孤儿持仓"被当成真实持仓）
- 688121重复下单10次
- 额度冲突疑问（估算态与实际账户不一致）

---

## 2. 根因分析

### 根因A：`_reconcile` 每bar重复执行

**位置**: `strategy_v2.py:732` (修复前)

```python
# 修复前：14:50后每个bar都跑reconcile
if current_hour == 14 and current_minute >= 50:
    _reconcile(C)
```

tick级bar下（1秒1bar），14:50~15:00约600个bar，`_reconcile`每秒执行一次。

**_reconcile的两件破坏性操作**：
1. **恢复未成交卖单持仓**（818-823行）：卖单未成交 → 把持仓加回 `_holdings`
2. **清空 `_pending_orders`**（826行）：所有在途订单记录归零

→ 恢复持仓 + 清空在途 = 下一个tick止损再次触发时，既查到持仓又没有在途守卫。

### 根因B：`_execute_sell` 无在途单守卫

**位置**: `strategy_v2.py:885` (修复前)

```python
def _execute_sell(C, code):
    # 修复前：只查 _holdings，不查 _pending_orders
    amount = _holdings.get(code, 0)
    if amount <= 0:
        return
```

已下卖单但尚未成交的股票，`_pending_orders`有记录但`_execute_sell`不检查，直接重复下单。

### 事故链条完整还原

```
11:19  止损触发 → _execute_sell(688121) → 下卖单 → _pending_orders记录
       卖单挂在簿上未成交（科创板小票流动性差）
14:50  _reconcile第1次 → 查成交记录：无成交 → 恢复_holdings[688121]=100
       → 清空_pending_orders → _save_state(持仓=67只的估算态)
14:50:01  _reconcile第2次 → _today_orders已空 → 直接跳过（return）
       但_holdings和_pending_orders已被第1次reconcile破坏
14:50:02  下一个bar → 止损检查 → 688121在_holdings中且不在_pending_orders
       → 再次_execute_sell → 重复下单
       → _reconcile又恢复 → 循环...
```

**核心矛盾**：_reconcile设计意图是"收盘校准一次"，但tick级bar下变成了"每秒校准一次"，而每次校准都会恢复未成交持仓+清空防重复机制。

## 3. 修复方案（三处改动）

### Fix 1：`_execute_sell`/`_execute_buy` 入口加在途守卫

**文件**: `strategy_v2.py:892-896` / `strategy_v2.py:836-841`

```python
def _execute_sell(C, code):
    global _pending_orders, _cash, _today_orders
    try:
        if code in _pending_orders:  # ← 新增
            return                    # ← 新增
        amount = _holdings.get(code, 0)
        ...

def _execute_buy(C, code):
    global _pending_orders, _cash, _today_orders
    try:
        if code in _pending_orders:  # ← 新增
            return                    # ← 新增
        price = _get_price(C, code, "close")
        ...
```

**效果**：无论从哪个路径调用（止损/暂缓队列/换仓），只要该股票已有在途订单，立即返回，不重复下单。

### Fix 2：`_reconcile` 加每日闸门

**文件**: `strategy_v2.py:66` (全局变量) + `strategy_v2.py:732` (handlebar调用点) + `strategy_v2.py:831` (reconcile内部)

```python
# 全局变量新增
_last_reconcile_date = ""  # 收盘对账每日闸门

# handlebar调用点（修复前 vs 修复后）
# 修复前：
if current_hour == 14 and current_minute >= 50:
    _reconcile(C)
# 修复后：
if current_hour == 14 and current_minute >= 50 and _last_reconcile_date != today_str:
    _reconcile(C)

# _reconcile尾部新增
_today_orders = {}
_pending_orders = {}
_last_reconcile_date = _get_market_time(C).strftime("%Y-%m-%d")  # ← 新增
```

**效果**：同一天 `_reconcile` 只执行一次，不会在tick级bar下每秒重复恢复持仓+清空在途。

### Fix 3：止损/暂缓队列循环跳过在途单

**文件**: `strategy_v2.py:599-602` (止损sells构建) + `strategy_v2.py:650-652` (暂缓队列处理)

```python
# 止损sells列表构建
sells = []
for code in list(_holdings.keys()):
    if code in _pending_orders:  # ← 新增
        continue                  # ← 新增
    price = _get_price(C, code, "close")
    ...

# 暂缓队列处理
for code in list(_suspended_sells):
    if code in _pending_orders:  # ← 新增
        continue                  # ← 新增
    if not _is_limit_down(C, code) and not _is_suspended(C, code):
        ...
```

**效果**：即使持仓因reconcile被恢复，止损/暂缓循环也不会把在途单的股票加入卖出列表，双重保险。

## 4. 修复覆盖矩阵

| 触发路径 | 修复前 | Fix1 | Fix2 | Fix3 | 修复后 |
|---|---|---|---|---|---|
| `_execute_sell` 直调 | 可重复下单 | **拦截** | - | - | 不重复 |
| 止损sells循环 → `_execute_sell` | 可重复下单 | **拦截**(兜底) | - | **拦截**(前置) | 不重复 |
| 暂缓队列 → `_execute_sell` | 可重复下单 | **拦截**(兜底) | - | **拦截**(前置) | 不重复 |
| `_reconcile` 每bar执行 | 恢复持仓+清空在途 | - | **每日只1次** | - | 不破坏 |
| `_execute_buy` 直调 | 可重复下单 | **拦截** | - | - | 不重复 |

三层防线：Fix2从根源（reconcile频率）控制，Fix3从触发源（循环构建）过滤，Fix1从执行入口兜底。

## 7. 遗留风险与待观察

### 已修复
- 688121重复下单：三层防线覆盖
- _reconcile tick级重复：每日闸门
- 持仓跳变根源（reconcile恢复+清空→止损重触发）

### 待模拟端验证（MOCK无法覆盖）
1. **真实成交回调**：reconcile校准后现金/持仓数值是否与账户一致
2. **跨日状态恢复**：QMT重启后读取`v2_holdings_state.json`，持仓数是否正确
3. **67只非调仓建仓**：需确认reconcile不再产生孤儿持仓后，此现象消失
4. **盘中卖出风控**：止损+暂缓队列在途守卫是否影响正常卖出节奏

### 未改动项（设计确认）
- `_reconcile`内部逻辑未改：恢复未成交持仓+清空pending是设计意图（收盘校准），闸门限制其频率即可
- `exit(C)`仍调用`_reconcile`：策略退出时强制对账，不受闸门限制（合理）
