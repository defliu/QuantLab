## E1. 策略逻辑正确性

### 结论
1. **因子方向正确**：BP = 1/PB，行业中性 z-score 越高（相对同行业越便宜）得分越高；质量排雷（bps>0 / roe>0 / profit_dedt>0）为纯剔除式排雷（只排除亏损/资不抵债股），不打分、不误杀。
2. **评分公式双侧一致，但存在一个 P0 级口径漂移**：`strategy/scoring.py` 与 `strategy_v2.py:_score_stocks` 的合成公式一致（纯行业中性 BP z，hp 权重为 0）；**但生产 QMT 版缺少回测宇宙的全部筛选条件**——无 30 亿流通市值上限、无 pe_ttm>0、无质量排雷、无 ST/停牌候选剔除。生产实际是「全市场行业中性 BP top80」，回测是「<30亿小盘 + 质量排雷后的行业中性 BP top80」，两者选出的组合可能完全不同，回测结论不能直接外推到当前生产代码。
3. **v2.3 两组件实现与 SPEC 一致**，无逻辑漏洞（细节见下）。

## E2. 回测口径可信度（重点）

### 结论
**逐日 close 结算 + 每日风控口径（对照B）年化 7.5% 是实盘真实预期，可信；状态机口径 18.0% 不可作为实盘预期**。「风控频率虚高 -8.3pp、结算频率 -2.2pp」的归因经代码与产物独立复核**成立**。另须警示：真实口径下 2024+ 超额为 **-44.4%**（对照B，`results/dir1_daily_risk.txt:15`），与状态机口径的「2024+ +50.1%」方向相反，引用历史数字时必须带口径标注。

### 证据
**三口径数字链（均可追溯）**
| 口径 | 年化 | 出处 |
|---|---|---|
| 状态机（双月 open 结算 + 换仓日风控） | 18.0%（累计 +285.0%） | `results/backtest_result.txt:6` |
| 对照A（逐日 close 结算 + 换仓日风控） | 15.8%（累计 +243.0%） | `results/dir1_daily_risk.txt:6` |
| 对照B（逐日 close 结算 + 每日风控） | **7.5%**（累计 +82.7%；2024+ 超额 -44.4%） | `results/dir1_daily_risk.txt:12,15` |

**代码级根因**
1. 状态机默认口径：`runner.py:210` `run_backtest(force_full_turn=False, daily_risk=False)`，风控仅在换仓日执行（`runner.py:295-315`），收益按换仓次日 open 结算（`runner.py:240-249`）——风控每两个月才查一次，实盘不存在此频率。
2. `--daily-risk` 旧实验（17.8%）的已知缺陷：`runner.py:217-220` 注释自认「每日止损剔除的股票直接移出 prev_holdings（`runner.py:277-280`），换仓日结算时其收益不计入 → 止损亏损被抹掉，该模式年化虚高（17.8% 不可信）」——该缺陷成立，17.8% 应弃用。
3. 正确隔离实现 `research/dir1_daily_risk.py`：对照A/B 共用同一逐日 close 结算引擎（`:124-140`），唯一变量是 `risk_check_daily`（`:47,143,160`）。18.0→15.8 的 -2.2pp 来自结算频率（双月 open→逐日 close），15.8→7.5 的 -8.3pp 来自风控频率（换仓日→每日）。
4. 归因核对：`results/优化方向实证结果_20260814.md:107` 汇总表「风控仅换仓日 15.8%→每日 7.5%（-8.3pp），结算频率次因（-2.2pp）」——与上述代码结构及 `dir1_daily_risk.txt` 输出吻合，归因成立。
5. 实盘对齐验证：生产 `strategy_v2.py` handlebar 每 bar 检查止损/持有期/回撤（`:698-758`），风控频率为每 bar（≥每日），故对照B 是对齐口径。
6. 历史污染 bug 已修：risk_state.json 残留致 18%→35.7% 虚高，修复为 per-pid state + 每次 run 前强制重置（`runner.py:130-135,201-222`）；修复后归档 18.0% 可复现（`backtest_result.txt` 与 `优化方向实证结果` §1 一致）。
