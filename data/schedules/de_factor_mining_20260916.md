## 1. 可行性判断：**有条件做**

- **数据资产足够厚**：`D:/astock` 1457 万行日线（2009 起，33 列含 pe_ttm/pb/ps_ttm/dv_ttm/turnover_rate/circ_mv）+ 8 张财务表（PIT 安全，ann_date/f_ann_date）+ 分钟线 5826 只（`AGENTS.md` 数据层约定）+ Tushare 在线增量 4 源已实测可用（lhb/top_list、report_rc、hk_hold_full，`全局控制台.md` T-20260914-002）。这比 harness 462 因子时代（仅行情+财务衍生）多了**真正的新数据维度**。
- **算力可行性有实证先例**：462 因子 × 3 universe 的批量 IC 筛选在本机完整跑完并归档（`研究总览与路线图.md` §2.2），证明数百因子量级的批量截面计算在本机可行。

### 1.2 工程链维度——✅ 基本够用，缺的是"批量跑批层"

现有链路盘点：
- `factors/base.py`：FactorBase + winsorize(1%,99%)/zscore/rank_normalize 预处理齐备；
- `factors/engine.py`：FactorEngine 支持 register → compute_all → compute_ic（逐日截面相关 + IC/ICIR/IC>0 占比，forward_days=20，每期最少 30 样本）；
- `research_audit/factor_health.py`：调仓期月频 Spearman IC + 分段统计（全期/2024+/2026/近8期）+ FAILED/DEGRADED/WATCH/HEALTHY 衰减告警，且已证明"新增因子只需实现一个 factor_defs 条目"的可扩展设计；
- `backtest/engine.py`：next_open 真实约束回测（滑点/佣金/涨跌停/停牌拒单/整数手）+ PIT 宇宙（`universe_by_date`）+ 大盘门控；
- `data/astock_reader.py` / `astock_finance_reader.py`：数据读取与 PIT 财务查询接口现成。

**缺口**（需新建，属正常开发量而非技术风险）：
1. 批量候选表达式登记与批量 IC 跑批脚本（现有 FactorEngine 是单因子注册制，无"一个 YAML 清单跑 N 个表达式"的批处理入口）；
2. 三段切分（训练/验证/测试）的硬编码配置层——现有 compute_ic 是全期一口价，正是被 462 证伪教训点名的"全期筛选=牛市过拟合"结构；
3. 备用源交叉验证当前不可用：gpsj `is_available()=False`（E 盘缺失，`data/gpsj_reader.py` L25-27），所有结论只能单源，须按降级规则标注。

### 1.3 研究纪律维度——⚠️ 唯一实质风险，须以硬条件形式前置

历史证伪记录极惨烈：462 因子 → 小盘训练集 11 有效（2.4%）→ 样本外回测 **-24.54%**，0 个转正（`研究总览与路线图.md` §2.2）；大盘/中盘训练集 0 有效；GTJA191/Alpha101/Qlib158 训练集 0 有效（§五）。**"广撒网自动挖掘"的期望产出已被科学证伪过一轮。**

### 1.4 判定

**有条件做。** 理由：可行性的关键不在"能不能跑"（显然能），而在"跑的东西有没有增量"和"筛选纪律是否硬编码"。满足以下三个条件才值得启动：
1. **只挖 harness 462 未覆盖的增量数据方向**（另类数据/财务科目组合/时间维度），不重跑已证伪族（见 §2）；
2. **三段切分与筛选阈值硬编码进脚本**，全期 IC 只作淘汰参考、禁止作为入选依据；
3. **接受现实预期**：一年 0-1 个通过全门槛的新排序因子是正常产出（见 §6），不为"产出数量"放松门槛。

## 3. 闲时因子挖掘流水线设计

### 3.1 阶段划分

```
S0 登记层（DE+人工） → S1 IC 初筛（脚本，周末重计算） → S2 训练集验证（脚本，周末）
→ S3 样本外回测（脚本，夜间限量） → S4 上线门槛（脚本监控 + DE 裁决 + 人工拍板）
```

| 阶段 | 输入 | 输出 | 脚本类型 | 判定阈值（基准依据） | 失败即弃规则 |
|---|---|---|---|---|---|
| **S0 候选登记** | DE/人设计的表达式 + 数据源说明 | `candidates_batch_YYYYMMDD.yaml`（预登记清单：表达式、方向假设、数据源、与已有因子相关性预估） | 无（纯文本登记，人工审核） | 方向假设必须写清经济逻辑；无逻辑的纯数据挖掘不登记 | 审核不通过不进入批次 |
| **S1 截面 IC 初筛** | 登记清单 + D:/astock 数据 | `ic_screen_<batch>.csv`（全历史月频 Spearman IC + ICIR + 分段） | 纯 Python（复用 `factor_health.py` 的 per-period IC 口径 + 分段统计） | **只淘汰不入选**：\|全期IC\|<0.02 或训练段 IC 与全期反号 → 弃；其余全部晋级（防"全期选优"） | 初筛淘汰率预期 50-70% |
| **S2 训练集验证** | S1 幸存者 | `train_valid_<batch>.md` | 纯 Python（分段切死：训练 2021-01~2023-12，与 harness 同段） | 训练集月频 ICIR≥0.5 且 IC 正值占比≥60% 且逐年无反号（标杆：BP 行业中性z 全期 ICIR 0.775、正值占比 76%（`factor_health_报告.md`）；harness 有效线 \|ICIR\|>0.5（§2.2）；低效线参照基本面 6 因子 ICIR<0.5 判无效） | 任一条件不满足即弃，不留"观察名单" |
| **S3 样本外回测** | S2 幸存者（通常 0-3 个/批） | `oos_backtest_<factor>.md` | 纯 Python（`backtest/engine.py` 真实约束 next_open + B/D 模块口径） | 样本外（2024-2026）回测**不显著为负** + IC 不反号 + 超额 vs 基线（ATR/P10 池口径）分解后仍有独立贡献（与 BP 相关性>0.8 的不算新 alpha） | 样本外回测显著为负即弃并归档证伪记录 |
| **S4 上线门槛** | S3 幸存者（预期每数批 0-1 个） | 健康监控纳入 + 裁决报告 + 拍板记录 | `factor_health.py` 扩容 + gpsj 交叉验证脚本 + DE 裁决文档 | 连续 2 期 factor_health 等级 ≥ WATCH；gpsj 可用时交叉验证 1 个自然年 CAGR/回撤差异 ≤1pp（`AGENTS.md` 备用源规则；**当前 is_available()=False，须标注"单源结论"**） | 上线后任何一期 FAILED 即从排序权重移除（沿用现有监控红线） |

### 3.2 DE 与确定性脚本的分工

| 环节 | 归属 | 理由 |
|---|---|---|
| S0 表达式设计、方向假设撰写 | **DE**（人工终审） | LLM 的比较优势：跨文献/跨数据源的表达式联想与经济逻辑陈述 |
| S1/S2/S3 全部计算与筛选判定 | **必须脚本** | 防模型幻觉（DE 曾把日期标记 bug 归因错、TW 曾漏配置误报 +0.029%——`AGENTS.md` DE/TW 条款）；筛选阈值若由模型现场判断，等于重演"全期选优" |
| S3 结果解读、证伪裁决报告 | **DE**（人工终审） | DE 有独立视角，但**裁决必须引用脚本原始输出**，禁止凭模型记忆复述数字（audit13 教训，`AGENTS.md` DE 条款） |
| 上线拍板 | **人工（诚哥）** | 风控优先级红线：因子权重修改前需确认 SPEC 或用户明确要求（`AGENTS.md` 因子层约定） |
| 批量执行调度 | **纯脚本（schtasks）** | 模型降级规范"脚本优先"原则（`AGENTS.md` 定时任务模型降级规范）；DE 多次卡死实录（T-20260915-002 第四次卡死 31min 零产出）证明批量环节不能依赖 LLM 会话存活 |

### 3.3 单批次量级估算与节奏

**估算前提（显式标注：以下为工程估算，非文档实测数字）**：
- 数据加载一次成本：2018+ 子集约数百万行 parquet 读入 + 预处理，分钟级（`factor_health.py` 的 load_panel 同量级；该脚本作为周五 19:30 周期任务运行，属分钟-十分钟级任务）；
- 简单截面表达式：月频 100 期 × 每期 ~5000 只截面 rank+corr，向量化后单表达式秒级；含 rolling 窗口的表达式（如 60d 滚动）慢 5-10 倍；
- 硬先例：462 因子 × 3 universe 批量曾完整跑完（§2.2）。

**量级结论**：
- **周末窗口**（周六 09:00 启动，预算 30 小时、按 15-20 小时有效计算留安全余量）：单批次 **300-1000 个**已登记表达式走完 S1+S2；
- **夜间窗口**（20:30-23:30 约 3 小时）：轻量表达式 50-150 个，或 S3 单因子真实约束回测数个（回测远重于 IC：引擎逐日撮合 + 涨跌停/停牌处理，单次全 A 十年回测为十分钟级以上，一夜限 5-10 个候选）。
- **批次节奏建议：每双周一批，周末跑 S1+S2，周一至周五夜间跑 S3**。单批 >500 表达式时多重检验假阳性风险上升（500 个纯随机因子期望 ~25 个"ICIR>0.5"假阳性，需按 §4 纪律 6 上调门槛），**宁可 300 个/双周，不要 1000 个/周**。

## 4. 防过拟合硬纪律（必须内置进脚本，写在配置文件而非靠自觉）

1. **三段切分固定并写死在配置**：训练 2021-01~2023-12（与 harness 同段）/ 样本外回测 2024-2026 / 2026+ 只读不选。**禁止任何环节做全期选优**——462 教训：大盘/中盘全期 9/8 个"有效"训练集为 0（§2.2、§2.7 教训 1）。
2. **IC 有效 ≠ 回测有效**：S2 幸存者强制走 S3 真实约束回测——小盘训练集 11 个 IC 有效因子样本外 -24.54%（§2.7 教训 2）。回测必须含成本、涨跌停、停牌（`backtest/engine.py` 现有能力）。
3. **每个候选预登记（S0 先于运行）**：表达式、方向假设、数据源在运行前锁定，禁止跑完后补假设、禁止从批次结果里"挑好看的"补登记。这是对"事后挑因子"的机制性封锁。
4. **初筛只淘汰不入选**：全期 IC 仅用于剔除明显无效者，入选判定只看训练集段。分段统计直接复用 `factor_health.py` 的 regime_stats 结构（全期/2024+/2026/近8期）。
5. **多重检验校正意识**：单批次 N>200 时，训练集门槛从 ICIR≥0.5 上调至 ≥0.6 且要求分年度一致；批次间禁止对同一表达式反复微调参数重跑（参数微调视为新表达式须重新登记，防止"挖掘到通过为止"）。
6. **与已有因子相关性检查**：与 BP 行业中性 z（当前唯一 HEALTHY 排序因子，`factor_health_报告.md`）相关性 >0.8 的候选不视为新 alpha，只作 BP 的冗余确认记录。
7. **上线前双门禁**：factor_health 健康监控连续 2 期 ≥ WATCH + gpsj 备用源交叉验证（当前不可用 → 按降级规则在报告显著位置标注"单源结论（仅 astock），未经备用源交叉验证"，`AGENTS.md` 备用源降级规则）。
8. **单批次证伪率预期写入任务书**：每批次报告必须显式记录"登记 N → 初筛剩 X → 训练集剩 Y → 样本外剩 Z"，防止幸存者叙事。历史基准：462 → 11（2.4%）→ 0（0%）。
9. **PIT 铁律**：财务因子一律 ann_date/f_ann_date 过滤（`data/astock_finance_reader.py`）；宇宙选择用 `universe_by_date` PIT 宇宙（`backtest/engine.py`）；复权 look-ahead 按 `AGENTS.md` 数据层约定（前复权 = 原始价 × adj_factor/最新 adj_factor，禁止用未来 adj）。

## 6. 成本收益预期（现实版）

**漏斗数量级**（基于历史证伪率推演）：
- 单批次 300-1000 登记表达式 → S1 初筛剩 ~30-50% → S2 训练集验证剩 **个位数**（历史基准 2.4%，且我们已排除已证伪族、预期略高，按 3-5% 计）→ S3 样本外回测剩 **0-2 个**（历史基准：11 个训练集有效者样本外 0 个转正）。
- **年化预期：跑 20-25 个批次、约 1-2 万个表达式，最终通过全门槛的新排序因子 0-1 个。** 第一年大概率是 0。这不是悲观，是 462 实证 + 公开因子库全灭（GTJA191/Alpha101/Qlib158）给出的基准率。

**若一年找不到新 alpha，体系的保留价值**：
1. **因子库沉淀（负结果资产）**：每个证伪因子带证据归档，直接扩写 `研究总览与路线图.md` 第二节"已跑过勿重复"清单——本项目最贵的是研究时间，不是算力；一次登记的证伪记录能防止未来任何 agent 重挖；
2. **factor_health 监控扩容**：即使没有新排序因子，通过 S1 的候选（如另类数据弱因子）可纳入每周五健康监控作 WATCH 级观察哨，衰减预警网络变厚；
3. **过滤型因子比排序因子更现实**：ATR MAX5 彩票过滤的先例证明"减法式风险排除"能在不换排序的情况下 +1.45pp CAGR / 回撤 -4.75pp（`研究总览与路线图.md` §五 ATR 条目）；挖掘管线若产出的是合格域过滤条件而非排序因子，同样有价值且门槛可适当放宽（不走 S3 全量回测，走 ATR 域 ablation）；
4. **数据管道沉淀**：北向/龙虎榜/研报三源的 PIT 快照化管道一旦建成，本身就是未来策略研究（不限因子）的基础设施。

**成本**：主要是前期一次性开发（批量登记/跑批/切分脚本 + 调度包装，估计 2-3 个工作日的人工），以及每双周 ~30 分钟的人工审核（S0 登记 + 批次汇总卡）。闲时算力近零机会成本。
